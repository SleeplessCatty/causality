# 密码与 MCP 配置界面优化设计

## 目标

在不扩展业务能力、不修改数据库结构的前提下，统一登录与主界面的品牌标识，改善修改密码交互，并将参数配置页的 MCP 服务模块整理为紧凑、清晰的桌面端布局。

## 修改范围

### MCP 服务模块

- 使用紧凑分区布局：服务概览、个人令牌管理、客户端配置说明三个区域保持明确层级。
- 服务概览在同一区域展示运行状态、连接地址以及 `15 Tool / 5 Prompt / 4 Resource`。
- 个人令牌标题、创建操作和令牌表格属于同一管理区，减少散落文字和无意义留白。
- 用户可见的“设备名称”统一改为“令牌名称”；创建说明改为“设置一个便于识别的令牌名称”。
- 撤销说明只描述令牌及使用该令牌的连接，不把令牌绑定到设备或客户端概念。
- 后端与共享契约中的 `deviceName` 暂时保持不变，避免仅为展示文案引入数据库迁移和 API 破坏性变更。

### 修改密码页面

- 当前密码、新密码、确认新密码输入框分别提供显示/隐藏按钮，默认隐藏，按钮具有明确无障碍名称。
- 用户主动修改密码时显示“取消”，点击后返回进入该页面前保存的 `returnTo`，不调用退出登录接口。
- 首次登录强制修改密码时不显示取消按钮，用户必须完成密码修改才能进入业务页面。

### 品牌图标

- 提取可复用的 `AppBrandMark` 组件，登录页和左侧导航使用相同 DOM 与视觉样式。
- 创建同一造型的 SVG favicon，写入 Web 公共资源并由 `index.html` 引用。
- 图标继续使用当前深绿色、圆角方框和衬线字母 `C`，不重新设计品牌。

## 测试与验收

- 组件测试覆盖三组密码可见切换、主动取消返回和首次登录不显示取消。
- 登录页和侧栏测试验证共享品牌标记。
- MCP 组件测试验证新文案、紧凑信息分区、创建与撤销交互。
- E2E 更新令牌名称选择器，并验证主动修改密码取消返回。
- 使用桌面视口检查 `/settings`、`/login`、`/change-initial-password` 的布局、控制台和交互状态。

## 非目标

- 不修改个人令牌的数据模型、API 字段或数据库列名。
- 不增加移动端适配、OAuth 或新的 MCP 能力。
- 不修改登录页密码输入框；本次密码可见按钮只作用于修改密码页面。
