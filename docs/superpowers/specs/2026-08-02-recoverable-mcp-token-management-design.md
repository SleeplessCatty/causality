# 可恢复 MCP 个人令牌管理设计

## 目标

重新设计参数配置页的 MCP 个人令牌管理，使用户可以在创建后随时查看、复制和删除自己的令牌，同时避免在列表接口、日志或数据库明文中暴露令牌。

本次仅调整个人令牌的存储、管理接口和参数配置页面，不改变 MCP Bearer Token 的认证方式，也不增加管理员与普通用户的权限差异。

## 已确认原则

- 升级时删除全部现有个人令牌，用户升级后重新创建。
- 令牌名称只要求在当前用户范围内唯一。
- 名称保存前去除首尾空格，唯一性比较忽略大小写。
- 完整令牌只在当前页面临时显示，刷新、跳转或重新进入页面后恢复隐藏。
- 隐藏状态下可以直接复制令牌或完整 JSON 配置，复制不会自动展开令牌。
- 查看或复制只要求当前登录会话有效，不重复验证密码。
- 令牌缩写格式为 `cau_pat_abcd••••wxyz`。
- 创建时保留名称输入弹窗；创建成功后立即关闭，不再展示一次性令牌结果窗口。
- 撤销操作直接删除记录，不保留已撤销令牌。

## 存储与加密

令牌记录同时保存认证摘要和可恢复密文：

- `token_digest`：不可逆摘要，继续用于 MCP 请求认证。
- `token_ciphertext`：AES-256-GCM 加密后的令牌原文。
- `token_iv`：每条令牌独立生成的随机 12 字节 IV。
- `token_auth_tag`：GCM 认证标签。
- `masked_token`：创建时生成的非敏感缩写，供列表直接读取而无需解密令牌。
- `name`：令牌名称。
- `created_at`、`last_used_at`、`last_client_name`：现有生命周期信息。

加密使用独立环境变量 `CAUSALITY_TOKEN_ENCRYPTION_KEY`，值为 Base64 编码的 32 字节随机密钥。用户 ID 和令牌 ID共同作为附加认证数据，使密文无法被替换到其他用户或令牌记录。

生产环境缺少密钥或密钥格式错误时，API 服务拒绝启动。开发环境和自动化测试可以使用明确标记为非生产用途的固定密钥。密钥必须长期保存；密钥丢失或错误会使现有令牌无法查看和复制，此时只能删除并重新创建令牌。

## 数据库迁移

迁移按以下顺序执行：

1. 删除 `mcp_access_tokens` 中全部现有记录。旧记录只保存摘要，无法恢复原文。
2. 将 `device_name` 重命名为 `name`，清除内部“设备”概念。
3. 删除 `revoked_at` 字段和依赖该字段的索引。
4. 增加密文、IV 和认证标签字段及长度检查。
5. 增加 `(user_id, lower(btrim(name)))` 唯一索引。
6. 更新 Drizzle schema、数据库验证脚本和迁移测试。

历史审计日志保留原有 `mcp_token.revoked` 动作。新删除操作新增 `mcp_token.deleted` 动作；审计记录不保存令牌原文、密文或摘要。

## 服务端边界

服务端拆分为三个明确职责：

1. 令牌加密器负责生成随机令牌、加密、解密和生成缩写，不接触数据库。
2. 令牌仓储负责当前用户范围内的唯一性、查询、创建和硬删除，不负责 HTTP。
3. 令牌服务负责权限、事务、审计、认证摘要和错误转换。

完整令牌只在创建和按需读取期间存在于进程内存中，不写入日志。列表查询不得读取或返回完整令牌。

## API 设计

### 列表

`GET /api/mcp/tokens`

返回当前用户的有效令牌摘要：

```json
{
  "id": "uuid",
  "name": "Codex",
  "maskedToken": "cau_pat_abcd••••wxyz",
  "createdAt": "2026-08-02T08:00:00.000Z",
  "lastUsedAt": null
}
```

列表结果中不存在 `status`、`revokedAt` 或完整令牌。

### 创建

`POST /api/mcp/tokens`

请求：

```json
{ "name": "Codex" }
```

成功时只返回新令牌摘要，不返回完整令牌。名称重复返回 `409 TOKEN_NAME_EXISTS`。

### 按需读取完整令牌

`GET /api/mcp/tokens/:tokenId/secret`

仅允许读取当前登录用户自己的令牌。成功时返回：

```json
{ "token": "cau_pat_..." }
```

响应必须包含 `Cache-Control: no-store`。不存在或不属于当前用户统一返回 404；解密失败返回 `TOKEN_SECRET_UNAVAILABLE`。

### 删除

`DELETE /api/mcp/tokens/:tokenId`

在同一事务中硬删除令牌并追加 `mcp_token.deleted` 审计记录，成功返回：

```json
{ "deleted": true }
```

删除成功后，该令牌的下一次 MCP 请求立即认证失败。

## 页面设计

参数配置页个人令牌表格只显示四列：

| 令牌名称 | 令牌 | 最近使用时间 | 操作 |
| --- | --- | --- | --- |
| Codex | `cau_pat_abcd••••wxyz` | 从未 | 查看　复制令牌　复制完整 JSON 配置　撤销 |

### 创建

- 点击“创建个人令牌”打开名称输入弹窗。
- 创建成功后弹窗立即关闭并刷新列表。
- 不再显示一次性令牌或“我已保存”步骤。
- 名称重复时保留弹窗并在原错误位置显示“令牌名称已存在”。

### 查看与隐藏

- 点击“查看”时调用 secret 接口，仅展开当前行，按钮变为“隐藏”。
- 点击“隐藏”后立即从前端状态中移除该令牌原文。
- 刷新、离开页面或组件卸载时不保留已读取的完整令牌。
- 读取失败时保持缩写并显示三秒错误提示。

### 复制

- “复制令牌”和“复制完整 JSON 配置”在隐藏状态下始终可用。
- 操作时临时调用 secret 接口并写入剪贴板，但不改变当前行的展开状态。
- JSON 配置由前端使用 MCP 服务地址和完整令牌生成，不增加第二个服务端接口。
- 成功提示分别为“令牌已复制”和“JSON 配置已复制”；复制失败使用现有三秒错误提示。

### 删除

- 用户点击“撤销”后显示二次确认。
- 确认成功后直接从列表删除，不显示已撤销状态。
- 删除失败时保留确认弹窗和原列表行，显示原因并允许重试。

### 长文本与布局

- 令牌名称和令牌值均采用单行省略显示，并复用现有 `OverflowText` 显示可滚动完整提示。
- 操作列使用四个紧凑文字按钮，“撤销”使用危险色。
- 表格为桌面端预留固定操作列宽度，按钮不得挤压名称和令牌列造成页面横向溢出。

## 错误和安全规则

- 所有管理接口继续使用 Web 登录会话和 CSRF 保护。
- secret 接口按当前用户查询，不单独暴露令牌归属。
- 完整令牌不得出现在列表响应、错误响应、审计日志或应用日志中。
- 解密、剪贴板或删除失败均不得清除仍然有效的列表记录。
- 同一用户并发创建规范化后同名令牌时，由数据库唯一约束提供最终一致性。
- `CAUSALITY_TOKEN_ENCRYPTION_KEY` 不写入镜像或仓库；README 提供生成和部署配置说明。

## 测试与验收

### 自动化测试

- 合同测试：新的摘要、创建、secret 和删除响应；拒绝旧状态字段。
- 加密单元测试：加密解密、错误密钥、密文篡改、错误用户或令牌附加数据。
- 数据库迁移测试：旧令牌删除、字段变更、长度检查和用户内名称唯一约束。
- API 集成测试：创建、大小写重复、列表缩写、按需读取、跨用户 404、删除和删除后认证失败。
- 前端组件测试：四列表格、四项操作、查看/隐藏、隐藏复制、JSON 复制、错误恢复和 80 字名称。
- Playwright：创建后直接进入列表、查看完整令牌、隐藏、复制 JSON、撤销后消失。

### 发布门禁

- 全量单元测试、类型检查、Lint、格式检查和生产构建通过。
- Playwright E2E 全部通过。
- 浏览器人工验证创建、查看、复制、隐藏和撤销的完整流程。
- 验证日志、网络列表响应和错误提示均不包含完整令牌。

## 不包含的内容

- 不提供令牌编辑或重命名功能。
- 不保留已删除令牌列表。
- 不支持加密密钥在线轮换。
- 不为查看或复制增加二次密码验证。
- 不修改 MCP 客户端 Bearer Token 的使用方式。
