# 全局加载体验与布局稳定性设计

## 1. 目标

统一 Causality Web 应用中的认证、路由模块和业务数据加载体验，消除快速刷新时连续出现的“正在检查登录状态”“正在加载页面”“加载事件”等瞬时文字，减少真实内容出现时的模块位移，同时保留慢请求、后台刷新和失败情况下必要且准确的反馈。

本阶段同时修正折叠导航下的用户入口：只有展开导航时才允许打开用户操作菜单。

## 2. 范围

### 2.1 本阶段包含

- 认证会话首次检查的延迟反馈和稳定占位；
- 懒加载路由的分级预加载与稳定占位；
- 普通业务查询的短期缓存和后台刷新反馈；
- 五类可复用页面骨架；
- 复合页面的模块级并行加载、局部错误和局部重试；
- 折叠导航下用户入口的非交互状态；
- 自动化测试、桌面浏览器限速验收和布局稳定性检查。

### 2.2 本阶段不包含

- 移动端适配；
- 服务端渲染；
- 把用户身份或会话结果持久化到浏览器；
- 修改业务 API；
- 修改因果图布局算法；
- 统一重构创建、删除、导入、索引等明确业务操作的进度提示。

## 3. 总体方案

采用分层加载状态管理。认证、路由和数据查询分别保留自己的数据职责，但共享延迟计时、骨架、后台刷新和错误展示规范。

不采用以下替代方案：

- 仅用 CSS 隐藏现有加载文字：无法解决模块位移、重复请求和复合页面阻塞；
- 全局启动遮罩：最慢请求会阻塞整个应用，局部失败也无法独立恢复；
- 立即展示所有骨架：快速请求下仍会出现骨架闪烁。

## 4. 统一加载状态模型

所有读取型加载过程归一为四种状态：

| 状态 | 触发条件 | 展示方式 |
| --- | --- | --- |
| 短暂等待 | 首次加载未满 180ms | 保留稳定背景和页面框架，不显示加载文字或骨架 |
| 首次加载 | 首次加载达到 180ms | 显示页面类型骨架；骨架出现后至少保持 300ms |
| 后台刷新 | 已有可用数据，刷新达到 500ms | 保留原内容，在页面或模块标题区域显示不占布局空间的“更新中”状态 |
| 加载失败 | 首次加载或后台刷新失败 | 首次失败在原骨架区域显示错误；后台失败保留旧内容并显示局部错误和重试入口 |

业务操作的显式进度，例如“正在创建”“正在删除”“正在导入”“正在索引”，不纳入读取型加载状态，继续由现有业务组件显示。

## 5. 公共组件边界

### 5.1 延迟可见性

公共 Hook `useDelayedVisibility` 只负责时间状态，不负责业务文案或布局：

- 首次加载延迟：180ms；
- 首次骨架最短显示时间：300ms；
- 后台刷新提示延迟：500ms；
- 组件卸载或加载结束时必须清理计时器；
- 支持假时间单元测试。

### 5.2 加载状态容器

公共 `LoadingState` 负责：

- 根据首次加载、后台刷新和错误状态选择展示内容；
- 提供 `role="status"`、`aria-live` 等必要的无障碍语义；
- 后台状态使用绝对定位或预留标题槽位，不改变内容区域尺寸；
- 错误状态接受明确的重试回调；
- 不包含业务查询代码。

### 5.3 页面骨架

提供五套公共骨架：

| 骨架 | 主要结构 | 适用范围 |
| --- | --- | --- |
| 列表骨架 | 标题、搜索区、固定表头和固定行 | 原子事件、因果关系、具体案例、导入历史、AI 导入历史、数据问题列表 |
| 详情骨架 | 返回入口、标题、摘要网格和关联列表 | 三类业务详情、文件导入详情、AI 导入详情 |
| 表单骨架 | 标题、字段组和操作区 | 创建、编辑和密码修改页面 |
| 设置面板骨架 | 页面标题、固定卡片和模块区 | 参数配置、系统状态、数据维护、导入导出 |
| 全画布骨架 | 固定工具栏和画布背景 | 因果图 |

骨架只表达空间结构，不显示虚假名称、数值或业务结论。骨架尺寸应接近真实页面，使内容替换不会明显推动相邻区域。

## 6. 认证加载

- 每次硬刷新都必须调用 `/api/auth/session`，不得用 Local Storage 或其他客户端缓存绕过服务端会话检查；
- 认证开始后的前 180ms 仅显示稳定应用背景；
- 超过 180ms 后显示固定尺寸的应用启动骨架，并至少保持 300ms；
- 认证成功后进入受保护页面；认证失败后进入登录页；
- 认证完成前不得提前渲染受保护业务内容；
- 认证错误不得短暂显示已缓存用户名或业务页面。

## 7. 路由预加载与路由骨架

### 7.1 分级预加载

- 用户完成认证并且浏览器进入空闲时，预加载原子事件、因果关系、具体案例、数据维护、导入导出、参数配置和系统状态等常用轻量页面；
- 因果图等大型模块不参与空闲全量预加载，只在对应导航项发生鼠标悬停或键盘聚焦时预加载；
- 相同模块的预加载请求必须复用同一 Promise，避免重复下载；
- 预加载失败不阻断当前页面，真正导航时仍允许重新加载并进入错误边界。

### 7.2 路由占位

- 导航栏和应用外壳始终保持挂载；
- 路由模块未完成时，只在主内容区显示对应页面类型骨架；
- 路由加载不足 180ms 时不显示即时文字；
- 不再使用“正在加载页面”或“正在加载因果图”作为立即出现的独立页面内容。

## 8. 数据查询与缓存

### 8.1 普通业务查询

- React Query 普通读取查询默认 `staleTime` 为 30 秒；
- 创建、编辑、删除、导入和数据处理成功后继续通过精确 Query Key 主动失效相关缓存；
- 失效后的后台刷新保留旧内容，不恢复为首次骨架；
- 列表翻页、筛选和搜索使用上一份结果作为占位，直到新结果完成；
- 返回 30 秒内仍然新鲜的列表或详情时直接显示缓存内容。

### 8.2 实时数据例外

下列查询不继承普通 30 秒策略，继续使用自己的轮询或刷新规则：

- 系统服务状态；
- 语义模型下载、加载和索引进度；
- 数据检查任务状态；
- AI 入库任务状态；
- 其他已有明确 `refetchInterval` 的任务型查询。

这些查询在已有数据时同样保留内容，并只在超过 500ms 后显示非阻塞更新状态。

## 9. 复合页面并行加载

复合页面先稳定呈现页面标题和整体结构，各模块独立请求、独立骨架、独立失败和独立重试。

### 9.1 参数配置

- MCP 服务配置、个人令牌和语义模型生命周期并行加载；
- MCP 加载失败不阻塞语义模型区域；
- 语义模型加载失败不隐藏 MCP 服务区域；
- 每个区域使用固定尺寸的设置面板骨架。

### 9.2 系统状态

- API、数据库和语义 Worker 状态独立呈现；
- 单一状态请求失败不替换整个系统状态页面；
- 实时检查结果使用现有轮询频率，并保留上一份状态。

### 9.3 数据维护

- 孤立数据统计、最近检查快照和问题列表独立加载；
- 问题列表后台刷新时保留筛选、分页和展开状态；
- 当前检查任务进度继续使用明确业务进度提示。

### 9.4 导入导出

- 当前导入/导出操作区与历史列表独立加载；
- 历史列表刷新保留当前分页；
- 文件上传、导出统计和文件保存继续使用业务操作进度，不改为页面骨架。

## 10. 错误与重试

- 首次加载失败时，在原骨架占用区域内显示简短原因和“重新加载”按钮；
- 错误区域保持与骨架近似的最小高度，避免失败状态导致页面收缩；
- 后台刷新失败时保留旧内容，在标题状态槽显示简短错误和重试入口；
- 一个模块的重试只重新执行该模块查询；
- 认证失败按认证规则进入登录页，不在业务页面显示重试；
- 不把请求取消、组件卸载或用户主动导航视为可见错误。

## 11. 折叠导航中的用户入口

- 展开导航时，当前用户区域保持按钮语义，可以打开修改密码、退出当前会话和退出全部会话菜单；
- 折叠导航时，用户区域改为非交互身份展示，只保留头像和用户名 `title` 提示；
- 折叠状态不得响应鼠标点击、Enter 或 Space；
- 从展开切换为折叠时，已打开的用户菜单立即关闭；
- 折叠状态不提供 `aria-expanded` 或“打开用户菜单”名称，避免辅助技术误认为可操作。

## 12. 测试与验收

### 12.1 单元和组件测试

- 使用假时间验证 179ms 不显示、180ms 显示首次骨架；
- 验证骨架出现后至少保持 300ms；
- 验证后台刷新 499ms 不显示、500ms 显示更新状态；
- 验证计时器在卸载和状态切换时被清理；
- 验证已有内容在后台刷新和刷新失败时保持可见；
- 验证普通查询 30 秒缓存和实时查询例外；
- 验证认证完成前不渲染受保护业务页面；
- 验证五类骨架的语义与主要结构；
- 验证复合页面模块互不阻塞；
- 验证折叠用户区域不可点击、不可通过键盘打开菜单。

### 12.2 浏览器验收

在支持的桌面视口检查原子事件列表、详情页、参数配置、系统状态和因果图：

- 快速刷新时不出现加载文字或骨架闪现；
- 限速刷新时在 180ms 后出现正确骨架；
- 骨架出现后至少保持 300ms；
- 页面主要容器在骨架替换前后的尺寸和位置无明显跳动；
- 后台刷新超过 500ms 后显示非阻塞状态，原内容仍可读、可滚动；
- 模块级失败只影响对应模块；
- 折叠导航下点击用户头像不会打开菜单；
- 浏览器控制台无 React 更新、未清理计时器、查询取消或未捕获请求错误。

### 12.3 发布门禁

- Web 单元与组件测试全部通过；
- Web 类型检查、Lint、格式检查和生产构建通过；
- 相关 Playwright E2E 通过；
- 快速网络和受控慢速网络的人工浏览器验收通过。

## 13. 实施顺序

1. 修正折叠导航用户入口，并锁定回归测试；
2. 实现延迟可见性 Hook、加载状态容器和五类骨架；
3. 改造认证和路由预加载；
4. 调整 React Query 普通缓存策略和实时查询例外；
5. 改造列表、详情和表单页面；
6. 改造参数配置、系统状态、数据维护和导入导出复合页面；
7. 改造因果图全画布首次加载；
8. 完成自动化回归、限速浏览器验收和发布检查。
