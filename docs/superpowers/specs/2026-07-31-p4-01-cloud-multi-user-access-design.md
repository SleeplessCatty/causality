# P4-01 云端远程访问与多用户支持设计

日期：2026-07-31

状态：设计已审核，等待实施计划审核

前置阶段：P3-03 MCP 兼容性与使用体验完善已完成

## 1. 目标

将 Causality 从单用户、本机可信环境应用改造为可以部署在单台 Linux 云服务器上的公网应用，使少量受信任用户能够：

- 通过用户名和密码远程登录同一个 Web 应用；
- 共同查看和维护同一套因果知识库；
- 分别创建自己的 MCP 个人访问令牌；
- 从支持自定义 Bearer Token 的桌面端或移动端 AI 客户端连接远程 MCP；
- 在多人并发编辑时避免静默覆盖；
- 追溯关键写入、安全和运维操作；
- 在单机故障后通过异地数据库备份恢复。

本阶段以“小范围朋友共同使用”为规模假设，不建设 SaaS、多租户或高可用平台。

## 2. 已确认原则

1. 所有用户共同维护一套全局知识库，不建立私有知识库、团队或工作空间。
2. 所有启用用户拥有相同业务权限，不区分管理员和普通用户。
3. 账号只能由服务器维护者通过 CLI 创建、停用、启用和重置密码。
4. Web 使用本地用户名和密码，不接入第三方登录。
5. 不支持 TOTP；通过强密码、限流、失败锁定、安全会话和备份降低风险。
6. MCP 第一版只支持个人访问令牌，不实现 OAuth。
7. 个人访问令牌方案只承诺兼容允许配置自定义 `Authorization` 请求头的 MCP 客户端，不承诺所有远程 MCP 客户端都能连接。
8. 云端部署使用单台 Linux 服务器和 Docker Compose。
9. Web、API 和 MCP 使用同一公网域名；MCP 位于 `/mcp`。
10. 多人修改使用乐观并发控制，不采用最后写入覆盖或编辑锁。
11. 保存 90 天最小审计日志，不保存字段修改前后快照。
12. Web 继续只面向电脑端，本阶段不做任何 Web 移动端兼容设计。
13. 移动端范围仅指移动端 AI 客户端通过远程 MCP 连接。

## 3. 非目标

P4-01 不包含：

- 公开注册、邀请链接或应用内用户管理；
- 管理员、普通用户或细粒度业务角色；
- 多租户、团队、工作空间和数据隔离；
- OAuth、OpenID Connect、第三方登录和 TOTP；
- Web 移动端适配；
- 多服务器部署、Kubernetes、负载均衡和自动故障转移；
- 托管 PostgreSQL；
- 实时协同编辑、WebSocket 推送和字段级自动合并；
- 完整字段修改历史、撤销和版本恢复；
- 在线 AI 模型接入；
- 自动新闻抓取或股票预测。

## 4. 当前状态与改造原因

当前应用没有用户登录体系，业务 API 按本机可信环境设计。所有知识数据全局共享，MCP 使用数据库中的单一全局 Bearer Token。生产 Compose 将 Web 和 MCP 绑定到 `127.0.0.1`，没有公网域名、TLS、反向代理、用户级凭据、异地备份或多人并发保护。

不能通过简单地把现有 Web 和 MCP 端口绑定到公网完成云端部署。这样会暴露匿名业务 API，并使所有 MCP 客户端共享一枚无法归属、无法单独撤销的 Token。

## 5. 总体架构

```text
互联网
   │
   ▼
Caddy（80/443，TLS 与反向代理）
   ├── /       → Web
   ├── /api/*  → API
   └── /mcp    → MCP Server
                    │
Docker 私有网络     │
   ├── API ◀────────┘
   ├── PostgreSQL
   └── Semantic Worker
```

只有 Caddy 暴露公网端口。Web、API、MCP、PostgreSQL 和语义 Worker 均只连接 Docker 私有网络。MCP Server 继续通过 API 执行业务逻辑，不直接访问数据库。

公网入口示例：

```text
https://causality.example.com/
https://causality.example.com/api/*
https://causality.example.com/mcp
```

实际域名通过云端环境配置提供，不写入应用代码。

## 6. 统一身份模型

Web 会话、MCP Token 和服务器 CLI 最终都解析为统一操作主体：

```text
RequestActor
- actorType: user | system
- userId、username（登录用户）
- actorLabel: server-cli（服务器命令）
- channel: web | mcp | cli
- sessionId 或 mcpTokenId
- requestId
```

Web 和 MCP 认证由 API 统一管理。服务器 CLI 在受信任的命令进程中创建 `system` 主体。业务服务只接收已经建立的 `RequestActor`，不自行解析 Cookie 或 Token，也不把 CLI 操作虚构为某个登录用户。

Web 请求流程：

```text
浏览器登录
→ API 验证用户名和密码
→ 创建 Web 会话
→ 浏览器保存安全 Cookie
→ 后续 API 请求解析为用户身份
```

每个受保护 Web 请求都重新检查会话未撤销、未过期且用户仍处于启用状态。账号停用不依赖会话自然过期。

MCP 请求流程：

```text
AI 客户端发送 Authorization: Bearer <个人令牌>
→ MCP Server 接收请求
→ API 验证令牌哈希、用户状态和撤销状态
→ 请求绑定用户与令牌身份
→ API 执行业务查询或受控入库
```

每个 MCP HTTP 请求都重新验证个人 Token 和用户状态，不能只在 MCP initialize 时缓存授权结果。撤销 Token 或停用用户后，已有 MCP 会话的下一次请求立即失败。

## 7. 数据模型

### 7.1 新增表

`users`：

- 用户 ID；
- 不可修改的唯一用户名；
- Argon2id 密码哈希；
- 是否必须修改初始密码；
- 是否启用；
- 连续失败次数；
- 锁定截止时间；
- 创建、更新时间和最后登录时间。

`web_sessions`：

- 会话 ID；
- 用户 ID；
- 会话令牌哈希；
- 创建、最近使用、空闲失效和绝对失效时间；
- 撤销时间。

`mcp_access_tokens`：

- Token ID；
- 用户 ID；
- 设备名称；
- Token 短前缀；
- Token 哈希；
- 创建、最近使用和撤销时间；
- 最近 MCP 客户端名称。

`auth_rate_limits`：

- 使用服务器密钥计算的来源 IP 摘要，不保存原始 IP；
- 当前时间窗口、失败次数和限制截止时间；
- 自动清理时间。

`audit_logs`：

- 主体类型和主体名称；
- 登录用户 ID 和用户名快照；服务器 CLI 操作时用户 ID 为空；
- Web、MCP 或 CLI 入口；
- 操作类型；
- 目标类型和目标 ID；
- 成功、失败或冲突结果；
- request ID；
- Web Session ID 或 MCP Token ID；
- 操作时间。

### 7.2 现有数据

现有知识数据继续全局共享，不增加 `user_id`、`tenant_id` 或 `workspace_id`：

- 原子事件；
- 因果关系；
- 具体案例；
- 案例关联；
- 文件导入与 AI 导入历史；
- 语义模型和向量索引。

需要被编辑或删除的业务实体增加递增版本号，初始值为 `1`。

## 8. 账号生命周期

系统不提供公开注册、邀请和找回密码入口。服务器维护者通过交互式 CLI 执行：

```bash
pnpm user:create
pnpm user:list
pnpm user:reset-password
pnpm user:disable
pnpm user:enable
```

规则：

- 创建账号时生成一次性初始密码，只显示一次；
- 首次登录只能进入设置新密码流程；
- 用户名创建后不可修改；
- 用户可以在 Web 中修改自己的密码；
- 忘记密码只能由服务器 CLI 重置；
- 账号不允许删除，只能停用；
- 停用立即撤销该用户的全部 Web 会话和 MCP Token；
- CLI 操作写入最小审计日志。

账号不可删除是为了保留已有导入历史和审计日志的身份关联。

## 9. 密码、登录和会话安全

### 9.1 密码

- 长度为 12–128 个字符；
- 拒绝用户名、纯重复字符和常见弱密码；
- 不强制大小写、数字和符号的固定组合；
- 使用 Argon2id 和独立随机盐；
- 不保存或记录明文密码；
- 登录错误统一显示“用户名或密码错误”。

### 9.2 失败保护

- 同一账号连续失败 10 次后锁定 15 分钟；
- 同一 IP 在 15 分钟内最多允许 20 次失败登录；
- 超过 IP 限制返回 `429`；
- 成功登录后清除账号失败计数；
- 锁定到期后自动解除；
- CLI 可以重置密码并解除锁定。

账号失败计数保存在 `users`，来源 IP 限流保存在 `auth_rate_limits`，因此 API 或服务器重启不会清除限制。IP 只保存带服务器密钥的摘要，不能从数据库直接还原。

### 9.3 Web 会话

- 使用至少 256 位随机会话令牌；
- 数据库只保存令牌哈希；
- 云端 Cookie 必须为 `Secure`、`HttpOnly` 和 `SameSite=Lax`；
- 空闲 12 小时失效；
- 最长 7 天后强制重新登录；
- 支持退出当前会话和退出所有设备；
- 修改密码后撤销其他 Web 会话；
- CLI 重置密码或停用账号时撤销全部会话；
- 修改类请求要求 CSRF Token 并校验 `Origin`；
- 不在 `localStorage`、URL 或日志中保存身份令牌。

当前本地部署仍使用 `http://127.0.0.1`。只有公开地址主机严格等于 `127.0.0.1` 或 `localhost` 时，才允许通过本地 Compose 关闭 Cookie 的 `Secure` 属性；此模式仍必须绑定回环地址。任何非回环地址或云端配置关闭 `Secure` 都视为启动错误。

## 10. 个人 MCP Token

每个用户可以创建最多 10 个有效 Token，并按设备命名。

规则：

- Token 随机秘密部分至少 256 位；
- 完整 Token 只在创建成功时显示一次；
- 数据库只保存哈希和短前缀；
- Token 默认长期有效，不自动过期；
- 用户可以单独撤销任一 Token；
- 页面显示创建时间、最近使用时间和最近客户端；
- 用户停用后全部 Token 立即失效；
- Token 只接受 `Authorization: Bearer` 请求头；
- 禁止使用查询参数传输；
- 日志和审计记录不得包含完整 Token。

客户端配置示例：

```json
{
  "transport": "streamable-http",
  "url": "https://causality.example.com/mcp",
  "headers": {
    "Authorization": "Bearer <个人访问令牌>"
  }
}
```

MCP 官方 HTTP 授权规范推荐 OAuth 2.1 发现与授权流程：

```text
https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization
```

P4-01 已明确不实现 OAuth。因此，是否支持上述手工 Bearer Token 配置由具体 MCP 客户端决定。

## 11. 授权边界

API 采用默认拒绝策略：新增路由必须明确声明为公开、Web 登录用户可用或内部 MCP 可用，否则启动期契约测试失败。公网只允许最小健康检查、登录和已认证 Web API。

MCP 专用授权和业务 API 迁移到 `/internal/mcp/*`，Caddy 不转发该路径。MCP 容器通过 Docker 私有网络访问，并同时提供内部服务密钥和当前个人 Token；API 验证服务身份、Token 哈希与用户状态。外部请求不能绕过 MCP Server 直接访问 MCP 专用 API。

所有启用用户都可以：

- 管理原子事件、因果关系、具体案例和案例关联；
- 使用局部因果图、普通查询和语义增强查询；
- 执行文件导入、导出、数据检查和问题处理；
- 修改语义模型、相似度门槛并重新索引；
- 创建和提交自己的 AI 入库方案；
- 查看全部成功文件导入与 AI 导入历史；
- 查看最小操作记录。

所有用户不能通过 Web 或 MCP：

- 创建、停用、启用或重置其他账号；
- 查看其他用户的密码、Web 会话或完整 MCP Token；
- 执行数据库迁移、备份恢复和服务器命令；
- 读取服务器密钥或容器环境变量。

后者属于服务器维护者的 SSH 与 CLI 权限，不属于应用业务角色。

## 12. 乐观并发控制

读取可编辑记录时返回版本号。保存或删除时提交 `expectedVersion`。

若数据库版本已经变化：

- 当前写操作不执行；
- API 返回 `409 CONCURRENT_MODIFICATION`；
- Web 保留当前表单输入并要求重新加载；
- MCP 返回结构化冲突错误；
- 不自动合并，不采用最后写入覆盖。

同一事务修改多条记录时，只要一条记录版本冲突，整个事务回滚。

删除操作发生冲突时，需要重新检查关联数据并再次确认。

## 13. AI 入库方案归属

- 候选对比和入库方案保存 `createdByUserId`；
- 只有创建方案的同一用户可以查看状态和提交；
- 同一用户可以通过自己的其他 MCP Token 继续处理；
- 其他用户不能提交或替换该方案；
- 成功入库后，结果历史对所有用户可见；
- 提交时重新检查业务版本和依赖指纹；
- 任一依赖变化时，方案整体失效并要求重新对比；
- 正式写入、审计和历史记录在同一事务完成。

等权用户拥有相同业务能力，但不能代替另一名用户确认其会话中的临时入库方案。

## 14. 全局后台任务

语义模型和索引继续属于共享知识库：

- 同一时间只允许一个模型下载、切换或完整索引任务；
- 任意用户可以启动任务；
- 重复请求返回当前任务状态，不重复创建任务；
- 模型切换、删除索引和重新索引记录发起用户；
- 普通数据变化继续进入增量索引队列；
- 索引失败不回滚已经成功提交的业务事务；
- 索引落后状态对所有用户可见。

## 15. 审计日志

最小审计日志保留 90 天，并由定时任务删除过期记录。

记录：

- 登录成功、登录失败、锁定和退出；
- 密码修改、CLI 重置；
- MCP Token 创建、撤销和认证失败；
- 业务数据新增、修改、删除和合并；
- 文件导入、AI 入库和数据维护；
- 模型切换、重新索引和参数修改；
- 账号创建、启用和停用；
- 写入失败和并发冲突。

不记录：

- 明文密码、Cookie、会话令牌和完整 MCP Token；
- 查询正文和完整 MCP 请求；
- 修改前后的完整业务内容；
- AI 对话、推理过程和网页内容；
- 普通只读列表与详情浏览。

成功的普通 MCP 调用不逐条写入审计表，只更新 Token 最近使用时间并保留脱敏服务日志；最近使用时间最多每 5 分钟更新一次，避免每次只读请求都写数据库。审计日志不提供编辑、删除、撤销和恢复功能。

## 16. Web 页面

### 16.1 登录与账号

- 未登录访问业务路由时跳转登录页并保存原地址；
- 登录页只显示用户名、密码和登录按钮；
- 首次登录强制进入设置新密码页面；
- 左侧导航底部显示当前用户名；
- 用户入口提供修改密码、退出当前会话和退出所有设备；
- 不显示角色、注册、找回密码和用户管理入口。

### 16.2 MCP 参数配置

现有全局 MCP Token 面板改为当前用户的个人 Token 管理：

- 显示服务状态、公网端点、协议和能力数量；
- 显示当前用户 Token 列表；
- 支持创建、一次性显示和撤销；
- 显示短前缀、设备名、创建时间、最近使用和客户端；
- 撤销使用二次确认。

### 16.3 操作记录

新增电脑端“操作记录”标签，采用现有紧凑列表风格。显示时间、用户、入口、操作类型、目标和结果。支持用户、入口、操作类型、结果和时间范围筛选；每页 50 条并支持页码跳转。

超长目标名称使用现有省略与 Tip 组件。页面不显示字段修改前后值。

### 16.4 并发与错误

- 冲突时保留表单内容；
- 显示不会自动消失的并发提示和“重新加载”入口；
- 普通保存错误继续使用现有位置和 3 秒自动消失规则；
- 列表不实时推送其他用户修改；
- 翻页、搜索、返回列表或手工刷新时获取最新数据。

统一状态语义：

- `401`：会话无效；
- `403`：账号停用或操作不可用；
- `409`：数据版本冲突；
- `423`：账号临时锁定；
- `429`：请求过于频繁；
- `503`：维护模式或依赖暂不可用。

登录接口只有在用户名和密码正确但账号仍处于锁定期时才返回 `423`；错误密码始终返回通用 `401`，避免通过响应差异探测账号。

## 17. 公网代理与网络安全

Caddy 是唯一公网入口，负责：

- 自动申请和续期 TLS 证书；
- HTTP 跳转 HTTPS；
- Web、API 和 MCP 同域名转发；
- 按路由设置请求大小和连接超时；
- HSTS、内容类型保护等响应头；
- 覆盖外部伪造的转发头；
- 禁止记录 Authorization、Cookie 和请求正文。

登录与业务请求限流由 API 实现，MCP 请求限流由 MCP Server 按 Token 和来源执行，不依赖非标准 Caddy 插件。默认上限为每个 MCP Token 每分钟 60 次、每个来源每分钟 120 次；超过限制返回 `429`，且不创建业务事务。上限可以通过生产环境配置降低，但不能在运行时由普通 Web 页面修改。

MCP Server 对带 `Origin` 的请求只接受配置的公网域名；原生 AI 客户端通常不发送 `Origin`，这种请求仍必须通过个人 Token 认证。

服务器防火墙只开放：

- `80/tcp`；
- `443/tcp`；
- 使用密钥登录且限制来源的 SSH 端口。

禁止 PostgreSQL、Docker API、API、MCP 和语义 Worker 直接暴露公网。应用容器不以 root 用户运行。

## 18. Compose 与生产密钥

部署配置拆分为：

```text
compose.yaml
compose.local.yaml
compose.cloud.yaml
```

- `compose.yaml` 定义公共服务；
- `compose.local.yaml` 只提供本机回环端口；
- `compose.cloud.yaml` 增加 Caddy、云端域名、备份和安全配置。

本地覆盖显式设置回环公开地址和非 Secure Cookie；云端覆盖显式设置 HTTPS 公开地址和 Secure Cookie。生产预检必须拒绝非回环 HTTP 地址或云端非 Secure Cookie。

建议服务器目录：

```text
/opt/causality/
├── repository/
├── environment/
├── secrets/
├── backups/
└── caddy-data/
```

数据库密码、会话密钥和内部服务密钥互相独立，通过服务器密钥文件或 Compose Secret 注入，不进入 Git。生产数据库不使用示例密码。容器日志必须轮换。

## 19. 备份与恢复

### 19.1 备份

- 每天执行压缩 PostgreSQL 备份；
- 本机保留最近 14 天；
- 加密复制到服务器之外的对象存储或另一台设备；
- 异地副本至少保留最近 30 天；
- 数据库迁移和应用升级前额外备份；
- 每月自动执行一次恢复验证；
- 备份失败产生明确告警。

备份包含业务数据、用户、会话状态、Token 哈希、导入历史、审计和系统配置。语义模型可以重新下载，向量索引可以重建，不作为关键备份对象。

### 19.2 恢复

恢复流程：

1. 进入维护模式并停止新写入；
2. 停止 API、MCP 和语义 Worker；
3. 恢复指定数据库备份；
4. 检查版本并执行必要迁移；
5. 启动 API；
6. 重建或继续语义索引；
7. 验证登录、查询、写入和 MCP；
8. 退出维护模式。

恢复后全部 Web 会话失效。恢复点中仍存在的个人 MCP Token 继续有效；服务器维护者可以执行统一撤销命令。

## 20. 单机可靠性边界

本方案不提供高可用：

- 服务器重启期间应用不可用；
- 主机或磁盘故障需要从异地备份恢复；
- 部署升级允许短暂停机；
- 不支持多实例负载均衡和自动故障转移。

用户规模扩大或可用性要求提高后，优先将 PostgreSQL 迁移到托管数据库，再评估多实例应用服务。

## 21. 已接受的残余风险

- 不使用 TOTP 时，密码泄露会使攻击者取得该用户的全部业务权限；
- 个人 MCP Token 长期有效，泄露后会持续可用直到用户撤销或账号停用；
- 不实现 OAuth 会使部分只支持标准授权发现的 MCP 客户端无法连接；
- 所有用户等权，任一账号都可以删除业务数据、处理数据问题和触发全局索引任务；
- 审计日志不保存字段快照，不能用于撤销具体修改；
- 单台服务器仍是单点故障。

强密码、失败锁定、个人 Token 独立撤销、乐观并发、最小审计和异地备份只能降低这些风险，不能完全消除。若用户范围扩大，不应直接沿用本设计，需要重新评估 TOTP、OAuth、角色权限和高可用。

## 22. 迁移策略

1. 升级前生成数据库备份；
2. 新增用户、会话、个人 Token、审计和版本字段；
3. 现有业务记录版本设为 `1`；
4. 保留现有知识数据和成功导入历史；
5. 使升级时未提交的 AI 入库方案失效；
6. 通过 CLI 创建首个用户；
7. 用户首次登录并创建个人 MCP Token；
8. 更新所有 AI 客户端配置；
9. 禁用多用户模式下的全局 MCP Token；
10. 验证完成后再进入公网服务状态。

旧全局 Token 数据暂时保留用于紧急版本回退，但新版本运行时不接受它。旧 Token 不自动归属用户。

没有用户时，应用只允许最小健康检查和服务器 CLI 建号，不允许匿名访问业务数据。本地正式部署升级后同样要求登录，不建立生产认证绕过模式。

## 23. 实施任务顺序

### Task 1：用户、会话与认证基础

数据库表、密码服务、会话、登录限流、失败锁定、用户 CLI 和统一身份。

### Task 2：Web 登录与账号操作

登录、首次修改密码、路由保护、修改密码、退出和统一认证错误处理。

### Task 3：个人 MCP Token 与远程身份

Token 生命周期、MCP 用户认证、参数配置页面、诊断和兼容测试。

### Task 4：多人乐观并发

业务版本、编辑与删除冲突、AI 方案归属和依赖重新验证。

### Task 5：最小审计日志

审计服务、关键操作接入、90 天清理和操作记录页面。

### Task 6：云端 Compose 与 HTTPS

Compose 拆分、Caddy、网络隔离、生产密钥、部署升级和重启持久化。

### Task 7：备份、恢复与维护模式

自动备份、异地复制接口、恢复、维护模式和恢复验证。

### Task 8：整体验收与交付文档

本地升级、全新云端安装、双用户并发、远程 MCP、恢复、README 和最终复核。

每个 Task 开始前单独编写详细设计并由用户审核；审核后再编写实施计划和代码。涉及 Web 的 Task 必须完成人工复核。

## 24. 自动化测试

必须覆盖：

- 密码哈希、弱密码拒绝和初始密码；
- 登录失败、账号锁定、IP 限流和自动解锁；
- 重启后账号锁定和 IP 限流仍然有效；
- Cookie、CSRF 和 Origin 校验；
- 会话退出、全部退出、密码重置和账号停用；
- MCP Token 一次性显示、哈希、独立撤销和停用失效；
- 撤销 Token 或停用用户后已有 MCP 会话的下一次请求失败；
- 两个用户同时使用 Web 和 MCP；
- 所有受保护 API 拒绝匿名访问；
- `/internal/mcp/*` 不能通过公网 Caddy 访问；
- 乐观并发冲突和事务回滚；
- AI 入库方案归属和跨用户提交拒绝；
- 审计脱敏和 90 天清理；
- Caddy 路由和内部端口隔离；
- 现有数据迁移与保留；
- 备份、恢复、重启和语义索引重建。

## 25. 人工验收

1. CLI 创建两个用户；
2. 两个用户分别首次登录并修改密码；
3. 两个用户看到同一套知识库；
4. 同时编辑同一记录时不会相互覆盖；
5. 两个用户分别创建个人 MCP Token；
6. 两个 AI 客户端同时连接远程 MCP；
7. 撤销一个 Token 不影响另一用户；
8. 停用用户后其 Web 会话和 Token 立即失效；
9. 操作记录能区分用户和入口；
10. 云服务器重启后数据完整；
11. 数据库可以从异地备份恢复；
12. PostgreSQL、API、MCP 和语义 Worker 端口不能从公网直接访问。

## 26. 完成标准

P4-01 只有同时满足以下条件才标记完成：

- 所有已确认的 Task 1–8 完成；
- 现有知识数据无损迁移；
- 匿名用户无法访问任何业务数据；
- 两个等权用户可以同时使用共享知识库；
- Web 和个人 MCP Token 身份均可正确追溯；
- 多人编辑不会静默覆盖；
- 全局 MCP Token 在多用户模式下失效；
- 公网只暴露统一 HTTPS 入口；
- 自动备份和恢复验证通过；
- 全仓自动化质量门禁通过；
- 用户完成人工复核。
