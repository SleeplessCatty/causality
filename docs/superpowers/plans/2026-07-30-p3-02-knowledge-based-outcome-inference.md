# P3-02 Knowledge-Based Outcome Inference Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a read-only `causality_infer_outcomes` Prompt and `Causality Infer Outcomes` Skill that infer up to five downstream outcomes for one database event through existing MCP evidence tools, while extending `search_atomic_events` with compatible semantic-enhanced matching.

**Architecture:** Keep the application free of an embedded online AI and add no outcome-aggregation API or MCP Tool. Extend the existing atomic-event search Tool with an optional `standard/enhanced` mode, then let one canonical Prompt orchestrate event matching, bounded downstream graph queries, path verification, evidence loading, and a fixed user-facing report. Generate the portable Markdown Prompt and expose a thin Codex Skill from that same source so Streamable HTTP, stdio, portable prompts, and Codex all share one policy.

**Tech Stack:** TypeScript 6, Node.js 24, Zod 4, `@modelcontextprotocol/sdk` 1.30, Vitest 4, pnpm 11, YAML Skill metadata, Markdown documentation.

## Global Constraints

- Support exactly one starting atomic event per inference run.
- Search downstream only; use a default maximum path depth of 3.
- Display at most 5 candidate outcomes in the first report.
- Query 20 graph nodes first, then 50 and 100 only when the prior result is truncated and fewer than 5 relevant outcomes are available.
- Keep relations with `minConfidence = 0` and `minCaseCount = 0`; label every zero-case relation as having no case evidence.
- Verify each selected outcome with `find_causal_paths` using `maxDepth = 3` and `pathLimit = 10`.
- Display at most 3 paths per outcome and at most 3 cases per displayed relation.
- Do not calculate an aggregate evidence grade, average confidence, multiplied confidence, or outcome probability.
- Keep database facts separate from model selection, ordering, explanation, and external information.
- Add no new MCP Tool, database table, migration, Web page, internal online AI, inference history, or automatic write path.
- Preserve all five controlled capture tools and require a separate `Causality Capture` workflow for any write request.
- Keep `search_atomic_events` backward compatible: omitted `searchMode` means `standard`.
- Keep Streamable HTTP and stdio on the same MCP Server factory with 15 Tools, 5 Prompts, and 4 Resources.
- Use TDD for every production behavior change and commit only the files belonging to the current task.
- Do not push GitHub during task execution; push only after the complete stage has passed code review and manual acceptance.

1. **分析范围**：起始事件、下游方向、三层范围、候选上限和截断状态。
