# 通用因果知识应用总体实施阶段路线图

版本：V1.10
日期：2026-07-27
状态：第一阶段 v0.1.0 已正式发布，P2-01、P2-02 已完成，下一步进入 P2-03 设计阶段

## 1. 路线图目标

本路线图只确定：

- 已确定的技术选型与版本；
- 第一、第二和第三阶段的范围；
- 各实施步骤的正确开发顺序；
- 每一步的设计、开发、自动化测试和人工复核门禁；
- 每一步需要交付的可验证结果。

本路线图不提前展开每个步骤的字段、接口、页面细节和测试用例。每个步骤开始前，必须单独编写设计文档并交由用户审核；设计未获批准，不得开始该步骤的代码实现。

## 2. 文档优先级

当前仓库中的 `docs/application-design-spec.md` 记录了早期模型，其中“具体事件归属于单个抽象事件”“置信度自动计算”“默认展示全局因果网络”等内容已经被后续讨论推翻，只作为历史参考，不再作为开发依据。

后续开发按以下优先级解释需求：

1. 用户最新明确指示；
2. 用户审核通过的当前实施步骤设计文档；
3. 本总体路线图；
4. 其他历史研究和设计文档。

如果不同文档发生冲突，必须在实施前指出冲突并按以上优先级处理，不得自行选择旧规则。

## 3. 已确认的核心模型

第一阶段只包含三个核心业务对象：

1. **抽象原子事件**：因果关系中的节点；事件名称必填，别名可选且可定义多个。
2. **抽象因果关系**：连接原因事件和结果事件的有向关系；置信度完全由用户人工填写和调整。
3. **具体案例**：最多 100 字的独立真实事件叙述；可以不关联关系，也可以同时支持多条抽象因果关系，不作为全局图节点。

第一阶段不记录条件化因果关系，不记录反例或不确定案例，不自动计算置信度，不使用 AI、嵌入模型或向量搜索。

## 4. 已确认的产品边界

- 产品以桌面端 Web 应用为主，第一、第二阶段暂不安排移动端适配。
- 前端和后端分离，但保存在同一个 Monorepo 中。
- 主展示方式为围绕一个事件生成的局部因果图，不绘制整个知识库。
- 局部图支持：上游和下游、仅上游、仅下游三种查询方向。
- 初始显示最多 20 个节点，可扩展到 50 个、100 个；100 个以后不再整体扩展。
- 节点拖动只在当前局部图会话中临时固定；重新生成图时重新布局。
- 扩展局部图时重新取得完整结果并执行完整布局，不保留旧节点坐标。
- 不实现“悬浮节点时高亮前后各 5 个节点”的功能。
- 不使用悬浮高亮；选择节点或关系后按其一跳邻接范围高亮。
- 关系显示人工置信度和具体因果案例数量。
- 传统搜索使用事件标准名称、多个别名和关键词；候选项不展示匹配原因。
- 语义搜索不属于第一阶段；第二阶段通过用户主动触发的增强查询实施。

## 7. 每个实施步骤的固定工作流

每个步骤都必须按以下顺序执行：

### 7.1 请求进入步骤

开始前先说明：

- 即将进入的步骤；
- 该步骤解决的问题；
- 该步骤不包含的内容；
- 前置步骤是否已经通过验收。

随后明确请求用户确认是否进入该步骤。未得到确认，不创建设计文档、不修改代码。

### 7.2 编写步骤设计文档

用户同意进入后，创建：

```text
docs/stages/phase-<阶段>/<步骤编号>-<名称>-design.md
```

设计文档至少包含：

- 目标和非目标；
- 用户操作流程；
- 数据模型或接口；
- 页面结构和交互；
- 校验和错误状态；
- 自动化测试方案；
- 人工复核步骤；
- 本步骤预计创建和修改的文件。

设计文档完成后先交给用户审核。用户可以要求缩小范围、拆分步骤或调整顺序。

### 7.3 设计审核门禁

只有用户明确批准设计文档后，才能开始编码。设计审核期间不得提前搭建、实现或修改相关代码。

### 7.4 开发实施

- 严格按照已批准设计实施；
- 不加入设计文档之外的附加功能；
- 优先测试驱动或测试同行；
- 保持每次修改范围小且可审查；
- 遇到影响数据模型或交互的新增决策时停止开发并请求确认。

### 7.5 自动化验证门禁

实现完成后，根据步骤范围运行：

```text
pnpm lint
pnpm typecheck
pnpm test
pnpm test:integration
pnpm test:e2e
pnpm build
```

不要求每个步骤都运行全部命令，但必须运行所有与该步骤相关的检查。涉及 Web 页面和局部因果图的步骤，Playwright 和真实浏览器检查是完成标准的一部分。

自动化验证结果必须报告：

- 实际执行的命令；
- 通过数量；
- 失败数量；
- 未执行项及原因；
- 已知限制。

### 7.6 用户人工复核门禁

自动化测试通过后，提供一份简短、可逐项执行的人工验收清单。涉及 Web 页面时，应启动实际应用并让用户在浏览器中检查。

用户未确认通过前：

- 不把该步骤标记为完成；
- 不请求实现下一个步骤；
- 可以按用户反馈修复并重新进行自动化和人工验收。

### 7.7 步骤完成与下一步请求

只有用户明确确认人工验收通过后，才更新进度记录，并请求是否进入下一步骤。系统不得自动连续执行多个步骤。

## 8. 第一阶段：基础可用应用

第一阶段目标：交付一个桌面端、单用户、可实际录入和查询数据的基础应用。用户能够维护抽象原子事件、抽象因果关系和具体因果案例，并以一个中心事件生成最多 100 个节点的局部因果图。

### P1-01 项目基础与质量门禁

**目标：** 建立 Monorepo、Web/API 空应用、共享契约包、PostgreSQL 开发环境和统一质量命令。

**交付：**

- Web 首页可以打开；
- API 健康检查可访问；
- API 可以连接开发数据库；
- 根目录统一执行 lint、typecheck、test 和 build；
- 版本矩阵和锁文件生效；
- 建立后续步骤设计文档和测试报告约定。

**不包含：** 业务表、业务页面、认证、局部图。

### P1-02 核心数据模型、迁移与测试数据工具

**目标：** 建立抽象事件、事件别名、抽象因果关系、具体因果案例的数据库模型和约束。

**交付：**

- 可重复执行的数据库迁移；
- 唯一性、方向性和外键约束；
- 人工置信度字段；
- 首个具体案例数据模型；该模型将在 P1-05 按最新需求迁移为独立案例与多对多关联；
- 小型固定种子数据；
- 可配置规模的模拟数据生成工具；
- 数据库集成测试。

**不包含：** CRUD 页面和局部图查询。

### P1-03 抽象原子事件管理

**目标：** 完成事件的创建、列表、搜索、查看和编辑闭环。

**交付：**

- 事件 REST API；
- 事件列表与详情页面；
- 创建和编辑表单；
- 标准名称必填；
- 可选多个别名；
- 基于名称、别名和关键词的传统搜索；
- 候选项不显示匹配原因；
- 页面与 API 自动化测试；
- 浏览器人工验收流程。

**不包含：** 语义搜索、AI、关系创建。

### P1-04 抽象因果关系管理

**目标：** 完成原因事件到结果事件的有向关系管理。

**交付：**

- 关系 REST API；
- 关系列表、详情、创建和编辑页面；
- 搜索选择原因事件和结果事件；
- 阻止自环和同向重复关系；
- 允许反向关系独立存在；
- 人工填写和调整置信度；
- 关系状态与案例数量占位；
- 自动化和人工验收。

**不包含：** 自动置信度、条件化关系、局部图。

### P1-05 具体因果案例管理

**目标：** 独立维护真实案例，并将案例作为支持记录关联到一条或多条抽象因果关系。

**交付：**

- 案例 REST API；
- 案例列表、详情、创建和编辑页面；
- 案例保存最多 100 字的真实事件叙述；
- 案例可以独立存在，并与关系多对多关联；
- 关系表单支持搜索、选择或创建案例；
- 关系详情显示案例数量和最近 5 条；
- 案例关联变化只更新计数，不自动改变置信度；
- 自动化和人工验收。

**不包含：** 结构化时间、地点和来源，反例、不确定案例、附件系统。

### P1-06 局部因果图查询 API

**目标：** 从中心事件稳定查询局部上游、下游或双向子图。

**交付：**

- 上游和下游、仅上游、仅下游三种模式；
- 20、50、100 节点限制；
- 关系数量保护上限；
- 确定性排序；
- 循环检测；
- 置信度和案例数量返回；
- 返回停止原因，不计算完整可达数量；
- 使用较大模拟数据进行数据库集成和性能基线测试。

**不包含：** 图形页面和布局。

### P1-07 局部因果图基础展示

**目标：** 使用 Cytoscape.js 和 ELK 展示初始 20 节点局部因果图。

**交付：**

- 搜索并选择中心事件；
- 三种查询方向切换；
- 有向分层布局；
- 节点显示事件名；
- 关系显示人工置信度和案例数量；
- 箭头、曲线、基础节点类型样式；
- Zoom、Pan、适应屏幕；
- 空数据、加载和错误状态；
- Playwright与浏览器人工视觉验收。

**不包含：** 50/100扩展、拖动固定、详细信息卡。

### P1-08 局部图交互与信息查看

**目标：** 完成节点和关系的基础交互。

**交付：**

- 完全取消节点和关系的悬浮交互；
- 选择节点时高亮一跳关系及另一端节点；
- 选择关系时高亮关系及两端节点；
- 未关联元素保持原样，不降低透明度；
- 方向键按节点→关系→节点执行空间导航；
- 空格独立开关右侧详情检查器；
- 节点信息和关系案例摘要按当前选择切换；
- 节点拖动后在当前图中临时固定；
- 重新生成或重新布局时清除临时位置；
- 节点可被设置为新的中心事件；
- 键盘和鼠标交互测试；
- 浏览器人工验收。

**不包含：** 扩展布局稳定性和持久化布局。

### P1-09 局部图扩展、筛选与布局稳定性

**目标：** 完成 20 → 50 → 100 的渐进扩展和可读性保护。

**交付：**

- 扩展到50和100节点；
- 100节点后阻止继续整体扩展并给出下一步提示；
- 每次扩展重新取得完整结果并执行完整布局；
- 查询和布局期间保留旧图，成功后原子替换并建立可读视口；
- 手工拖动节点在当前图中保持临时固定；
- 最低置信度和最低案例数筛选；
- 显示当前节点/关系数量和查询停止原因；
- 关系数量超过保护上限时明确提示；
- 20、50、100节点模拟数据视觉回归和交互测试。

**不包含：** 新布局引擎和全局因果图。

### P1-10 第一阶段整体验收与容器化交付

**目标：** 将第一阶段功能作为一个可重复部署和验收的完整应用交付。

**交付：**

- Web、API、PostgreSQL生产容器；
- 一个 `compose.yaml` 启动完整应用；
- 数据库持久化卷和健康检查；
- 从空库执行迁移和种子数据；
- 完整自动化回归；
- 桌面浏览器人工验收清单；
- 第一阶段已知限制和第二阶段入口说明。

**第一阶段完成标准：** 用户明确确认 P1-01 至 P1-10 全部人工验收通过。

## 9. 第二阶段：优化与扩展

第一阶段已经完成自动化门禁、用户人工复核和 `v0.1.0` 正式发布。用户于 2026-07-23 确认进入第二阶段，并同意按照本节确定的顺序逐步实施。

### 9.1 确认执行顺序与阶段门禁

第二阶段按以下顺序推进：

1. P2-01 数据清理、安全删除与完整性检查；
2. P2-02 语义增强搜索；
3. P2-03 批量导入与公开录入接口；
4. P2-04 局部因果图体验与性能优化；
5. P2-05 历史案例检索与路径分析；
6. P2-06 生产运维与安全增强。

现有普通搜索保持不变，语义增强只在用户主动操作时调用。批量导入必须复用语义候选能力，帮助用户发现名称不同但含义可能相同的原子事件；系统只提供疑似重复候选，最终是否复用已有事件仍由用户人工确认。

每个步骤仍采用与第一阶段相同的渐进式门禁：

1. 先请求用户确认是否进入下一步骤；
2. 只编写当前步骤的设计文档，不提前展开后续步骤；
3. 设计文档经用户审核通过后，才进入实现；
4. 实现完成后先执行对应自动化测试和回归门禁；
5. 涉及 Web 页面操作的步骤必须交付桌面端人工复核路径；
6. 只有用户确认人工复核通过后，当前步骤才标记为“已完成”并进入下一步骤；
7. 任一门禁失败时停留在当前步骤修复，不并行推进后续业务步骤。

以下各任务的“候选交付”只确定总体范围。具体字段、接口、页面、迁移、兼容策略、性能指标和测试用例必须在对应步骤的设计文档中确定。

第二期开发期间只保留必要的本地阶段提交，不在每个步骤结束后频繁推送 GitHub。P2-01 至 P2-06 全部完成、完整代码检查和用户人工验收通过后，再统一推送第二期成果。

### P2-01 数据清理、安全删除与完整性检查

**目标：** 提升人工知识库长期维护的可靠性。

**候选交付：**

- 三类主记录的安全永久删除；
- 删除影响检查、引用保护和关联清理；
- 孤立记录统计与列表跳转；
- 手动异步数据检查和最近一次成功快照；
- 完整性错误、疑似重复警告和逐条处理。

### P2-02 语义增强搜索

**目标：** 保持现有普通搜索简单快速，并在用户主动请求时识别名称或说明不同但含义可能相同的原子事件、因果关系和具体案例，为后续批量导入去重提供候选。

**候选交付：**

- 独立“参数配置”页面；
- 四个固定版本的本地嵌入模型；
- 模型手动首次下载、自动加载、索引进度和离线复用；
- 独立 TypeScript 语义任务服务；
- 普通搜索保持现有自动查询方式；
- 三个主列表提供用户主动触发的增强查询入口；
- 中英文混合嵌入模型评测；
- pgvector 和 HNSW 索引；
- 普通搜索与语义搜索候选合并；
- 每个模型独立的可配置相似度门槛；
- 不记录搜索日志，不展示匹配原因；
- 用户继续人工选择；
- 不自动创建事件和关系。

### P2-03 批量导入与公开录入接口

**目标：** 在保持人工确认原则的前提下提高录入效率，并使用语义搜索候选降低重复事件入库风险。

**候选交付：**

- CSV/JSON导入；
- 导入前预览；
- 字段和引用校验；
- 重复数据报告；
- 失败行下载；
- 稳定的外部录入API；
- 导入数据进入人工审核流程。

### P2-04 局部因果图体验与性能优化

**目标：** 根据100节点真实使用情况优化布局和交互。

**候选交付：**

- ELK参数调优；
- 布局计算移入Web Worker；
- 关系标签碰撞和语义缩放优化；
- 大量关系的视觉降噪；
- 必要时独立评估fCoSE增量布局；
- 真实数据性能基线和视觉回归。

### P2-05 历史案例检索与路径分析

**目标：** 更方便地从当前事件或关系查找相关历史支持案例和多段因果路径。

**候选交付：**

- 按事件和关系聚合历史案例；
- 上下游路径查询；
- 路径长度和最低关系置信度筛选；
- 循环路径解释；
- 从图中进入路径和案例详情。

本步骤仍不自动计算最终利好/利空概率。

### P2-06 生产运维与安全增强

**目标：** 在需要长期部署时补齐生产能力。

**候选交付：**

- 数据备份和恢复演练；
- 日志、指标和错误追踪；
- API限流和安全响应头；
- 数据库查询监控；
- 镜像安全扫描；
- 如确有多用户需求，再单独设计认证和权限。

## 10. 第三阶段：MCP、AI 辅助录入与知识推演

第三阶段只记录候选开发方向，不在第二阶段完成前展开详细需求、技术选型或实施计划。第三阶段继续坚持“AI 只生成候选或推测，正式知识由人工确认”的产品边界。

### P3-01 MCP Server 与外部 AI 接入

**目标：** 让外部 AI 模型工具通过标准 MCP 接口使用 Causality。

**候选交付：**

- 提供 Causality MCP Server；
- 向外部 AI 暴露知识查询和候选提交工具；
- MCP 只能提交待审核数据，不能直接修改正式知识；
- 工具能力、权限、限流、错误返回和调用记录。

### P3-02 多来源关联数据提取

**目标：** 让外部 AI 从长文本文档、网页链接或交互式问答中提取相互关联的候选知识。

**候选交付：**

- 提交候选原子事件、因果关系和具体案例；
- 候选数据必须形成有关联的局部结构，不接受完全独立的数据集合；
- 保留原始来源、引用位置和提取上下文；
- 支持长任务的进度、失败重试和批次管理；
- AI 提取置信度与正式关系的人工置信度分开记录。

### P3-03 候选对比、去重、归类与关联

**目标：** 将 AI 候选与已有数据库比较，筛选出适合进入人工审核的数据。

**候选交付：**

- 查找可能相同或相近的已有事件、关系和案例；
- 区分复用已有记录、补充已有记录和创建新记录；
- 检测重复、反向关系、潜在冲突和来源重叠；
- 将候选归入已有因果网络，而不是生成孤立数据；
- 批量展示自动建议，由用户决定最终处理方式。

### P3-04 人工审核与事务化入库

**目标：** 建立 AI 候选进入正式知识库之前的审核门禁。

**候选交付：**

- 按批次审核事件、关系、案例及其关联；
- 支持接受、修改、合并、拒绝和暂缓；
- 展示来源证据、已有数据对比和关联影响；
- 只有完整关联且审核通过的数据才能事务化入库；
- 保留审核决定和入库结果，支持失败恢复。

### P3-05 MCP 知识查询与证据检索

**目标：** 让外部 AI 在对话中安全、受控地查询正式知识库。

**候选交付：**

- 查询原子事件、因果关系、具体案例和局部因果图；
- 查询上下游关系、历史案例和多段因果路径；
- 返回可追溯的记录标识和来源证据；
- 控制查询深度、数量、置信度和案例数，避免无界查询；
- 区分数据库事实、关系记录和 AI 生成的解释。

### P3-06 基于知识库的结果推测

**目标：** 让外部 AI 基于数据库中的因果链和案例，对事件可能产生的结果进行可解释推测。

**候选交付：**

- 从新事件查找相关上下游路径和历史案例；
- 输出可能结果、依据路径、支持案例和不确定性说明；
- 明确区分库中事实与模型推测；
- 推测结果不自动写入正式库、不自动调整置信度；
- 暂不自动预测股票价格、涨跌幅或目标价。

### P3-07 来源追踪、质量评估与反馈

**目标：** 评估 AI 辅助录入和查询是否稳定、准确且可追溯。

**候选交付：**

- 记录来源、模型、工具调用、候选批次和审核结果；
- 建立提取、去重、归类、查询和推测的人工评测集；
- 统计接受、修改、合并和拒绝比例；
- 识别常见遗漏、错误关联和错误推测；
- 使用人工审核反馈改进提示词与工具流程，但不自动训练或自动入库。

## 11. 明确不自动进入的后续方向

以下内容不属于当前已规划的第一、第二和第三阶段步骤，必须由用户另行决定：

- 自动抓取新闻；
- AI 绕过人工审核直接写入正式事件、关系或案例；
- 自动修改置信度；
- 记录反例和条件化关系；
- 统计因果推断；
- 自动预测股票涨跌幅或目标价；
- 移动端适配；
- 全局十万节点图；
- 多人实时协作。
