# P2-01 数据清理、安全删除与完整性检查设计

版本：V1.0
日期：2026-07-23
状态：设计已审核通过（2026-07-23），等待实施计划审核
所属路线图步骤：P2-01 数据清理、安全删除与完整性检查
前置条件：第一阶段 `v0.1.0` 已发布，第二阶段执行顺序已确认

## 1. 目标

为长期人工维护知识库补齐三类能力：

1. 允许用户安全地永久删除原子事件、因果关系和具体案例；
2. 通过系统状态页面统计孤立记录，并跳转到对应列表人工处理；
3. 由用户手动启动异步数据检查，保存最近一次成功快照，展示并逐条处理完整性错误和疑似重复警告。

P2-01 不判断事件是否足够原子，也不判断因果关系是否真实合理。所有检查必须建立在可以客观验证的数据或关联规则上。

## 2. 范围

### 2.1 包含

- 三类主记录的永久删除；
- 删除影响预检、二次确认、引用保护和事务化清理；
- 孤立原子事件、无案例因果关系、孤立具体案例统计；
- 三个列表的隐藏孤立过滤条件；
- 手动启动、数据库持久化的单个异步检查任务；
- 最近一次成功检查快照；
- 完整性错误和疑似重复警告；
- 问题分页、筛选、自动处理、手动处理和已处理状态；
- 约 10 万事件、50 万关系、10 万案例的数据检查性能基准。

### 2.2 不包含

- 软删除、归档、回收站或恢复；
- 置信度修改历史；
- 关键字段修改历史；
- 删除记录或问题处理的审计历史；
- 自动合并重复事件；
- 批量修复或一键修复；
- 模糊相似度、语义搜索或 AI 判断；
- 自动判断事件原子性或因果合理性；
- 自动更新孤立统计或定时检查；
- 移动端适配。

## 3. 核心定义

- **永久删除**：不可从应用恢复的主记录删除。
- **孤立原子事件**：没有作为任何关系原因或结果的事件。
- **无案例因果关系**：没有关联任何具体案例的关系。
- **孤立具体案例**：没有关联任何关系的案例。
- **完整性错误**：违反确定性字段、唯一性或引用规则的数据。
- **疑似重复警告**：跨事件标准名称和别名精确冲突产生的人工判断线索。
- **检查任务**：用户手动启动的一次异步数据检查，同一时间最多一个。
- **检查快照**：最近一次成功任务产生的孤立统计和问题列表。
- **已处理问题**：只在当前快照中标记完成的问题；不等同于永久忽略。

孤立记录是维护提醒，不属于完整性错误或警告。

## 4. 已确认决策

- 原子事件、因果关系和具体案例都使用永久删除，不提供软删除。
- 三个列表在“编辑”后增加“删除”，详情页和编辑页不增加删除入口。
- 三类主记录删除都需要二次确认。
- 有关系引用的事件不能删除，只能跳转到相关关系列表处理。
- 删除关系不会删除事件或案例。
- 删除案例不会删除关系。
- 删除确认框不展开关联列表，不显示关联名称或数量，只说明是否有关联以及影响类型。
- 完整性问题的安全自动处理不需要二次确认。
- 不提供批量处理。
- 系统状态统计和完整性检查由同一个手动操作触发。
- 只保存最近一次成功检查快照；检查失败保留上次成功结果。
- 页面只显示检查时间，不判断或提示快照是否过期。
- 问题列表每页固定 50 条。
- 疑似重复警告不保存永久例外。
- P2-01 期间只创建必要的本地提交，不推送 GitHub。

## 5. 永久删除设计

### 5.1 通用流程

1. 用户在列表行点击“删除”；
2. 前端读取删除影响；
3. 前端打开对应确认框；
4. 用户确认后发送删除请求；
5. 后端在事务内重新检查引用；
6. 删除成功后刷新当前列表；
7. 如果当前页因删除失效，则回到上一页。

列表刷新保留搜索词、有效页码和隐藏过滤条件。删除不会刷新最近一次检查快照或孤立统计。

### 5.2 删除原子事件

没有关系引用时：

- 显示不可恢复的删除确认；
- 删除事件；
- 由现有从属关系一并删除其别名和关键词。

存在关系引用时：

- 禁止删除；
- 确认框只提示存在关联因果关系；
- 不展示名称、数量或列表；
- 只提供“取消”和“查看相关因果关系”；
- 跳转到 `/relations?eventId=<事件 ID>`。

后端删除请求必须再次检查关系引用。检查影响后新建的关系仍能阻止删除。

### 5.3 删除因果关系

确认框说明：

- 该记录关联原因事件和结果事件；
- 是否关联具体案例；
- 删除不会删除事件或案例。

确认后在同一事务中：

1. 删除该关系的全部关系—案例关联；
2. 删除因果关系主记录。

原因事件、结果事件和具体案例全部保留。

### 5.4 删除具体案例

确认框说明：

- 是否关联因果关系；
- 删除不会删除因果关系。

确认后在同一事务中：

1. 删除该案例的全部关系—案例关联；
2. 删除具体案例主记录。

所有因果关系保留。

### 5.5 删除错误

- 目标不存在：返回 404，前端关闭确认框并刷新列表；
- 事件仍被引用：返回 409 和专用错误码，前端切换到阻止状态；
- 删除影响读取失败：不打开确认框，使用现有短暂错误样式；
- 事务失败：不产生部分删除，列表保持原状；
- 不提供任何级联删除其他主记录的参数。

## 6. 孤立记录统计与列表过滤

### 6.1 统计

每次成功数据检查保存：

- 孤立原子事件数量；
- 无案例因果关系数量；
- 孤立具体案例数量。

三个统计卡片位于系统状态页面。点击后进入：

```text
/events?orphan=true
/relations?orphan=true
/cases?orphan=true
```

### 6.2 隐藏过滤

三个列表和对应后端查询支持 `orphan=true`，但页面不增加常驻筛选控件。

- 搜索、总条目数、总页数和分页都在孤立范围内计算；
- 关系列表另外支持 `eventId=<事件 ID>`，用于从事件删除阻止状态跳转；
- 点击左侧导航的普通列表入口时不保留隐藏参数；
- 统计卡片使用最近一次检查快照；
- 跳转后的列表查询当前数据库，因此实际条数可能与快照不同；
- 页面不显示快照过期提示。

## 7. 数据检查任务

### 7.1 执行方式

采用“PostgreSQL 任务状态 + API 内部执行器”：

- 用户点击后在数据库中创建运行状态；
- API 返回任务已启动，并在进程内异步执行；
- 不增加 Redis、消息队列、Worker 容器或定时任务；
- 使用数据库锁保证同一时间只有一个任务；
- 用户离开页面不影响任务；
- 前端返回页面后按数据库状态继续轮询。

### 7.2 一致性

孤立统计和所有检查规则使用同一个 PostgreSQL 一致性读取快照。扫描完成后，再在独立写事务中整体替换最近一次成功结果。

检查过程中允许用户继续使用应用。检查结果代表该次读取快照，不承诺与展示时的当前数据库完全一致。

### 7.3 成功、失败和中断

检查成功：

- 生成新的快照标识；
- 替换三类孤立统计；
- 删除旧问题并写入新问题；
- 保存成功时间和分类数量；
- 清除本次失败信息。

检查失败：

- 保存失败时间和简短错误；
- 保留最近一次成功统计和问题；
- 第一次检查失败时显示“暂无成功结果”。

API 启动时如果发现上次进程遗留的运行中任务，将其标记失败。系统不会自动重试，用户可以再次手动启动。

## 8. 检查规则

### 8.1 完整性错误

检查以下确定性问题：

- 关系的原因事件或结果事件 ID 不存在；
- 关系—案例关联指向不存在的关系或案例；
- 别名或关键词指向不存在的事件；
- 因果关系形成自环；
- 置信度不在 0–100；
- 同方向因果关系重复；
- 标准事件名称出现数据库级重复；
- 具体案例内容出现数据库级重复；
- 同一事件内部存在重复别名或关键词；
- 必填文本为空、未正确去除首尾空格或超过长度限制；
- 可选文本存在非空但去除首尾空格后为空的值；
- 关键词位置重复、越界或不连续；
- 更新时间早于创建时间；
- 当前数据库明确约束覆盖、但实际数据仍违反约束的其他情况。

当前数据库外键、唯一索引和检查约束会阻止多数问题。检查仍保留这些规则，用于发现手工修改、异常迁移或未来导入造成的损坏。

### 8.2 疑似重复警告

只采用标准化后的精确比较：

- 一个事件的别名与另一个事件的标准名称相同；
- 同一个别名被不同事件使用。

本阶段不使用字符相似度、全文相关性、向量或语义判断。

### 8.3 明确不检查

- 反向关系不是错误；
- 孤立记录不是错误或警告；
- 案例数量不会自动影响关系置信度；
- 事件是否原子；
- 因果关系是否真实、充分或具有条件；
- 具体案例是否足以证明关系；
- 股票最终利好、利空、涨跌幅或目标价。

## 9. 问题快照与展示

### 9.1 问题数据

每条问题保存：

- 快照标识；
- 错误或警告；
- 问题类型；
- 目标记录类型和 ID；
- 生成跳转所需的相关记录标识；
- 简短问题描述；
- 简短处理建议；
- 自动处理或手动处理；
- 未处理或已处理；
- 处理时间。

不保存历次问题，也不把问题处理状态作为永久例外。

### 9.2 列表

列表每页 50 条，只显示三列：

| 列 | 内容 |
|---|---|
| 问题描述 | 紧凑严重程度标识、简短描述和可用的详情、编辑或过滤列表链接 |
| 处理建议 | 简短处理方式 |
| 执行入口 | 自动处理、手动处理或已处理 |

列表支持按严重程度、问题类型和处理状态筛选。页面顶部显示错误、警告、未处理和已处理数量。

目标记录不存在时，问题描述显示可定位的剩余记录或原始 ID，不生成失效链接。

## 10. 问题处理

### 10.1 自动处理

适用于能够确定安全结果的从属数据：

- 删除失效别名；
- 删除失效关键词；
- 删除失效关系—案例关联；
- 删除确定重复的从属记录，并保留稳定排序下的第一条；
- 按稳定顺序重新整理关键词位置。

点击后不显示二次确认。后端必须在事务中重新验证：

- 问题仍存在且处理安全：修改数据并标记已处理；
- 问题已经不存在：不修改业务数据，直接标记已处理；
- 数据变化导致处理不再安全：返回错误，保留未处理。

处理成功后更新当前快照的未处理和已处理数量，不重新扫描全库，也不更新孤立统计。

### 10.2 手动处理

以下问题只提供查看、编辑或过滤列表链接：

- 自环关系；
- 置信度异常；
- 同方向重复关系；
- 主记录字段异常；
- 主记录缺失必要引用；
- 疑似重复事件。

用户自行处理后点击“手动处理”，系统只将当前快照中的问题标记为已处理，不验证或修改业务数据。

如果实际数据没有解决，下次完整检查会重新生成该问题。

### 10.3 不提供的操作

- 一键修复全部；
- 按类型批量处理；
- 从检查页面直接删除主记录；
- 永久忽略某条警告；
- 自动合并事件、关系或案例。

## 11. 数据模型

### 11.1 数据检查状态

新增单例状态记录，保存：

- 当前任务状态：空闲、运行中、成功或失败；
- 当前或最近一次尝试的开始和结束时间；
- 最近一次失败时间和错误；
- 最近一次成功时间和快照标识；
- 三类孤立数量；
- 错误、警告、未处理和已处理数量。

该记录是当前系统状态，不是检查历史。

### 11.2 当前检查问题

新增当前快照问题表：

- 每条问题具有稳定 UUID；
- 通过快照标识与当前成功结果关联；
- 保存规则类型、目标、描述、建议、处理方式和状态；
- 快照替换时删除上一快照问题；
- 问题状态更新不会修改快照检查时间。

### 11.3 现有表

- 不给三类主表增加 `deleted_at`；
- 不增加历史表；
- 保留现有事件—关系外键限制；
- 关系和案例删除显式清理关系—案例关联；
- 保留别名、关键词随事件删除的从属语义；
- 为孤立查询、事件过滤关系和检查规则补充经查询计划验证确有需要的索引。

## 12. 模块与接口

### 12.1 后端模块

- **删除模块**：读取删除影响并执行永久删除；
- **检查协调模块**：启动任务、维护单任务状态、恢复中断任务；
- **检查规则模块**：在一致性快照中生成问题；
- **检查快照模块**：替换和读取最近一次结果；
- **问题处理模块**：重新验证并执行自动处理，或记录手动处理。

检查规则模块使用统一的窄接口返回问题草稿。增加新规则不要求修改任务协调、分页或页面协议。

### 12.2 删除接口

```text
GET    /api/events/:eventId/deletion-impact
DELETE /api/events/:eventId

GET    /api/relations/:relationId/deletion-impact
DELETE /api/relations/:relationId

GET    /api/cases/:caseId/deletion-impact
DELETE /api/cases/:caseId
```

影响接口只返回关联是否存在和能否删除，不返回关联列表、名称或数量。

### 12.3 数据检查接口

```text
POST /api/data-checks
GET  /api/data-checks/latest
GET  /api/data-checks/latest/issues
POST /api/data-checks/issues/:issueId/auto-handle
POST /api/data-checks/issues/:issueId/manual-handle
```

- 启动成功返回 202；
- 已有任务时返回现有任务状态，不创建第二个任务；
- 最新状态接口返回任务、最近成功摘要和最近失败信息；
- 问题接口使用页码分页，每页固定 50 条；
- 处理接口只接受当前快照中的问题。

### 12.4 现有列表接口

```text
GET /api/events?orphan=true
GET /api/relations?orphan=true
GET /api/relations?eventId=<事件 ID>
GET /api/cases?orphan=true
```

隐藏条件可以与搜索和页码组合。

## 13. 页面设计

### 13.1 列表删除

- 三个列表在“编辑”后增加“删除”；
- 复用统一确认框外壳；
- 各资源使用不同影响文案和操作；
- 确认框不展开任何关联列表；
- 删除事件受阻时显示“查看相关因果关系”；
- 所有错误沿用现有位置和三秒自动消失样式。

### 13.2 系统状态

现有 `/system` 页面不新增独立子页面。

页面顶部按钮改为“检查系统与数据”：

- 重新读取 API 和数据库运行状态；
- 数据库可用时启动数据检查；
- 数据库不可用时保留旧快照且不启动任务；
- 运行中禁用重复启动；
- 返回页面后继续读取任务状态。

页面依次展示：

1. API 和 PostgreSQL 状态；
2. 数据检查状态、成功时间和最近失败信息；
3. 三张孤立统计卡片；
4. 问题摘要和筛选；
5. 三列问题列表和分页。

首次没有成功检查时显示明确空状态。失败但存在旧快照时，旧结果和本次失败信息同时显示。

## 14. 并发与错误处理

- 删除影响只用于展示，删除事务中的检查才是最终依据；
- 所有删除和自动处理使用数据库事务；
- 单任务限制由 PostgreSQL 状态和锁共同保证；
- 检查任务不持有跨越整个后台执行过程的应用内全局锁；
- 任务中断不会覆盖成功快照；
- 快照替换必须整体成功或整体失败；
- 自动处理只接受当前快照问题，旧问题 ID 返回冲突；
- 手动处理重复点击保持幂等；
- 列表、检查和处理错误不得清空已有成功数据。

## 15. 性能边界

- 问题列表只执行数据库分页，不向 Web 返回全部问题；
- 检查规则记录各自耗时，便于定位慢规则；
- 查询必须利用现有或新增索引，避免逐记录请求和 N+1 查询；
- 基准数据约为 100,000 个事件、500,000 条关系、100,000 个案例；
- 项目基准环境中一次完整检查初始目标为 30 秒内完成；
- 超过目标时视为性能失败，先优化规则查询和索引，不通过减少检查范围隐藏问题。

## 16. 实施拆分

实现阶段按以下小任务顺序执行：

1. 数据库与共享契约；
2. 永久删除后端；
3. 列表删除交互；
4. 孤立查询与异步检查任务；
5. 系统状态与问题处理；
6. 完整回归、性能基准和人工验收。

每个小任务完成对应自动化验证后再进入下一项。涉及列表删除和系统状态页面的任务必须提供桌面端人工复核路径。

## 17. 自动化验证

至少覆盖：

- 当前数据库从旧版本迁移后原数据完整；
- 删除影响只返回布尔影响，不泄露关联列表；
- 有关系事件无法删除；
- 无关系事件删除时别名和关键词同步删除；
- 删除关系只删除关系及关系—案例关联；
- 删除案例只删除案例及关系—案例关联；
- 删除不存在记录和并发新增引用的错误语义；
- 删除不会自动更新检查快照；
- 三类孤立查询的总数、搜索、分页和组合条件；
- `eventId` 关系列表过滤；
- 同时启动检查时只有一个任务；
- 成功检查整体替换旧快照；
- 失败和 API 中断保留最近成功结果；
- 所有确定性规则和两类疑似重复警告；
- 自动处理的重新验证、成功、已不存在和不再安全分支；
- 手动处理只更新当前问题状态；
- 下次检查重新发现未实际修复的问题；
- 问题筛选、固定 50 条分页和分类数量；
- 页面离开、返回、刷新和浏览器历史恢复；
- 生产容器迁移、运行和重启持久化；
- 大数据检查在性能门禁内完成。

## 18. 桌面端人工复核

实施完成后至少检查：

1. 三个列表删除按钮位置和危险样式一致；
2. 三类确认框不展示关联详情或列表；
3. 事件删除受阻和关系列表跳转正确；
4. 删除关系、案例后其他主记录仍存在；
5. 检查系统与数据按钮、进行中和失败状态；
6. 离开系统页面后任务继续，返回后恢复；
7. 三张统计卡片及隐藏过滤跳转；
8. 三列问题列表、筛选、页码和分类数量；
9. 自动处理、手动处理和已处理状态；
10. 页面刷新和容器重启后最近成功快照仍存在。

## 19. 完成标准

P2-01 只有同时满足以下条件才标记完成：

- 本设计文档通过用户审核；
- 六个实施小任务全部完成；
- 数据库迁移、自动化回归、性能基准和生产烟雾通过；
- 删除与系统状态页面完成桌面端人工复核；
- 用户明确确认人工复核通过；
- 总体路线图中的 P2-01 更新为“已完成”。

P2-01 完成后再请求是否进入 P2-02。第二期全部结束前不推送 GitHub。
