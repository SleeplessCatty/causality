# P2-03 批量导入、导出与数据治理增强设计

版本：V1.1

日期：2026-07-27

状态：设计文档待审核

所属路线图步骤：P2-03 批量导入、导出与数据治理增强

前置条件：P2-02 语义增强搜索已完成人工复核并推送至 GitHub

## 1. 目标

P2-03 在保持人工维护原则的前提下，提高关联因果数据的批量录入、备份和迁移效率。

本阶段采用以下职责边界：

1. 导入只负责确定性格式校验、严格文本匹配和追加数据；
2. 导入不得修改任何已有业务记录；
3. 语义相似、潜在重复和内容准确性不阻塞导入；
4. 入库后的数据质量问题由数据维护模块统一检查和人工处理；
5. 导出文件与导入文件使用完全相同的 CSV 格式；
6. 不保存原始导入文件或导出文件，只保存成功导入日志。

## 2. 范围

### 2.1 包含

- 独立“导入导出”主标签；
- CSV 批量导入；
- 成功导入历史与详情；
- 全量 CSV 导出；
- 按多个起始事件、方向和关系深度筛选导出；
- 原子事件与具体案例的高置信度语义查重；
- 数据检查问题的类型化操作弹窗；
- 原子事件、具体案例和重复关系的事务化合并；
- 从数据检查问题进入编辑页后的返回与单问题实时复查；
- 每个语义模型独立的数据查重门槛。

### 2.2 不包含

- JSON、Excel、ZIP 或其他文件格式；
- 外部或公开录入 API；
- 原始导入文件持久化；
- 失败导入历史；
- 无效记录内容或错误行日志；
- 导出文件或导出历史；
- 入库前语义审核或待审核列表；
- 自动判断数据内容是否真实、准确或满足逻辑原子性；
- 自动修改已有事件、案例或关系字段；
- 用户、权限或多租户功能；
- 第三阶段 MCP 和外部 AI 数据提取能力。

## 3. 核心原则

### 3.1 只追加、不修改

导入允许：

- 创建新的原子事件；
- 创建新的具体案例；
- 创建新的因果关系；
- 创建新的关系与案例关联；
- 复用严格匹配到的唯一已有记录。

导入禁止：

- 覆盖已有事件的名称、说明、别名或关键词；
- 覆盖已有案例内容；
- 覆盖已有关系说明或置信度；
- 使用语义相似结果自动选择已有记录；
- 在严格匹配得到多条记录时任意选择其中一条。

新增关系与案例关联属于追加数据，不属于修改已有记录。

### 3.2 导入与数据治理分离

导入前只执行确定性规则。语义相似和内容质量检查在数据入库后，由用户手动启动数据维护检查。

这个边界避免导入阶段维护跨记录审核状态，也避免一个疑似重复事件阻塞整批关系依赖。

### 3.3 有效数据统一事务

文件中的普通无效记录先被排除。最终有效数据与成功导入日志使用同一个数据库事务写入。

写库阶段任意错误都会回滚本批次全部有效数据及日志。字段无效或依赖缺失的记录不会进入事务，也不会阻止其他有效记录参与事务。

### 3.4 现有应用兼容性

P2-03 是现有应用中的普通业务模块，不建立第二套页面框架、交互体系或视觉规范。

- 继续使用现有 React Router 懒加载路由；
- 继续使用 TanStack Query 管理服务端状态、请求取消和缓存失效；
- 继续使用共享 API 错误结构和 Zod 契约；
- 继续使用现有按钮、输入框、表格、分页、提示和页面标题样式；
- 不引入新的 UI 框架、CSS-in-JS 方案或独立设计系统；
- 新增通用组件必须同时服务于至少两个实际使用位置；
- 为复用而抽取现有组件时，原功能的视觉尺寸、键盘交互和测试语义必须保持不变。

## 4. CSV 文件契约

### 4.1 文件级规则

- 文件扩展名必须为 `.csv`；
- 文件编码必须为 UTF-8，可带 UTF-8 BOM；
- 只允许逗号作为字段分隔符；
- 同时接受 `LF` 和 `CRLF` 记录分隔；
- 文件末尾换行可有可无；
- 完全空白的逻辑记录被忽略，不计入50,000条上限；
- 文件不使用表头；
- 单个文件最大 `20 MB`；
- 单个文件最多 `50,000` 条逻辑记录；
- 每个字段都必须使用英文双引号包裹；
- 字段内部的英文双引号使用两个双引号表示；
- 字段可以包含逗号、回车和真实换行；
- 逻辑记录按标准 CSV 规则识别，禁止按物理行或逗号直接切割；
- 无法确定记录边界的语法错误会拒绝整个文件；
- 能确定记录边界的字段格式或业务校验错误只使当前记录无效。

20 MB 按实际上传字节数计算。50,000 条按 CSV 解析器输出的非空逻辑记录计算，多行字段仍然只属于一条记录。超过任意文件级上限时拒绝整个文件，不截断导入。

解析器必须保留“字段是否被双引号包裹”的词法信息。双引号字段外只允许逗号和合法记录分隔符，不接受额外空格或其他字符。字段未使用双引号、UTF-8 解码失败或记录数量超限时，按照能否继续可靠识别记录边界决定拒绝文件还是仅忽略当前记录。

文件级结构错误、没有最终有效数据或写库事务失败时，不创建导入历史。

### 4.2 记录类型

第一列必须是以下三个中文值之一：

- `原子事件`
- `具体案例`
- `因果关系`

不接受英文别名、数字类型码或其他同义写法。

### 4.3 原子事件记录

格式：

```csv
"原子事件","事件名称","事件说明","别名列表","关键词列表"
```

字段顺序：

1. 记录类型，必填；
2. 事件名称，必填；
3. 事件说明，可选；
4. 别名列表，可选；
5. 关键词列表，可选。

尾部可选字段可以完全省略。如果省略中间字段但填写后续字段，中间字段必须写成 `""`。

别名和关键词规则：

- 每个列表在一个单元格中；
- 多项使用英文分号 `;` 分隔；
- `\;` 表示项目内容中的英文分号；
- `\\` 表示项目内容中的反斜杠；
- 每项去除首尾空格后校验；
- 每个事件最多20个别名和20个关键词；
- 尾部孤立反斜杠或无效转义会使当前记录无效。

### 4.4 具体案例记录

格式：

```csv
"具体案例","案例内容"
```

案例内容是唯一业务字段，必须满足现有具体案例字段规则。多余非空字段会使当前记录无效。

### 4.5 因果关系记录

格式：

```csv
"因果关系","原因事件名称","结果事件名称","置信度","关系说明","具体案例1","具体案例2",...
```

字段顺序：

1. 记录类型，必填；
2. 原因事件名称，必填；
3. 结果事件名称，必填；
4. 置信度，可选；
5. 关系说明，可选；
6. 第1条具体案例，可选；
7. 后续具体案例，可继续增加。

关系规则：

- 原因事件和结果事件不能相同；
- 置信度必须是 `0` 至 `100` 的整数；
- 置信度省略或为空时使用 `10%`；
- 空案例单元格被忽略；
- 单条关系最多处理1000条非空案例；
- 同一关系行内严格相同的案例只处理一次。

### 4.6 示例

```csv
"原子事件","市场需求下降","市场购买意愿或能力下降","需求走弱;购买意愿下降","需求;市场"
"具体案例","某地区连续三个月销量下降，渠道库存增加"
"因果关系","市场需求下降","企业库存增加","70","需求下降导致产品销售速度放缓","某地区连续三个月销量下降，渠道库存增加"
"具体案例","企业公告称""原材料供应不足""导致交付延期"
```

导出文件必须使用相同的字段顺序、转义方式和全字段双引号格式。

## 5. 导入解析与严格匹配

### 5.1 处理阶段

一次同步导入按以下顺序执行：

1. 接收上传文件；
2. 校验扩展名、文件大小和编码；
3. 使用支持多行字段的 CSV 解析器读取全部逻辑记录；
4. 校验记录类型和字段；
5. 对文件内记录进行标准化、去重和依赖整理；
6. 开启数据库事务；
7. 在事务内批量读取可能复用的数据库记录；
8. 生成新增、复用、跳过和新增关联操作；
9. 在同一事务中写入最终有效数据及成功日志；
10. 提交事务；
11. 返回导入详情 ID；
12. Web 跳转到本次导入详情。

原始上传内容只存在于当前请求处理期间。请求完成或失败后立即释放，不写入持久化文件、对象存储或数据库大字段。

Web 不展示无法从同步请求获得的虚假进度百分比。请求期间只显示明确的“正在导入…”状态并禁止重复提交。

导入进行中时：

- 应用内导航、刷新和关闭窗口需要提示“离开将取消本次导入”；
- 用户确认离开后中止请求，服务端取消未提交事务；
- 用户留在页面时继续等待；
- 导入失败后保留浏览器当前选择的本地文件，允许再次点击导入；
- 数据库已经提交但浏览器未收到响应时，以导入历史为准，用户重新进入导入页即可看到成功记录。

### 5.2 事件依赖

因果关系两端事件只允许匹配：

- 数据库中标准化名称严格相同的唯一事件；
- 当前 CSV 中名称严格相同的唯一有效原子事件记录。

不使用别名、关键词或语义相似度解析关系端点。

如果任意端点在数据库和当前文件中都不存在，关系记录无效，关系内案例也不参与入库。

如果严格匹配在数据库或文件中得到多个候选，系统不选择任何候选，跳过受影响的关系或关联。关系本身被跳过时，其内嵌案例也不创建；只有某个案例匹配不唯一时，只跳过该案例及关联，关系的其他有效数据仍可处理。重复问题留给数据维护模块处理。

依赖解析基于整个文件的有效记录集合，与 CSV 中的物理先后顺序无关。关系可以出现在其事件记录之前。

### 5.3 严格复用标识

- 原子事件：标准化事件名称；
- 具体案例：去除首尾空格后的完整案例内容；
- 因果关系：最终原因事件 ID 与最终结果事件 ID；
- 关系与案例关联：最终关系 ID 与最终案例 ID。

严格匹配到唯一已有记录时复用。严格匹配到多条已有记录时跳过受影响的数据，不选择最早记录，也不创建新的重复记录。

### 5.4 文件内重复

- 第一次出现的有效事件或案例负责创建；
- 后续严格重复记录复用第一次记录；
- 第一次有效记录的可选字段生效；
- 后续重复记录不得覆盖或补充该记录的业务字段；
- 同方向重复关系复用第一次关系；
- 后续重复关系行可以继续补充尚未存在的案例关联。

“第一次”按 CSV 逻辑记录顺序确定。后续重复记录即使包含更多可选字段，也不得补写第一次记录缺少的字段；这个结果必须在成功日志中表现为复用，而不是修改。

### 5.5 已有关系

关系端点对应的因果关系已经存在时：

- 复用已有关系；
- 不修改说明和置信度；
- 严格匹配到唯一案例时复用案例；
- 创建尚不存在的新案例；
- 创建尚不存在的关系与案例关联；
- 关联已存在时只记录复用，不重复插入。

## 6. 导入事务与语义索引

### 6.1 写入顺序

最终有效操作在同一事务中按以下顺序执行：

1. 新原子事件及其别名、关键词；
2. 新独立案例和关系内新案例；
3. 新因果关系；
4. 新关系与案例关联；
5. 新业务记录对应的语义增量任务；
6. 导入批次和导入明细日志。

事务使用能够检测并发写入冲突的隔离级别。解析和字段校验在事务外完成；严格数据库匹配、依赖最终解析、业务写入、语义任务和日志全部在事务内完成。事务内不调用语义 Worker、外部网络或文件系统。

并发事务导致序列化失败时整批回滚，当前页面提示重试，不创建导入历史。

### 6.2 失败语义

- 字段无效：忽略当前记录；
- 关系依赖缺失或不唯一：忽略当前关系及受影响关联；
- 文件没有最终有效记录：返回错误，不创建历史；
- 数据库写入失败：回滚全部有效数据和日志；
- 同步请求超过5分钟：取消当前操作并回滚事务；
- 客户端断开时服务端应停止未提交工作；已经提交成功的事务以数据库结果为准。

同步导入接口使用独立的5分钟请求超时，不复用当前 JSON API 的10秒默认超时。客户端取消、服务端超时和数据库取消信号必须连接到同一个中止流程。

### 6.3 语义索引

导入不等待向量生成完成。新创建的事件、案例和关系复用现有增量索引任务机制。

复用已有业务记录不重复生成向量任务。只新增关系与案例关联时不更新关系向量，因为关系语义文档不包含关联案例内容。

## 7. 导入历史与详情

### 7.1 保存范围

只保存成功提交数据库事务的导入。

以下情况不保存历史：

- CSV 文件级语法错误；
- 文件中没有最终有效数据；
- 数据库事务回滚；
- 同步请求被取消或超时。

不保存：

- 原始 CSV；
- 无效记录内容；
- 无效行号；
- 无效原因；
- 失败导入尝试。

### 7.2 导入批次

导入批次至少保存：

- 批次 ID；
- 原始文件名的安全基本名称；
- 完成时间；
- 本批次包含的成功业务类型；
- 事件新增数与复用数；
- 案例新增数与复用数；
- 关系新增数与复用数；
- 关联新增数与复用数。

批次记录按完成时间倒序、ID 倒序稳定分页。

### 7.3 导入明细

每条成功处理明细保存：

- 批次 ID；
- 业务类型：事件、案例、关系或案例关联；
- 处理结果：新增或复用；
- 最终主业务记录 ID；
- 案例关联使用的可选关联记录 ID；
- 导入时的可读文本快照；
- 稳定排序字段。

文本快照保证业务记录以后被编辑或删除时，历史详情仍能显示当时结果。第一版本不提供删除导入历史功能。

### 7.4 导入历史页面

- 默认每页50条；
- 支持上一页、下一页、页码跳转；
- 显示当前页、总页数和总条目数；
- 切换页码后回到列表顶部；
- 显示完成时间、文件名、业务类型和各类型数量；
- 点击记录进入导入详情。

建议固定列顺序：

1. 完成时间；
2. 文件名；
3. 导入类型；
4. 原子事件；
5. 具体案例；
6. 因果关系；
7. 案例关联；
8. 查看详情。

导入类型只列出本批次成功处理过的业务类型。四类数量使用“新增 N / 复用 N”的紧凑表达，新增和复用均为0时显示短横线。

历史页码保存在 URL 查询参数中。浏览器前进、后退和刷新不得丢失当前页码。文件名、业务类型摘要和数量列使用现有紧凑表格密度，长文件名使用统一省略提示。

### 7.5 导入详情页面

顶部显示：

- 文件名；
- 完成时间；
- 四类数据的新增与复用汇总。

下方使用四个子标签：

- 原子事件；
- 具体案例；
- 因果关系；
- 案例关联。

每个子标签独立分页，默认每页50条。业务内容只显示文本，不展示内部 ID。

当前子标签和四个子标签各自的页码保存在 URL 查询参数中。切换子标签后再次返回时恢复该子标签之前的页码；无效页码由服务端返回的实际页码纠正。

长文本使用现有统一省略与提示组件：

- 单行省略；
- 使用既定悬停延迟显示完整内容；
- 提示框使用固定最大尺寸；
- 内容过长时显示滚动条。

关系显示为“原因事件 → 结果事件”。案例关联显示为“原因事件 → 结果事件 + 具体案例”。

从详情返回导入历史时恢复原页码和滚动位置。

详情页复用现有详情页标题结构、返回链接、摘要网格和按钮高度。页面不为日志记录增加编辑或删除入口。

## 8. 导入页面

“导入导出”主标签位于“数据维护”之后、“参数配置”之前。页面包含“导入”和“导出”两个子标签。

导入子标签包括：

- CSV 文件选择；
- 已选文件名和大小；
- 导入按钮；
- 同步处理中状态；
- 导入历史列表。

导入期间禁止重复提交。成功后直接跳转到本次导入详情。失败时停留在当前页面，使用现有默认3秒自动消失的错误提示。

本阶段不显示待审核记录列表。

页面状态规则：

- “导入/导出”子标签写入 URL，浏览器前进、后退和刷新后保持；
- 切换到导出子标签不会清空导入历史页码；
- 重新选择文件会清除上一次当前页面错误；
- 文件选择只做前端提示，扩展名、大小和格式仍由服务端权威校验；
- 成功导航到详情后，浏览器返回会回到原导入历史页和滚动位置。

## 9. 导出功能

### 9.1 通用规则

- 导出只读取业务数据；
- 不保存导出文件；
- 不保存导出历史；
- 文件通过流式响应生成；
- 文件使用与导入相同的无表头、全字段双引号 CSV 格式；
- 导出范围内的每个事件、案例和关系分别去重；
- 导出不包含数据库 ID、创建时间、更新时间或语义向量。

预计数量和下载采用两步协议：

1. Web 提交全量或筛选参数；
2. API 返回预计数量和短期下载令牌；
3. 用户确认后，浏览器使用令牌发起普通文件下载；
4. API 在一致读取快照中重新解析范围并流式输出 CSV。

短期令牌只保存生成导出所需的筛选条件和过期时间，不保存 CSV 内容，不出现在导出历史中。令牌默认10分钟过期；参数改变后旧令牌立即从当前页面失效。令牌过期时重新计算预计数量。

预计数量是预览时刻的数据规模。确认下载前数据库可能发生变化，最终文件以下载请求的一致读取快照为准。

记录顺序：

1. 原子事件；
2. 具体案例；
3. 因果关系。

所有具体案例都输出独立案例记录。关系行同时在尾部列出该关系关联的全部案例。重新导入时由严格复用规则消除重复创建。

### 9.2 全量导出

1. 用户点击“全量导出”；
2. 系统计算当前事件、案例和关系数量；
3. 弹窗显示预计数量；
4. 用户确认；
5. 服务端使用一致读取快照生成 CSV；
6. 浏览器保存本地文件。

建议文件名：

```text
causality-full-YYYYMMDD-HHmmss.csv
```

### 9.3 筛选事件导出

事件选择交互与因果图中心事件搜索框一致：

- 输入关键词显示事件候选下拉列表；
- 从下拉列表选择事件；
- 已选择事件显示为可删除标签；
- 可以继续搜索并选择多个起始事件；
- 已选择事件不能重复添加；
- 不增加语义增强查询入口。

事件搜索器复用因果图中心事件的普通候选查询、250毫秒防抖、键盘选择、全量候选分页加载和虚拟列表。导出页面在共享单选候选组件外增加多选标签，不复制候选查询逻辑。

已选择标签规则：

- 按选择顺序展示；
- 标签使用事件名称，不显示 ID；
- 长名称省略并使用统一完整文本提示；
- 删除标签后不影响其他已选事件；
- 没有选择起始事件时禁用筛选导出；
- 选择、方向或深度变化时清除上一次预计数量和下载令牌。

筛选参数：

- 方向：上游、下游、双向，默认双向；
- 关系深度：1至10层。

范围规则：

- 多个起始事件共同遍历；
- 循环关系不会重复遍历；
- 包含起始事件；
- 包含深度范围内符合方向的关系；
- 包含关系两端事件；
- 包含这些关系关联的全部案例；
- 结果合并去重；
- 不设置结果数量硬上限。

深度语义：

- 起始事件位于第0层；
- 每经过一条因果关系增加1层；
- 下游从原因事件走向结果事件；
- 上游从结果事件走向原因事件；
- 双向在每个当前事件上同时允许两种方向；
- 深度为1时只包含直接相邻关系和另一端事件；
- 深度为10时最多经过10条关系；
- 同一事件通过不同路径到达时只保留最小深度，但所有深度范围内符合方向的关系仍应纳入；
- 关系关联案例不增加关系深度。

点击导出后先显示预计事件、关系和案例数量，确认后生成文件。

下载响应使用安全文件名和 `Content-Disposition`。Web 先通过共享下载启动器验证令牌，再以不改变当前路由的浏览器下载方式获取文件。验证或下载启动失败时保持当前筛选条件，并显示现有样式的短暂错误。

预览时必须确认所有起始事件仍然存在。下载前任一起始事件被删除时，令牌失效并要求重新预览，不静默改变起始集合。

建议文件名：

```text
causality-filtered-YYYYMMDD-HHmmss.csv
```

## 10. 数据查重门槛

每个内置语义模型增加独立的“数据查重门槛”：

- 与增强查询门槛分别保存；
- 四个模型默认均为 `100%`；
- 可在参数配置的模型卡片中调整；
- 调整门槛不重建向量；
- 只影响下一次数据维护检查；
- 切换模型后使用该模型自己的查重门槛。

`100%` 是保守默认值。用户降低门槛后，数据检查才逐渐纳入表达不同但向量高度相似的候选。

模型卡片在现有“相似度门槛”下方增加“数据查重门槛”，两者都复用 `PercentageControl`：

- 标签和帮助文案必须明确区分“增强查询”和“数据查重”；
- 修改其中一个不得改变另一个；
- 保存失败时只回退当前控件；
- 保存期间只禁用当前控件，不阻止模型的其他安全操作；
- 四张模型卡片保持相同内部顺序和高度规则；
- 当前模型深色背景、状态标签和动作按钮样式保持不变。

## 11. 语义重复检查

语义检查只作用于：

- 原子事件；
- 具体案例。

规则：

- 使用当前模型的已发布向量；
- 使用当前模型的数据查重门槛；
- 相同记录不与自身比较；
- 同一记录对只生成一个问题；
- 标准化名称完全相同的事件由精确重复规则处理；
- 内容完全相同的案例由精确重复规则处理；
- 精确重复不得再次生成语义重复问题；
- 数据检查仍由用户手动启动并异步运行。

当前模型、索引或 Worker 不可用时：

- 继续执行全部确定性检查；
- 跳过语义重复规则；
- 在检查结果中明确显示“本次未执行语义查重”；
- 不自动下载或切换模型。

每个数据检查快照保存语义检查状态：

- `completed`：语义规则已完成；
- `skipped`：语义规则未执行，并保存稳定原因码；
- `failed`：语义规则执行失败，但确定性检查结果仍可发布。
- `truncated`：达到语义问题安全上限，已发布部分结果并提示提高门槛。

页面在最近检查时间附近显示简短状态，不把 Worker、模型或索引内部错误堆栈暴露给用户。

为防止用户把查重门槛降至较低数值后生成近似全组合：

- 每条记录只保留相似度最高且达到门槛的前5个候选；
- 记录对按稳定 ID 去重；
- 单次检查最多保存50,000条语义重复问题；
- 达到上限时不影响确定性问题，语义状态标记为 `truncated`；
- 页面提示提高数据查重门槛后重新检查。

## 12. 问题类型与操作弹窗

问题列表继续使用三列：

1. 问题描述；
2. 处理建议；
3. 执行入口。

未处理问题的执行入口统一显示“操作”按钮。点击后根据问题类型打开专用弹窗。

操作按钮不再根据旧的 `auto/manual` 模式显示“自动处理”或“手动处理”。所有未处理行使用同一按钮文案和现有次要按钮样式；加载操作上下文时显示“加载中…”。

| 问题类型 | 操作 |
| --- | --- |
| 事件语义疑似重复 | A 合并到 B、B 合并到 A、查看详情、忽略 |
| 案例语义疑似重复 | A 合并到 B、B 合并到 A、查看详情、忽略 |
| 标准名称相同的重复事件 | A 合并到 B、B 合并到 A、查看详情、忽略 |
| 内容相同的重复案例 | A 合并到 B、B 合并到 A、查看详情、忽略 |
| 同方向重复关系 | 选择保留关系并合并、查看详情、忽略 |
| 别名与其他事件名称冲突 | 合并事件、编辑任一事件、忽略 |
| 多个事件共享别名 | 合并事件、编辑任一事件、忽略 |
| 关系自环 | 编辑关系、删除关系、忽略 |
| 失效案例关联、别名或关键词 | 删除失效记录、忽略 |
| 重复别名或关键词 | 删除重复项、忽略 |
| 关键词位置异常 | 自动重新排序、忽略 |
| 名称、案例内容、说明或置信度异常 | 前往对应编辑页、忽略 |
| 时间顺序异常 | 自动修正更新时间、忽略 |
| 关系引用事件不存在 | 删除无效关系、忽略 |

“忽略”只把当前快照中的问题标记为已处理。下一次完整检查如果仍满足规则，问题会再次出现。

### 12.1 操作上下文

打开弹窗时，API 根据快照问题 ID 重新读取当前业务记录并返回该问题允许的动作。客户端不得仅根据问题类型自行构造可执行目标。

- 问题已经处理：刷新列表并关闭弹窗；
- 目标已经删除：把当前问题标记为已处理；
- 记录已经变化但问题仍存在：显示最新文本和动作；
- 当前状态不再允许原动作：禁用确认并提示重新检查；
- 完整数据只在弹窗打开时加载，问题列表保持紧凑摘要。

### 12.2 合并弹窗

事件、案例和关系合并弹窗使用统一结构：

- 并排显示记录 A 和记录 B 的核心文本与关联数量；
- 长文本使用统一省略与完整提示；
- 提供双方详情入口；
- 提供“保留 A，合并 B”和“保留 B，合并 A”两个明确选项；
- 默认不选择方向；
- 未选择方向时禁用确认按钮；
- 确认区显示将迁移、去重或删除的数据数量；
- 操作提交期间禁止关闭弹窗或重复提交；
- 成功后刷新当前问题、检查汇总和受影响业务查询缓存。

### 12.3 其他操作弹窗

- 清理类：显示目标类型和清理数量，确认后执行；
- 编辑类：显示问题摘要及“前往编辑”入口；
- 删除关系：沿用现有永久删除提示语义，不删除案例记录；
- 时间修复：显示原创建时间和更新时间，以及将写入的新更新时间；
- 忽略：与实际修复按钮分开，必须明确点击，不作为弹窗默认焦点。

弹窗统一支持焦点陷阱、Escape、点击遮罩关闭、关闭后恢复焦点和 `aria-modal`。提交进行中禁用 Escape 与遮罩关闭。

## 13. 合并规则

### 13.1 通用规则

- 用户必须明确选择保留记录和待合并记录；
- 弹窗提供两个方向，不预设永久保留对象；
- 合并前二次确认；
- 合并前重新读取并锁定相关记录；
- 按稳定 ID 顺序加锁；
- 数据已经变化或记录不存在时停止操作；
- 迁移、去重和删除在一个事务中完成；
- 保留记录的业务字段不自动合并或修改。

合并动作不直接依赖旧检查快照中的关联数量。确认提交时重新计算受影响关系和案例关联；数量发生变化时使用最新结果执行，记录不存在或保留方向无效时安全失败。

### 13.2 原子事件合并

将事件 A 合并到事件 B 时：

1. 保留 B 的名称、说明、别名和关键词；
2. 不把 A 的字段复制到 B；
3. 迁移 A 的全部入向和出向关系到 B；
4. 迁移后形成已有同方向关系时，保留原本已经连接 B 的关系及其说明和置信度，将案例关联合并到该关系；
5. 删除重复关系；
6. 迁移后形成 B 指向 B 的自环时，删除该关系及其关系与案例关联；
7. 自环关系引用的具体案例记录继续保留；
8. 删除事件 A。

### 13.3 具体案例合并

将案例 A 合并到案例 B 时：

1. 保留 B 的案例内容；
2. 不修改 B；
3. 将 A 的全部关系关联迁移到 B；
4. 已存在的相同关联自动去重；
5. 删除案例 A。

### 13.4 重复关系合并

- 用户选择保留关系；
- 保留关系的说明和置信度不变；
- 另一关系的全部案例关联迁移到保留关系；
- 重复关联自动去重；
- 删除另一关系；
- 不删除任何具体案例记录。

## 14. 编辑跳转与返回

需要修改业务字段的问题不在弹窗中重复实现完整编辑表单，而是跳转到现有编辑页面。

跳转时保存：

- 数据检查快照 ID；
- 问题 ID；
- 问题列表页码；
- 严重程度、问题类型和处理状态筛选；
- 页面滚动位置；
- 受限制的站内返回地址。

数据维护的问题页码、筛选条件和当前问题 ID 从组件本地状态迁移到 URL 查询参数。这样浏览器返回、刷新和编辑页往返都可以恢复状态。新的检查快照发布后，问题页码重置为1并关闭旧快照弹窗，筛选条件保留。

保存或取消后：

1. 返回数据维护页面原页码和滚动位置；
2. 恢复原筛选条件；
3. 重新打开原问题弹窗。

保存成功后只实时复查当前问题：

- 问题已消失：标记为已处理并显示成功状态；
- 问题仍存在：弹窗显示最新状态；
- 不自动重新执行完整数据检查。

返回地址只允许应用内部的数据维护路径，禁止任意外部跳转。

实现时扩展现有列表返回与记录定位机制，而不是为数据维护单独复制一套返回代码：

- 普通事件、关系、案例列表返回行为保持不变；
- 数据检查来源额外允许受校验的 `/maintenance` 返回路径；
- 返回时使用问题 ID 定位并滚动到原问题行；
- 保存成功携带一次性单问题复查标记；
- 取消编辑只恢复弹窗，不执行复查；
- 一次性标记消费后立即从 URL 或路由状态中移除，刷新页面不得重复提交复查。

## 15. 通用组件复用与视觉一致性

### 15.1 直接复用

| P2-03 能力 | 复用现有能力 | 约束 |
| --- | --- | --- |
| 方向、深度、问题筛选 | `AppSelect` | 不使用系统原生下拉，不改变现有尺寸和字重规则 |

| 按钮与页面结构 | `.button`、`.page-heading`、`.detail-heading`、现有 CSS 变量 | 不新增另一套颜色、圆角、阴影或字体 |

### 15.2 抽取通用弹窗

当前永久删除弹窗和语义模型动作弹窗分别实现了相似的遮罩、焦点陷阱、Escape、提交锁定和焦点恢复逻辑。P2-03 不再复制第三套。

实施时从现有行为中抽取共享 `AppDialog` 基础组件，并让以下组件共同复用：

- 现有 `DeleteRecordDialog`；
- 现有 `SemanticModelActionDialog`；
- 导出数量确认弹窗；
- 数据检查问题操作弹窗；
- 合并二次确认弹窗。

`AppDialog` 只负责可访问性、尺寸框架、关闭规则、错误区和操作区。具体文案、业务动作和内容布局留在各功能组件中。迁移现有弹窗不得改变当前视觉和交互。

### 15.3 抽取事件候选输入

现有 `GraphEventSelector` 同时包含通用候选查询与因果图专用“中心事件”标签和样式。实施时拆分为：

- 共享 `EventCandidateCombobox`：输入、防抖、全量候选、虚拟列表、键盘选择和错误状态；
- 因果图 `GraphEventSelector`：继续负责“中心事件”标签、单选值和原有尺寸；
- 导出 `ExportEventSelector`：负责多选、排除已选项和可删除标签。

因果图现有外观、字体、候选顺序和键盘行为必须通过回归测试保持不变。

### 15.4 新增可复用子标签

当前应用没有通用子标签组件。P2-03 新增一个共享 `AppTabs`，同时用于：

- 导入/导出两个主内容子标签；
- 导入详情的四个业务类型子标签。

`AppTabs` 使用标准 `tablist`、`tab` 和 `tabpanel` 语义，支持左右方向键、Home、End 和焦点可见状态。激活项使用现有深绿色、边框和紧凑间距，不创建独立视觉风格。

### 15.5 API 客户端复用

现有 `requestJson` 只适用于 JSON 响应和10秒默认超时。P2-03 在同一共享 HTTP 客户端模块中抽取公共响应错误解析，并补充：

- multipart CSV 上传请求，允许显式5分钟超时且不手动设置 multipart `Content-Type`；
- 导出预览 JSON 请求；
- 短期令牌文件下载启动；
- AbortSignal 取消传播。

功能模块不得直接散落原生 `fetch` 和重复的 API 错误解析。

### 15.6 页面风格

- 侧栏只在现有 `AppSidebar` 导航数组中增加一个条目，继续复用激活态、折叠动画和折叠提示；
- “导入导出”使用普通内容页面，不使用因果图全画布布局；
- 页面内容最大宽度与数据维护保持一致；
- 卡片使用现有白色表面、`var(--border)`、8px圆角和轻量阴影；
- 表格密度、字号和行高与现有三个主列表及数据维护表格一致；
- 主操作使用现有主按钮，次要与取消操作使用现有次要按钮，删除使用危险按钮；
- 状态标签只使用现有绿色、中性灰和错误红色语义；
- 仍以桌面端最小960px为目标，不在本阶段增加移动端布局；
- 所有新增动画遵守现有 `prefers-reduced-motion` 规则。

## 16. 数据存储

### 16.1 导入批次表

新增导入批次持久化结构，至少包括：

- ID；
- 安全文件名；
- 完成时间；
- 成功业务类型集合；
- 四类明细的新增数；
- 四类明细的复用数。

### 16.2 导入明细表

新增导入明细持久化结构，至少包括：

- ID；
- 批次 ID；
- 业务类型；
- 处理结果；
- 最终主业务记录 ID；
- 可选关联记录 ID；
- 文本快照；
- 稳定排序序号。

数据库必须为批次倒序分页、批次与类型明细分页建立必要索引。

### 16.3 短期导出请求

导出预计数量需要生成短期下载令牌。实现可以使用带过期时间的短期持久化记录，但必须满足：

- 只保存导出类型、起始事件 ID、方向、深度和过期时间；
- 不保存 CSV 内容或完整导出结果集；
- 不在 Web 中展示为导出历史；
- 令牌不可猜测；
- 过期记录可以安全清理；
- 即使实现选择在服务重启后使未过期令牌失效，也只要求用户重新预览，不得影响业务数据。

### 16.4 问题动作

数据检查问题动作请求使用按问题类型区分的结构化负载，不接受由客户端提交任意 SQL、任意目标类型或任意跳转地址。

合并和自动修复服务必须基于服务器保存的问题目标重新校验，不信任客户端提供的记录关系。

## 17. 内部 Web API

本阶段仍需要供当前 Web 应用调用的内部 HTTP API，但不提供面向外部工具的稳定公开录入 API。

建议端点职责：

- 上传并同步执行 CSV 导入；
- 分页读取成功导入批次；
- 读取导入批次汇总；
- 按业务类型分页读取导入明细；
- 计算全量导出预计数量；
- 计算筛选导出预计数量；
- 下载全量 CSV；
- 下载筛选 CSV；
- 读取问题操作上下文；
- 执行类型化问题动作；
- 实时复查单个问题；
- 读取和修改每个模型的数据查重门槛。

接口规则：

- 上传接口使用 multipart，只允许一个文件字段；
- 上传接口成功响应返回批次 ID 和四类汇总；
- 历史与明细使用现有页码分页响应结构；
- 明细类型使用封闭枚举，不接受任意表名或字段名；
- 导出预览使用 POST，避免把多个事件 ID 放入超长 URL；
- 下载使用不可猜测短期令牌和普通 GET，允许浏览器直接流式保存；
- 数据检查动作使用判别联合请求体，每种动作只接受所需参数；
- 合并方向通过保留 ID 和待合并 ID 明确表达；
- 单问题复查必须同时携带快照 ID 和问题 ID，防止处理错误快照；
- 所有响应由共享 contracts 包中的 Zod schema 校验；
- 对外错误继续使用现有稳定错误码和用户可读中文消息。

推荐前端路由：

```text
/data-transfer?tab=import&page=1
/data-transfer?tab=export
/data-transfer/imports/:batchId?tab=events&eventPage=1
```

导入详情的案例、关系和案例关联页码使用各自独立查询参数。数据维护继续使用 `/maintenance`，并把问题筛选、页码和当前问题 ID 写入查询参数。

具体 API URL 和文件命名在实施计划中按现有 Fastify 功能模块、service、repository 和 contracts 分层规范确定。

## 18. 性能与资源约束

- 同步导入最多处理20 MB、50,000条逻辑记录；
- 同步导入最长允许5分钟；
- CSV 语法解析必须采用流式或增量解析接口；
- 不得使用字符串按换行拆分记录；
- 严格匹配数据库记录必须批量查询，禁止逐条产生无界 N+1 查询；
- 业务数据和日志使用批量插入；
- 导出使用流式响应；
- 导出范围遍历在数据库中完成去重；
- 关系深度限制为1至10层；
- 语义重复检查使用现有 pgvector 索引；
- 数据查重门槛变化不得触发重新索引。

第一版不承诺固定秒级完成时间，但必须在参考 Colima 8 GiB 开发环境中完成上限数据基准，不得超时或内存溢出。

实现约束：

- 解析阶段只保留规范化后的中间记录和必要文本，不保留第二份完整原文件字符串；
- 数据库严格匹配使用集合查询或事务临时表，禁止按记录逐条查询；
- 50,000条记录不得产生50,000次独立 insert 往返；
- 日志和业务记录分别批量写入；
- 导入历史计数在事务内计算并保存，不在详情页实时全表统计；
- 语义重复规则必须分批读取向量候选，避免一次把全部向量加载到 Node.js 内存；
- 导出范围预计数量与实际导出复用同一个服务层范围定义，禁止维护两套遍历语义；
- 流式导出必须尊重响应背压和客户端取消；
- 短期导出请求应有定期或按需过期清理。

## 19. 错误处理

- 页面复用现有错误提示样式和位置；
- 错误提示默认3秒后自动消失；
- 再次操作可以再次显示；
- 导入处理中禁止重复点击；
- 导出范围计算和文件生成错误不产生历史；
- 合并冲突提示重新打开问题或重新执行检查；
- 语义服务故障只影响语义查重部分；
- 数据库事务错误不得留下部分业务数据或孤立导入日志。

### 19.1 页面状态

- 初次加载、空历史、请求失败和无结果使用现有页面状态样式；
- 历史翻页时保留上一页占位数据，分页控件禁用，避免表格跳动；
- 导入成功后立即写入 React Query 缓存或失效历史查询，再导航到详情；
- 合并或修复成功后只失效受影响的事件、案例、关系、图和检查查询；
- 打开问题弹窗失败不改变问题处理状态；
- 新检查快照替换旧快照时关闭旧弹窗并纠正无效页码。

### 19.2 安全边界

- 文件名只保存安全基本名称，不参与服务器路径拼接；
- 服务端不信任浏览器 `accept`、MIME 类型、记录数量或文件大小；
- CSV 字段只作为文本进入参数化 SQL，不拼接 SQL、命令或文件路径；
- 导入文本在 Web 中由 React 作为文本渲染，不注入 HTML；
- 导出令牌必须有足够随机性、过期时间和服务端参数校验；
- `Content-Disposition` 文件名必须过滤换行和控制字符；
- 返回地址只允许明确的站内路径；
- 数据检查动作以服务端问题记录为准，不信任客户端提交的任意目标 ID 组合；
- 合并、删除和自动修复必须执行实时引用检查并使用事务。
