# P2-03 批量导入、导出与数据治理增强设计

版本：V1.0

日期：2026-07-27

状态：设计文档待审核

所属路线图步骤：P2-03 批量导入、导出与数据治理增强

前置条件：P2-02 语义增强搜索已完成人工复核并推送至 GitHub

## 1. 目标

P2-03 在保持人工维护原则的前提下，提高关联因果数据的批量录入、备份和迁移效率。

本阶段采用以下职责边界：

1. 导入只负责确定性格式校验、严格文本匹配和追加数据；
2. 导入不得修改任何已有业务记录；
3. 语义相似、潜在重复和内容准确性不阻塞导入；
4. 入库后的数据质量问题由数据维护模块统一检查和人工处理；
5. 导出文件与导入文件使用完全相同的 CSV 格式；
6. 不保存原始导入文件或导出文件，只保存成功导入日志。

## 2. 范围

### 2.1 包含

- 独立“导入导出”主标签；
- CSV 批量导入；
- 成功导入历史与详情；
- 全量 CSV 导出；
- 按多个起始事件、方向和关系深度筛选导出；
- 原子事件与具体案例的高置信度语义查重；
- 数据检查问题的类型化操作弹窗；
- 原子事件、具体案例和重复关系的事务化合并；
- 从数据检查问题进入编辑页后的返回与单问题实时复查；
- 每个语义模型独立的数据查重门槛。

### 2.2 不包含

- JSON、Excel、ZIP 或其他文件格式；
- 外部或公开录入 API；
- 原始导入文件持久化；
- 失败导入历史；
- 无效记录内容或错误行日志；
- 导出文件或导出历史；
- 入库前语义审核或待审核列表；
- 自动判断数据内容是否真实、准确或满足逻辑原子性；
- 自动修改已有事件、案例或关系字段；
- 用户、权限或多租户功能；
- 第三阶段 MCP 和外部 AI 数据提取能力。

## 3. 核心原则

### 3.1 只追加、不修改

导入允许：

- 创建新的原子事件；
- 创建新的具体案例；
- 创建新的因果关系；
- 创建新的关系与案例关联；
- 复用严格匹配到的唯一已有记录。

导入禁止：

- 覆盖已有事件的名称、说明、别名或关键词；
- 覆盖已有案例内容；
- 覆盖已有关系说明或置信度；
- 使用语义相似结果自动选择已有记录；
- 在严格匹配得到多条记录时任意选择其中一条。

新增关系与案例关联属于追加数据，不属于修改已有记录。

### 3.2 导入与数据治理分离

导入前只执行确定性规则。语义相似和内容质量检查在数据入库后，由用户手动启动数据维护检查。

这个边界避免导入阶段维护跨记录审核状态，也避免一个疑似重复事件阻塞整批关系依赖。

### 3.3 有效数据统一事务

文件中的普通无效记录先被排除。最终有效数据与成功导入日志使用同一个数据库事务写入。

写库阶段任意错误都会回滚本批次全部有效数据及日志。字段无效或依赖缺失的记录不会进入事务，也不会阻止其他有效记录参与事务。

## 4. CSV 文件契约

### 4.1 文件级规则

- 文件扩展名必须为 `.csv`；
- 文件编码必须为 UTF-8，可带 UTF-8 BOM；
- 文件不使用表头；
- 单个文件最大 `20 MB`；
- 单个文件最多 `50,000` 条逻辑记录；
- 每个字段都必须使用英文双引号包裹；
- 字段内部的英文双引号使用两个双引号表示；
- 字段可以包含逗号、回车和真实换行；
- 逻辑记录按标准 CSV 规则识别，禁止按物理行或逗号直接切割；
- 无法确定记录边界的语法错误会拒绝整个文件；
- 能确定记录边界的字段格式或业务校验错误只使当前记录无效。

文件级结构错误、没有最终有效数据或写库事务失败时，不创建导入历史。

### 4.2 记录类型

第一列必须是以下三个中文值之一：

- `原子事件`
- `具体案例`
- `因果关系`

不接受英文别名、数字类型码或其他同义写法。

### 4.3 原子事件记录

格式：

```csv
"原子事件","事件名称","事件说明","别名列表","关键词列表"
```

字段顺序：

1. 记录类型，必填；
2. 事件名称，必填；
3. 事件说明，可选；
4. 别名列表，可选；
5. 关键词列表，可选。

尾部可选字段可以完全省略。如果省略中间字段但填写后续字段，中间字段必须写成 `""`。

别名和关键词规则：

- 每个列表在一个单元格中；
- 多项使用英文分号 `;` 分隔；
- `\;` 表示项目内容中的英文分号；
- `\\` 表示项目内容中的反斜杠；
- 每项去除首尾空格后校验；
- 每个事件最多20个别名和20个关键词；
- 尾部孤立反斜杠或无效转义会使当前记录无效。

### 4.4 具体案例记录

格式：

```csv
"具体案例","案例内容"
```

案例内容是唯一业务字段，必须满足现有具体案例字段规则。多余非空字段会使当前记录无效。

### 4.5 因果关系记录

格式：

```csv
"因果关系","原因事件名称","结果事件名称","置信度","关系说明","具体案例1","具体案例2",...
```

字段顺序：

1. 记录类型，必填；
2. 原因事件名称，必填；
3. 结果事件名称，必填；
4. 置信度，可选；
5. 关系说明，可选；
6. 第1条具体案例，可选；
7. 后续具体案例，可继续增加。

关系规则：

- 原因事件和结果事件不能相同；
- 置信度必须是 `0` 至 `100` 的整数；
- 置信度省略或为空时使用 `10%`；
- 空案例单元格被忽略；
- 单条关系最多处理1000条非空案例；
- 同一关系行内严格相同的案例只处理一次。

### 4.6 示例

```csv
"原子事件","市场需求下降","市场购买意愿或能力下降","需求走弱;购买意愿下降","需求;市场"
"具体案例","某地区连续三个月销量下降，渠道库存增加"
"因果关系","市场需求下降","企业库存增加","70","需求下降导致产品销售速度放缓","某地区连续三个月销量下降，渠道库存增加"
"具体案例","企业公告称""原材料供应不足""导致交付延期"
```

导出文件必须使用相同的字段顺序、转义方式和全字段双引号格式。

## 5. 导入解析与严格匹配

### 5.1 处理阶段

一次同步导入按以下顺序执行：

1. 接收上传文件；
2. 校验扩展名、文件大小和编码；
3. 使用支持多行字段的 CSV 解析器读取全部逻辑记录；
4. 校验记录类型和字段；
5. 对文件内记录进行标准化、去重和依赖整理；
6. 批量读取可能复用的数据库记录；
7. 生成新增、复用、跳过和新增关联操作；
8. 在一个事务中写入最终有效数据及成功日志；
9. 返回导入详情 ID；
10. Web 跳转到本次导入详情。

原始上传内容只存在于当前请求处理期间。请求完成或失败后立即释放，不写入持久化文件、对象存储或数据库大字段。

### 5.2 事件依赖

因果关系两端事件只允许匹配：

- 数据库中标准化名称严格相同的唯一事件；
- 当前 CSV 中名称严格相同的唯一有效原子事件记录。

不使用别名、关键词或语义相似度解析关系端点。

如果任意端点在数据库和当前文件中都不存在，关系记录无效，关系内案例也不参与入库。

如果严格匹配在数据库或文件中得到多个候选，系统不选择任何候选，跳过受影响的关系或关联。关系本身被跳过时，其内嵌案例也不创建；只有某个案例匹配不唯一时，只跳过该案例及关联，关系的其他有效数据仍可处理。重复问题留给数据维护模块处理。

### 5.3 严格复用标识

- 原子事件：标准化事件名称；
- 具体案例：去除首尾空格后的完整案例内容；
- 因果关系：最终原因事件 ID 与最终结果事件 ID；
- 关系与案例关联：最终关系 ID 与最终案例 ID。

严格匹配到唯一已有记录时复用。严格匹配到多条已有记录时跳过受影响的数据，不选择最早记录，也不创建新的重复记录。

### 5.4 文件内重复

- 第一次出现的有效事件或案例负责创建；
- 后续严格重复记录复用第一次记录；
- 第一次有效记录的可选字段生效；
- 后续重复记录不得覆盖或补充该记录的业务字段；
- 同方向重复关系复用第一次关系；
- 后续重复关系行可以继续补充尚未存在的案例关联。

### 5.5 已有关系

关系端点对应的因果关系已经存在时：

- 复用已有关系；
- 不修改说明和置信度；
- 严格匹配到唯一案例时复用案例；
- 创建尚不存在的新案例；
- 创建尚不存在的关系与案例关联；
- 关联已存在时只记录复用，不重复插入。

## 6. 导入事务与语义索引

### 6.1 写入顺序

最终有效操作在同一事务中按以下顺序执行：

1. 新原子事件及其别名、关键词；
2. 新独立案例和关系内新案例；
3. 新因果关系；
4. 新关系与案例关联；
5. 新业务记录对应的语义增量任务；
6. 导入批次和导入明细日志。

### 6.2 失败语义

- 字段无效：忽略当前记录；
- 关系依赖缺失或不唯一：忽略当前关系及受影响关联；
- 文件没有最终有效记录：返回错误，不创建历史；
- 数据库写入失败：回滚全部有效数据和日志；
- 同步请求超过5分钟：取消当前操作并回滚事务；
- 客户端断开时服务端应停止未提交工作；已经提交成功的事务以数据库结果为准。

### 6.3 语义索引

导入不等待向量生成完成。新创建的事件、案例和关系复用现有增量索引任务机制。

复用已有业务记录不重复生成向量任务。只新增关系与案例关联时不更新关系向量，因为关系语义文档不包含关联案例内容。

## 7. 导入历史与详情

### 7.1 保存范围

只保存成功提交数据库事务的导入。

以下情况不保存历史：

- CSV 文件级语法错误；
- 文件中没有最终有效数据；
- 数据库事务回滚；
- 同步请求被取消或超时。

不保存：

- 原始 CSV；
- 无效记录内容；
- 无效行号；
- 无效原因；
- 失败导入尝试。

### 7.2 导入批次

导入批次至少保存：

- 批次 ID；
- 原始文件名的安全基本名称；
- 完成时间；
- 本批次包含的成功业务类型；
- 事件新增数与复用数；
- 案例新增数与复用数；
- 关系新增数与复用数；
- 关联新增数与复用数。

批次记录按完成时间倒序、ID 倒序稳定分页。

### 7.3 导入明细

每条成功处理明细保存：

- 批次 ID；
- 业务类型：事件、案例、关系或案例关联；
- 处理结果：新增或复用；
- 最终主业务记录 ID；
- 案例关联使用的可选关联记录 ID；
- 导入时的可读文本快照；
- 稳定排序字段。

文本快照保证业务记录以后被编辑或删除时，历史详情仍能显示当时结果。第一版本不提供删除导入历史功能。

### 7.4 导入历史页面

- 默认每页50条；
- 支持上一页、下一页、页码跳转；
- 显示当前页、总页数和总条目数；
- 切换页码后回到列表顶部；
- 显示完成时间、文件名、业务类型和各类型数量；
- 点击记录进入导入详情。

### 7.5 导入详情页面

顶部显示：

- 文件名；
- 完成时间；
- 四类数据的新增与复用汇总。

下方使用四个子标签：

- 原子事件；
- 具体案例；
- 因果关系；
- 案例关联。

每个子标签独立分页，默认每页50条。业务内容只显示文本，不展示内部 ID。

长文本使用现有统一省略与提示组件：

- 单行省略；
- 使用既定悬停延迟显示完整内容；
- 提示框使用固定最大尺寸；
- 内容过长时显示滚动条。

关系显示为“原因事件 → 结果事件”。案例关联显示为“原因事件 → 结果事件 + 具体案例”。

从详情返回导入历史时恢复原页码和滚动位置。

## 8. 导入页面

“导入导出”主标签位于“数据维护”之后、“参数配置”之前。页面包含“导入”和“导出”两个子标签。

导入子标签包括：

- CSV 文件选择；
- 已选文件名和大小；
- 导入按钮；
- 同步处理中状态；
- 导入历史列表。

导入期间禁止重复提交。成功后直接跳转到本次导入详情。失败时停留在当前页面，使用现有默认3秒自动消失的错误提示。

本阶段不显示待审核记录列表。

## 9. 导出功能

### 9.1 通用规则

- 导出只读取业务数据；
- 不保存导出文件；
- 不保存导出历史；
- 文件通过流式响应生成；
- 文件使用与导入相同的无表头、全字段双引号 CSV 格式；
- 导出范围内的每个事件、案例和关系分别去重；
- 导出不包含数据库 ID、创建时间、更新时间或语义向量。

记录顺序：

1. 原子事件；
2. 具体案例；
3. 因果关系。

所有具体案例都输出独立案例记录。关系行同时在尾部列出该关系关联的全部案例。重新导入时由严格复用规则消除重复创建。

### 9.2 全量导出

1. 用户点击“全量导出”；
2. 系统计算当前事件、案例和关系数量；
3. 弹窗显示预计数量；
4. 用户确认；
5. 服务端使用一致读取快照生成 CSV；
6. 浏览器保存本地文件。

建议文件名：

```text
causality-full-YYYYMMDD-HHmmss.csv
```

### 9.3 筛选事件导出

事件选择交互与因果图中心事件搜索框一致：

- 输入关键词显示事件候选下拉列表；
- 从下拉列表选择事件；
- 已选择事件显示为可删除标签；
- 可以继续搜索并选择多个起始事件；
- 已选择事件不能重复添加；
- 不增加语义增强查询入口。

筛选参数：

- 方向：上游、下游、双向，默认双向；
- 关系深度：1至10层。

范围规则：

- 多个起始事件共同遍历；
- 循环关系不会重复遍历；
- 包含起始事件；
- 包含深度范围内符合方向的关系；
- 包含关系两端事件；
- 包含这些关系关联的全部案例；
- 结果合并去重；
- 不设置结果数量硬上限。

点击导出后先显示预计事件、关系和案例数量，确认后生成文件。

建议文件名：

```text
causality-filtered-YYYYMMDD-HHmmss.csv
```

## 10. 数据查重门槛

每个内置语义模型增加独立的“数据查重门槛”：

- 与增强查询门槛分别保存；
- 四个模型默认均为 `100%`；
- 可在参数配置的模型卡片中调整；
- 调整门槛不重建向量；
- 只影响下一次数据维护检查；
- 切换模型后使用该模型自己的查重门槛。

`100%` 是保守默认值。用户降低门槛后，数据检查才逐渐纳入表达不同但向量高度相似的候选。

## 11. 语义重复检查

语义检查只作用于：

- 原子事件；
- 具体案例。

规则：

- 使用当前模型的已发布向量；
- 使用当前模型的数据查重门槛；
- 相同记录不与自身比较；
- 同一记录对只生成一个问题；
- 标准化名称完全相同的事件由精确重复规则处理；
- 内容完全相同的案例由精确重复规则处理；
- 精确重复不得再次生成语义重复问题；
- 数据检查仍由用户手动启动并异步运行。

当前模型、索引或 Worker 不可用时：

- 继续执行全部确定性检查；
- 跳过语义重复规则；
- 在检查结果中明确显示“本次未执行语义查重”；
- 不自动下载或切换模型。

## 12. 问题类型与操作弹窗

问题列表继续使用三列：

1. 问题描述；
2. 处理建议；
3. 执行入口。

未处理问题的执行入口统一显示“操作”按钮。点击后根据问题类型打开专用弹窗。

| 问题类型 | 操作 |
| --- | --- |
| 事件语义疑似重复 | A 合并到 B、B 合并到 A、查看详情、忽略 |
| 案例语义疑似重复 | A 合并到 B、B 合并到 A、查看详情、忽略 |
| 标准名称相同的重复事件 | A 合并到 B、B 合并到 A、查看详情、忽略 |
| 内容相同的重复案例 | A 合并到 B、B 合并到 A、查看详情、忽略 |
| 同方向重复关系 | 选择保留关系并合并、查看详情、忽略 |
| 别名与其他事件名称冲突 | 合并事件、编辑任一事件、忽略 |
| 多个事件共享别名 | 合并事件、编辑任一事件、忽略 |
| 关系自环 | 编辑关系、删除关系、忽略 |
| 失效案例关联、别名或关键词 | 删除失效记录、忽略 |
| 重复别名或关键词 | 删除重复项、忽略 |
| 关键词位置异常 | 自动重新排序、忽略 |
| 名称、案例内容、说明或置信度异常 | 前往对应编辑页、忽略 |
| 时间顺序异常 | 自动修正更新时间、忽略 |
| 关系引用事件不存在 | 删除无效关系、忽略 |

“忽略”只把当前快照中的问题标记为已处理。下一次完整检查如果仍满足规则，问题会再次出现。

## 13. 合并规则

### 13.1 通用规则

- 用户必须明确选择保留记录和待合并记录；
- 弹窗提供两个方向，不预设永久保留对象；
- 合并前二次确认；
- 合并前重新读取并锁定相关记录；
- 按稳定 ID 顺序加锁；
- 数据已经变化或记录不存在时停止操作；
- 迁移、去重和删除在一个事务中完成；
- 保留记录的业务字段不自动合并或修改。

### 13.2 原子事件合并

将事件 A 合并到事件 B 时：

1. 保留 B 的名称、说明、别名和关键词；
2. 不把 A 的字段复制到 B；
3. 迁移 A 的全部入向和出向关系到 B；
4. 迁移后形成已有同方向关系时，将案例关联合并到保留关系；
5. 删除重复关系；
6. 迁移后形成 B 指向 B 的自环时，删除该关系及其关系与案例关联；
7. 自环关系引用的具体案例记录继续保留；
8. 删除事件 A。

### 13.3 具体案例合并

将案例 A 合并到案例 B 时：

1. 保留 B 的案例内容；
2. 不修改 B；
3. 将 A 的全部关系关联迁移到 B；
4. 已存在的相同关联自动去重；
5. 删除案例 A。

### 13.4 重复关系合并

- 用户选择保留关系；
- 保留关系的说明和置信度不变；
- 另一关系的全部案例关联迁移到保留关系；
- 重复关联自动去重；
- 删除另一关系；
- 不删除任何具体案例记录。

## 14. 编辑跳转与返回

需要修改业务字段的问题不在弹窗中重复实现完整编辑表单，而是跳转到现有编辑页面。

跳转时保存：

- 数据检查快照 ID；
- 问题 ID；
- 问题列表页码；
- 严重程度、问题类型和处理状态筛选；
- 页面滚动位置；
- 受限制的站内返回地址。

保存或取消后：

1. 返回数据维护页面原页码和滚动位置；
2. 恢复原筛选条件；
3. 重新打开原问题弹窗。

保存成功后只实时复查当前问题：

- 问题已消失：标记为已处理并显示成功状态；
- 问题仍存在：弹窗显示最新状态；
- 不自动重新执行完整数据检查。

返回地址只允许应用内部的数据维护路径，禁止任意外部跳转。

## 15. 数据存储

### 15.1 导入批次表

新增导入批次持久化结构，至少包括：

- ID；
- 安全文件名；
- 完成时间；
- 成功业务类型集合；
- 四类明细的新增数；
- 四类明细的复用数。

### 15.2 导入明细表

新增导入明细持久化结构，至少包括：

- ID；
- 批次 ID；
- 业务类型；
- 处理结果；
- 最终主业务记录 ID；
- 可选关联记录 ID；
- 文本快照；
- 稳定排序序号。

数据库必须为批次倒序分页、批次与类型明细分页建立必要索引。

### 15.3 问题动作

数据检查问题动作请求使用按问题类型区分的结构化负载，不接受由客户端提交任意 SQL、任意目标类型或任意跳转地址。

合并和自动修复服务必须基于服务器保存的问题目标重新校验，不信任客户端提供的记录关系。

## 16. 内部 Web API

本阶段仍需要供当前 Web 应用调用的内部 HTTP API，但不提供面向外部工具的稳定公开录入 API。

建议端点职责：

- 上传并同步执行 CSV 导入；
- 分页读取成功导入批次；
- 读取导入批次汇总；
- 按业务类型分页读取导入明细；
- 计算全量导出预计数量；
- 计算筛选导出预计数量；
- 下载全量 CSV；
- 下载筛选 CSV；
- 读取问题操作上下文；
- 执行类型化问题动作；
- 实时复查单个问题；
- 读取和修改每个模型的数据查重门槛。

具体 URL、请求体和响应契约在实施计划中按现有模块命名规范确定。

## 17. 性能与资源约束

- 同步导入最多处理20 MB、50,000条逻辑记录；
- 同步导入最长允许5分钟；
- CSV 语法解析必须采用流式或增量解析接口；
- 不得使用字符串按换行拆分记录；
- 严格匹配数据库记录必须批量查询，禁止逐条产生无界 N+1 查询；
- 业务数据和日志使用批量插入；
- 导出使用流式响应；
- 导出范围遍历在数据库中完成去重；
- 关系深度限制为1至10层；
- 语义重复检查使用现有 pgvector 索引；
- 数据查重门槛变化不得触发重新索引。

第一版不承诺固定秒级完成时间，但必须在参考 Colima 8 GiB 开发环境中完成上限数据基准，不得超时或内存溢出。

## 18. 错误处理

- 页面复用现有错误提示样式和位置；
- 错误提示默认3秒后自动消失；
- 再次操作可以再次显示；
- 导入处理中禁止重复点击；
- 导出范围计算和文件生成错误不产生历史；
- 合并冲突提示重新打开问题或重新执行检查；
- 语义服务故障只影响语义查重部分；
- 数据库事务错误不得留下部分业务数据或孤立导入日志。

## 19. 自动化测试

### 19.1 CSV

- UTF-8 与 BOM；
- 全字段双引号；
- 字段内逗号、双引号、回车和真实换行；
- 未闭合引号导致文件拒绝；
- 可恢复的未加引号字段导致当前记录无效；
- 无表头和三种中文记录类型；
- 可选尾部字段和中间空字段；
- 别名、关键词分号及反斜杠转义；
- 关系多案例和1000案例上限；
- 文件大小与逻辑记录数上限。

### 19.2 导入

- 无效记录跳过；
- 关系端点严格匹配；
- 缺失或多候选依赖跳过；
- 文件内重复复用；
- 已有记录只复用、不修改；
- 已有关系增加新案例关联；
- 全部有效数据和日志统一提交；
- 写库失败完整回滚；
- 失败导入不创建历史；
- 新记录正确创建语义增量任务。

### 19.3 历史与页面

- 历史倒序和稳定分页；
- 四类明细独立分页；
- 新增与复用状态；
- 文本快照在业务记录删除后仍可读取；
- 长文本省略和完整提示；
- 导入成功跳转详情；
- 详情返回恢复列表位置。

### 19.4 导出

- 全量预计数量和下载；
- 上游、下游、双向；
- 1至10层；
- 多起始事件；
- 循环路径；
- 实体、关系和案例去重；
- 全字段双引号；
- 全部案例独立记录及关系内关联案例；
- 导出后重新导入能够恢复业务数据和关联。

### 19.5 数据治理

- 每模型查重门槛保存；
- 默认100%；
- 门槛变化不创建索引任务；
- 精确重复不重复生成语义问题；
- Worker 或索引不可用时降级；
- 操作按钮打开对应弹窗；
- 忽略只作用于当前快照；
- 事件双向合并；
- 案例双向合并；
- 重复关系合并；
- 事件合并产生重复关系；
- 事件合并产生自环并删除关系；
- 合并并发变化安全退出；
- 编辑返回和单问题实时复查。

### 19.6 全仓库门禁

- lint；
- Prettier 检查；
- TypeScript 类型检查；
- 单元测试；
- PostgreSQL 集成测试；
- 生产构建；
- Compose 回归；
- 导入与导出上限性能基准。
