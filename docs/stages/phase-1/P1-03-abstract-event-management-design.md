# P1-03 抽象原子事件管理设计

版本：V1.0
日期：2026-07-21
状态：已完成
人工复核：2026-07-21 通过
所属路线图步骤：P1-03 抽象原子事件管理
前置步骤：P1-02 已完成人工验收并提交

## 1. 目标

完成抽象原子事件的创建、列表、传统搜索、查看和编辑闭环，使用户能够在桌面端 Web 应用中维护因果网络的节点数据。

本步骤交付后，用户可以：

1. 浏览已有事件；
2. 按标准名称、别名或关键词搜索事件；
3. 创建包含标准名称、说明、多个别名和多个关键词的事件；
4. 在创建时查看可能已存在的候选事件；
5. 查看事件详情；
6. 编辑事件及其别名、关键词；
7. 通过 REST API 完成同样的操作。

事件是否满足“逻辑上的原子事件”仍由用户人工判断。系统提供简短的命名提示和重复候选，不使用规则或 AI 代替判断。

## 2. 已确认的产品规则

- 抽象原子事件是后续因果图的节点；
- 标准名称必填；
- 别名在创建和编辑时可选，并且可以定义多个；
- 关键词可选，用于第一版传统搜索；
- 搜索候选项不显示匹配原因、匹配字段或匹配分数；
- 不使用 AI、嵌入模型、向量数据库或独立搜索服务；
- 数据完全由用户人工填写和调整，同时保留 REST API 录入能力；
- 第一阶段为单用户桌面端应用，不设计认证和权限。

## 3. 非目标

P1-03 不实现：

- 删除、归档、恢复、批量修改和批量导入事件；
- 修改历史、审计记录或并发编辑冲突处理；
- 自动判断事件是否原子；
- 自动合并重复事件；
- 模糊语义搜索、向量搜索或 AI 候选；
- 抽象因果关系或具体因果案例的创建与展示；
- 事件关联的上下游、关系数量或案例数量；
- 局部因果图；
- 移动端适配；
- 搜索日志、复杂相关性调优和搜索分析。

不提供删除 API。P1-02 已通过外键阻止删除仍被关系引用的事件，统一的软删除和引用影响预览留到 P2-01。

## 4. 页面方案选择

### 4.1 采用方案：独立路由页面

采用列表、详情、创建和编辑四类独立页面：

```text
/                  → 跳转到 /events
/events            → 事件列表与搜索
/events/new        → 创建事件
/events/:eventId   → 事件详情
/events/:eventId/edit → 编辑事件
/system            → 现有系统状态页
```

选择原因：

- 每个页面职责明确，表单状态和浏览器前进、后退行为稳定；
- 详情链接可直接访问，便于后续从关系、案例和局部图跳转；
- 创建和编辑页面有足够空间展示字段说明与重复候选；
- 相比抽屉或大型弹窗，自动化测试和键盘操作更可靠。

### 4.2 未采用方案

1. **列表内抽屉完成全部操作**：切换快，但详情深链接、表单离开确认和窄窗口布局更复杂。
2. **表格内直接编辑**：适合字段很少的数据，不适合动态别名、关键词和较长说明。

首版不提供“快速创建”弹窗，避免同时维护两套表单交互。

## 5. 应用信息架构

P1-03 将现有基础状态首页调整为应用外壳：

- 顶部保留 `Causality` 品牌；
- 主导航只显示已经可用的“事件”和“系统状态”；
- 不提前展示无法使用的关系、案例和因果图菜单；
- 桌面内容区最大宽度约 1280px，最小支持宽度仍为 960px；
- 现有系统状态组件迁移到 `/system`，功能保持不变。

视觉继续使用现有的深绿色、暖白和中性色体系。业务页面使用紧凑、清晰的管理界面，不使用大面积营销式 Hero。

## 6. 事件列表页

### 6.1 页面结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 原子事件                                      [创建事件]     │
│ 管理因果网络中可复用的原子事件                               │
├──────────────────────────────────────────────────────────────┤
│ [搜索名称、别名或关键词………………………………]              │
├──────────────────────────────────────────────────────────────┤
│ 标准名称              别名             关键词       更新时间 │
│ 央行提高政策利率      政策利率、加息   利率…        07-21    │
│ 市场流动性收紧        资金面           流动性…      07-20    │
├──────────────────────────────────────────────────────────────┤
│ [上一页]                                      [下一页]       │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 列表行为

- 每页默认 30 条，允许 API 调整到 1–100 条；Web 固定使用 30 条；
- 默认按 `updated_at desc, id desc` 排序；
- 点击行或标准名称进入事件详情；
- 别名和关键词各显示最多 3 项，超出后显示“+N”；
- 时间按用户本地时区显示到分钟；
- 使用服务端游标分页，不使用深分页性能会持续下降的 `OFFSET`；
- Web 保存已访问页的游标栈，因此支持“上一页”和“下一页”；
- 搜索条件写入 URL 的 `q` 参数，刷新页面后保留；
- 修改搜索词时回到搜索结果第一页；
- 输入停止 300ms 后请求，前一请求通过 `AbortSignal` 取消。

### 6.3 状态

- 首次加载显示表格骨架，不显示空白页面；
- 无任何事件时显示“还没有原子事件”和“创建第一个事件”；
- 搜索无结果时显示“没有找到事件”，保留当前搜索词和创建入口；
- 请求失败时显示简短错误和“重新加载”，不清空上一批成功数据；
- 搜索候选和结果中不显示“命中别名”“关键词匹配”等原因。

## 7. 创建与编辑表单

### 7.1 字段

| 字段 | 必填 | 规则 | 页面控件 |
|---|---|---|---|
| 标准名称 | 是 | 去除首尾空白后 1–120 字符 | 单行输入框 |
| 事件说明 | 否 | 空白转为 `null`；最多 2000 字符 | 多行输入框 |
| 别名 | 否 | 最多 20 个；每项去除首尾空白后 1–120 字符 | 可添加、移除的标签输入 |
| 关键词 | 否 | 最多 20 个；每项去除首尾空白后 1–60 字符 | 可添加、移除的标签输入 |

同一请求中的别名和关键词分别按“去除首尾空白并忽略大小写”判断重复。发现重复时在表单内提示，不静默丢弃用户输入。

### 7.2 原子事件提示

名称输入框下方固定显示一行帮助文字：

> 使用“主体 + 单一状态变化”命名，例如“原油价格上涨”。不要在名称中同时描述原因和结果。

这只是人工判断提示，不扫描连接词，不给出原子性分数，也不阻止保存。

### 7.3 重复候选

- 标准名称去除首尾空白后非空时，延迟 300ms 查询最多 5 个候选；
- 创建页显示所有候选；编辑页排除当前事件；
- 候选区域标题为“可能已存在”；
- 每个候选只显示标准名称，并提供打开详情的链接；
- 不显示匹配原因、相似度、命中别名或关键词；
- 候选只用于辅助判断，不阻止创建；
- 只有标准名称经过数据库规范化后完全重复时，保存被拒绝。

### 7.4 别名与关键词输入

- 按 Enter 或中文逗号、英文逗号确认当前输入；
- 每项以可移除标签显示；
- 删除按钮带有包含具体内容的无障碍名称；
- 不允许提交只包含空白的项；
- 别名和关键词保持用户输入的显示形式，搜索时由服务端执行大小写归一。

### 7.5 保存行为

- 创建成功后进入新事件详情页，并显示“事件已创建”；
- 编辑成功后返回事件详情页，并显示“修改已保存”；
- 保存期间禁用重复提交；
- 服务端校验错误显示在对应字段附近；
- 网络或未知错误显示在表单顶部，保留全部输入；
- 点击取消返回来源页面；没有来源记录时返回事件列表；
- 首版不增加未保存修改离开确认，避免引入全局路由拦截；表单提交失败时内容不会丢失。

## 8. 事件详情页

详情页展示：

- 标准名称；
- 事件说明，没有说明时显示“未填写”；
- 全部别名；
- 全部关键词；
- 创建时间；
- 最后更新时间；
- “编辑事件”按钮；
- 返回事件列表的链接。

详情页不显示置信度、关系数量、案例数量和图谱入口，因为这些数据尚未在本步骤实现。

## 9. REST API

所有接口使用 `/api` 前缀，进入现有 OpenAPI 文档。

### 9.1 接口清单

| 方法 | 路径 | 用途 | 成功状态 |
|---|---|---|---:|
| `GET` | `/api/events` | 列表、搜索和游标分页 | 200 |
| `GET` | `/api/events/candidates` | 轻量候选查询 | 200 |
| `GET` | `/api/events/:eventId` | 读取详情 | 200 |
| `POST` | `/api/events` | 创建事件 | 201 |
| `PUT` | `/api/events/:eventId` | 完整更新事件 | 200 |

不提供 `DELETE /api/events/:eventId`。

### 9.2 列表查询

`GET /api/events` 查询参数：

| 参数 | 默认值 | 规则 |
|---|---:|---|
| `q` | 空 | 去除首尾空白；最多 120 字符 |
| `limit` | 30 | 整数 1–100 |
| `cursor` | 空 | 服务端返回的不透明 Base64URL 游标 |

响应：

```json
{
  "items": [
    {
      "id": "uuid",
      "name": "原油价格上涨",
      "aliases": ["油价上涨"],
      "keywords": ["原油", "能源价格"],
      "updatedAt": "2026-07-21T03:00:00.000Z"
    }
  ],
  "nextCursor": "opaque-or-null",
  "hasMore": false
}
```

列表不返回事件总数。首版只需要稳定浏览和搜索，避免每次请求额外执行全量计数。

### 9.3 候选查询

`GET /api/events/candidates?q=原油&limit=5&excludeId=<uuid>`：

- `q` 必填，去除首尾空白后 1–120 字符；
- `limit` 默认 10，最大 20；
- `excludeId` 可选，用于编辑时排除当前事件；
- 响应项只包含 `id` 和 `name`；
- 不返回匹配原因和分数；
- 该接口可以在 P1-04 复用于原因事件和结果事件选择器。

### 9.4 详情响应

```json
{
  "id": "uuid",
  "name": "原油价格上涨",
  "description": "国际原油价格持续上行",
  "aliases": ["油价上涨"],
  "keywords": ["原油", "能源价格"],
  "createdAt": "2026-07-20T03:00:00.000Z",
  "updatedAt": "2026-07-21T03:00:00.000Z"
}
```

### 9.5 创建和更新请求

`POST` 和 `PUT` 使用相同的完整表单结构：

```json
{
  "name": "原油价格上涨",
  "description": "国际原油价格持续上行",
  "aliases": ["油价上涨"],
  "keywords": ["原油", "能源价格"]
}
```

`PUT` 是完整更新，不接受部分字段。这样可以避免动态别名列表在部分更新中的新增、替换和删除语义不清。

### 9.6 错误响应

统一错误结构：

```json
{
  "code": "EVENT_NAME_CONFLICT",
  "message": "该标准名称已被使用",
  "fields": {
    "name": "该标准名称已被使用"
  }
}
```

错误码：

| HTTP | code | 场景 |
|---:|---|---|
| 400 | `VALIDATION_ERROR` | 参数、游标或请求体不合法 |
| 404 | `EVENT_NOT_FOUND` | 事件不存在或 UUID 不存在 |
| 409 | `EVENT_NAME_CONFLICT` | 规范化后的标准名称重复 |
| 409 | `EVENT_ALIAS_CONFLICT` | 同一事件中别名重复 |
| 500 | `INTERNAL_ERROR` | 未分类服务端错误 |

错误响应不包含 SQL、约束名称、堆栈、连接字符串或数据库字段实现细节。

## 10. 数据写入规则

### 10.1 创建

在一个短事务中：

1. 插入 `abstract_events`；
2. 批量插入 `event_aliases`；
3. 返回事件和别名。

API 在事务前完成 Zod 校验和输入规范化。事务中不执行外部请求。

### 10.2 编辑

在一个短事务中：

1. 更新事件名称、说明、关键词和 `updated_at`；
2. 删除该事件原有别名；
3. 批量插入提交的别名；
4. 返回更新后的完整事件。

别名当前没有被其他业务表引用，完整替换比设计别名增删子接口更简单。任一步失败时事务整体回滚。

### 10.3 名称冲突

- 标准名称仍由数据库生成的 `normalized_name = lower(btrim(name))` 保证全局唯一；
- API 捕获唯一约束冲突并转换为 409；
- 不同事件允许使用相同别名；
- 别名可以与另一个事件的标准名称相同；候选搜索会同时返回相关事件，但不强制阻止保存。

## 11. 传统搜索设计

### 11.1 匹配范围

搜索词经过 `lower(btrim(q))` 处理后匹配：

1. 标准名称；
2. 事件别名；
3. 关键词数组中的单项。

标准名称和别名支持包含匹配；关键词支持忽略大小写的完整项匹配和包含匹配。搜索不分词、不扩展同义词、不做语义召回。

### 11.2 排序

搜索结果按以下优先级稳定排序：

1. 标准名称完全匹配；
2. 标准名称前缀匹配；
3. 别名完全匹配；
4. 别名前缀匹配；
5. 关键词完全匹配；
6. 其他包含匹配；
7. 同级按 `normalized_name asc, id asc`。

内部可以计算整数等级，但 API 和页面不返回等级或匹配原因。

### 11.3 游标

- 默认列表游标包含 `updated_at` 和 `id`；
- 搜索游标包含内部排序等级、`normalized_name` 和 `id`；
- 游标只作为不透明字符串返回；
- 游标无法解码、字段缺失、版本不符或与当前查询条件不一致时返回 400；
- 查询读取 `limit + 1` 条判断 `hasMore`，不执行 N+1 查询。

### 11.4 索引迁移

新增 `0001_event_management.sql`：

- 启用 PostgreSQL 内置扩展 `pg_trgm`；
- 为 `abstract_events.normalized_name` 增加 GIN trigram 索引；
- 为 `event_aliases.normalized_alias` 增加 GIN trigram 索引；
- 为 `abstract_events(updated_at desc, id desc)` 增加游标排序索引；
- 保留 P1-02 已有唯一索引和外键索引。

关键词分支首版使用数组展开匹配，不新增搜索文档列或额外关键词表。后续增强搜索独立实现，不改变本阶段的传统匹配规则。

## 13. 前端数据状态

- 查询键使用 `['events', 'list', q, cursor]`、`['events', 'detail', id]` 和 `['events', 'candidates', q, excludeId]`；
- 创建成功后写入详情缓存，并使事件列表缓存失效；
- 编辑成功后更新详情缓存，并使列表和候选缓存失效；
- 不使用乐观更新，避免失败时恢复动态别名列表；
- API 请求统一设置 10 秒超时；候选和搜索请求允许被取消；
- 页面只显示面向用户的中文错误，不直接展示 `Error.message` 或服务端内部内容。

## 14. 可访问性与键盘操作

- 所有输入都有可见标签和关联的错误说明；
- 错误摘要使用 `role="alert"`；
- 保存结果使用非打断式 `aria-live` 提示；
- 列表行中的事件名称使用真实链接；
- 搜索框有明确的“搜索事件”名称；
- 表单可完全使用键盘完成；
- 标签删除按钮不能只依赖图标表达含义；
- 焦点样式延续现有高对比度绿色轮廓；
- 颜色不作为错误、成功或选中状态的唯一表达方式。

## 15. 自动化测试设计

### 15.1 共享契约测试

- 合法创建和更新输入通过；
- 名称为空、过长时失败；
- 别名或关键词数量超限时失败；
- 单项为空、过长或规范化后重复时失败；
- 列表、候选、详情和错误响应符合 Schema；
- 非法 UUID、limit 和游标查询失败。

### 15.2 API 单元测试

- 游标可以编码和解码；
- 被修改、版本不符或查询条件不同的游标被拒绝；

## 19. 实施视觉复核记录

已在真实 API 和开发数据库上，将列表页、创建表单与批准的视觉概念进行并排复核：

1. **布局**：1440×900 和 1280×800 下，应用壳、标题区、搜索、表格及表单双栏均无横向溢出或遮挡；
2. **字体层级**：页面标题、表头、正文和辅助文字层级明确，长模拟数据不会破坏列布局；
3. **色彩**：沿用深绿色主操作、暖白背景和中性边框，错误与焦点状态不只依赖颜色表达；
4. **信息密度**：列表行高、四列比例和最多三项元数据显示在两个目标视口内保持可读；
5. **控件**：搜索框、主要按钮、标签输入、取消操作和键盘焦点样式与概念保持一致；
6. **候选区**：标准名称输入后只显示“可能已存在”和事件名称，不显示匹配原因或分数；
7. **文案**：原子事件命名提示、空值、成功、校验和冲突信息均使用简短中文。
