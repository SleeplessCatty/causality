# P1-04 抽象因果关系管理设计

版本：V1.0
日期：2026-07-21
状态：开发中
所属路线图步骤：P1-04 抽象因果关系管理
前置步骤：P1-03 已完成人工验收并提交

## 1. 目标

完成抽象因果关系的列表、传统搜索、创建、展开查看和编辑闭环。关系表示一个已有原子事件指向另一个已有原子事件的有向因果关联，置信度完全由用户人工填写和调整。

P1-04 不录入具体案例，不自动计算置信度，也不实现局部因果图。

## 2. 已确认规则

- 原因事件和结果事件都必须从已有原子事件中选择；
- 关系有方向，`A → B` 与 `B → A` 可以分别存在；
- 同方向 `A → B` 只能存在一条；
- 禁止 `A → A` 自环；
- 创建反向关系时允许保存，同时提示“反向关系已存在”并提供查看入口；
- 创建和编辑时可以修改两端事件、置信度和说明；
- 置信度是必填整数，范围为 0–100；
- 置信度使用同步的滑块和数字输入，初始为“未设置”，不提供默认值；
- 不增加关系状态字段；
- 案例数量在 P1-04 固定为 `0`；
- 不提供关系删除；
- 列表使用一个搜索框，不增加高级筛选器；
- 搜索结果和事件候选不显示匹配原因或分数。

## 3. 非目标

P1-04 不实现：

- 具体因果案例的创建、编辑或展示；
- 根据案例数量自动修改置信度；
- 条件化关系、反例、关系权重历史或审核流程；
- 关系删除、归档、恢复或批量操作；
- 局部因果图和上下游遍历；
- 在关系表单内创建事件；
- AI、语义搜索或向量搜索；
- 移动端适配。

## 4. 全局界面约定

P1-03 已建立应用的全局界面基线。P1-04 及后续模块直接复用现有应用壳、顶部导航、内容宽度、色彩、字体、间距、边框、按钮、输入框、表格、分页、加载状态、空状态、错误状态和键盘焦点样式。

后续阶段不再重新选择页面风格，只设计各模块特有的数据字段、操作流程、表格列和必要布局。

顶部导航调整为：

```text
事件 | 因果关系 | 系统状态
```

“事件”和“因果关系”是独立业务模块，通过普通应用内链接跳转。事件只能在事件模块中创建和管理；离开关系表单前往事件模块时，不保留未提交关系。

## 5. 页面与路由

采用独立的列表、创建和编辑页面，关系详情在列表中展开：

```text
/relations                     关系列表、搜索和展开详情
/relations/new                 创建关系
/relations/:relationId/edit    编辑关系
```

不建设独立关系详情页面。

### 5.1 关系列表

列表列为：

```text
原因事件 → 结果事件 | 置信度 | 案例数量 | 更新时间 | 操作
```

- Web 每页固定 30 条，API 支持 1–100 条；
- 默认按 `updated_at desc, id desc` 排序；
- 原因和结果名称分别链接到事件详情；
- 置信度显示为百分比；
- 案例数量显示 `0`；
- 操作列提供“展开”和“编辑”；
- 不在表格行中完整显示关系说明；
- 使用服务端游标分页，不返回总数量；
- 加载、空数据、无搜索结果和失败状态沿用事件列表。

单一搜索框匹配：

1. 原因事件的标准名称和别名；
2. 结果事件的标准名称和别名；
3. 关系说明。

搜索词写入 URL 的 `q` 参数，输入停止 300ms 后请求，不显示命中原因。

### 5.2 展开详情

点击“展开”后，在当前行下显示：

- 完整的 `原因事件 → 结果事件`；
- 关系说明，未填写时显示“未填写”；
- 人工置信度；
- 案例数量 `0`；
- 创建时间和最后更新时间；
- “编辑关系”按钮。

同一时间只展开一条关系。当前关系 ID 写入 URL 的 `expanded` 参数。若指定关系不在当前分页，页面将该关系作为“定位的关系”显示在表格顶部并展开。

### 5.3 创建与编辑表单

表单布局：

```text
原因事件选择器 → 结果事件选择器
置信度滑块 + 数字输入
关系说明
```

事件选择器复用 P1-03 候选 API：

- 搜索事件标准名称、别名和关键词；
- 候选只显示标准名称；
- 选中后显示事件名称并允许重新选择；
- 没有合适事件时提示用户前往事件模块创建；
- 原因和结果相同时在字段附近提示并阻止保存。

两端事件均选中后检查已有事件对：

- 同方向关系存在：显示冲突和查看入口，阻止保存；
- 反向关系存在：显示非阻断提示和查看入口，允许保存；
- 编辑时排除当前关系自身。

置信度：

- 初始数据为 `null`，显示“未设置”；
- 用户首次操作滑块或输入数字后产生数值；
- 滑块和数字输入保持同步；
- 只接受 0–100 的整数；
- 未设置时阻止保存。

关系说明可选，去除首尾空白，空白转为 `null`，最多 2000 字符。

创建成功后返回列表并展开新关系；编辑成功后返回列表并展开修改后的关系。保存失败时保留全部输入，保存期间禁用重复提交。

## 6. REST API

| 方法 | 路径 | 用途 | 成功状态 |
|---|---|---|---:|
| `GET` | `/api/relations` | 列表、搜索和游标分页 | 200 |
| `GET` | `/api/relations/pair-check` | 检查同方向和反向关系 | 200 |
| `GET` | `/api/relations/:relationId` | 展开详情和编辑预加载 | 200 |
| `POST` | `/api/relations` | 创建关系 | 201 |
| `PUT` | `/api/relations/:relationId` | 完整更新关系 | 200 |

不提供 `DELETE`。

### 6.1 表单请求

```json
{
  "causeEventId": "uuid",
  "effectEventId": "uuid",
  "confidence": 75,
  "description": "政策利率上升促使市场流动性收紧"
}
```

`PUT` 使用相同结构并完整更新。

### 6.2 列表响应

列表项包含：

- 关系 ID；
- 原因事件的 ID 和标准名称；
- 结果事件的 ID 和标准名称；
- 置信度；
- `caseCount: 0`；
- 更新时间。

展开详情额外返回说明和创建时间。

### 6.3 事件对检查

`pair-check` 接收 `causeEventId`、`effectEventId` 和可选 `excludeId`，返回：

```json
{
  "sameDirection": null,
  "reverseDirection": {
    "id": "uuid",
    "causeEventName": "事件 A",
    "effectEventName": "事件 B"
  }
}
```

表单用它提供即时反馈；保存接口仍须独立执行全部校验，避免并发写入绕过检查。

## 7. 数据库与查询

继续使用现有 `causal_relations` 表和约束：

- `(cause_event_id, effect_event_id)` 同方向唯一索引；
- 自环检查约束；
- 置信度 0–100 检查约束；
- 两端事件外键和方向查询索引。

允许反向关系，因此不增加无方向事件对唯一约束，也不清理现有固定或模拟数据。

P1-04 新迁移只增加：

- `causal_relations(updated_at desc, id desc)` 列表游标索引；
- 关系说明包含搜索所需的 trigram 表达式索引。

列表和搜索一次读取两端事件名称；别名匹配使用集合查询，禁止逐行查询。搜索结果去重，并按匹配等级、更新时间和 ID 稳定排序。案例数量不写入关系表。

创建和编辑使用短事务。数据库唯一约束和检查约束是最终一致性保护，API 将数据库错误转换为稳定业务错误。

## 8. 错误处理

| HTTP | code | 场景 |
|---:|---|---|
| 400 | `VALIDATION_ERROR` | 参数、游标、说明或置信度不合法 |
| 400 | `RELATION_EVENT_NOT_FOUND` | 原因或结果事件不存在 |
| 404 | `RELATION_NOT_FOUND` | 关系不存在 |
| 409 | `RELATION_SELF_LOOP` | 原因和结果相同 |
| 409 | `RELATION_DIRECTION_CONFLICT` | 同方向关系已存在 |
| 500 | `INTERNAL_ERROR` | 未分类服务端错误 |

错误响应不返回 SQL、约束名称、堆栈或连接信息。反向关系存在不是错误。

## 11. 人工复核

自动化测试通过后，用户验证：

1. 顶部导航可以在事件、因果关系和系统状态之间切换；
2. 固定和模拟关系可以分页及搜索；
3. 列表能够展开和收起详情；
4. 可以搜索并选择两端已有事件；
5. 置信度未设置时不能保存，滑块和数字输入同步；
6. 自环和同方向重复被阻止；
7. 反向关系显示提示但可以保存；
8. 创建和编辑后返回列表并展开目标关系；
9. 事件链接可以进入事件模块；
10. 1280×800 和 1440×900 下无明显遮挡或溢出。

只有用户明确确认人工复核通过，P1-04 才标记为完成。

3. 置信度没有默认值；
4. P1-04 不提供删除和具体案例入口；
5. 后续模块统一继承 P1-03 的全局界面风格。
