# P1-09 局部图扩展、筛选与布局稳定性设计

版本：V1.0  
日期：2026-07-21  
状态：开发与自动化测试完成，等待人工复核
所属路线图步骤：P1-09 局部图扩展、筛选与布局稳定性  
前置步骤：P1-08 已完成用户验收并提交

## 1. 目标

在 P1-08 局部图展示和交互能力之上，完成 20 → 50 → 100 个关联节点的渐进扩展、最低置信度和最低案例数筛选、查询状态说明以及大图重新布局和可读性保护。

本阶段继续围绕单个中心事件生成局部图，不计算整个知识库的完整匹配数量。每次查询仍由现有 P1-06 API 在节点和关系保护上限内停止。

## 2. 非目标

P1-09 不实现：

- 超过 100 个关联节点的整体扩展；
- 完整可达节点数、完整匹配数或剩余数量统计；
- 客户端增量合并图数据；
- 服务端图会话或游标式图扩展；
- 扩展前后保留旧节点坐标；
- 节点坐标持久化或用户自定义布局保存；
- 新布局引擎或 ELK 之外的备用布局；
- 新增筛选维度、条件化因果关系或语义搜索；
- 修改后端 API、共享契约、数据库结构或种子数据结构；
- 移动端和触摸端适配。

## 3. 已确认原则

- 初次查询使用 20 节点档，可扩展到 50 和 100 节点档；
- 只有 `node_limit` 或 `relation_limit` 才允许扩展，`exhausted` 不显示扩展操作；
- 100 节点档达到保护上限后不再扩展，只引导用户调整筛选；
- 每个档位都调用现有 API 取得一张完整局部图，不在客户端增量合并；
- 扩展和其他查询条件变化都执行完整 ELK 布局，旧节点位置可以自由改变；
- 查询和布局期间保留上一张完整图，成功后原子替换；
- 新图成功替换后清除选择、检查器、拖动位置、Zoom 和 Pan；
- 失败时保留旧图和旧图交互状态，并提供重试；
- 筛选采用先编辑草稿、再明确应用的方式；
- 应用或重置筛选后回到 20 节点档；
- 切换中心或方向后回到 20 节点档并保留已应用筛选；
- 搜索选择新中心时恢复“双向”，图中节点设为中心时保留当前方向；
- 查询参数写入 URL，交互和画布临时状态不写入 URL；
- 大图初始视口优先保证中心事件可见和节点可读，不强求一次显示全图；
- 页面保持 P1-03 至 P1-08 已建立的统一视觉语言，不重新定义应用风格。

## 4. 方案选择

比较以下三种方案：

1. **无状态完整重建**：每个档位以全部查询参数调用现有 API，收到完整响应后完整布局；
2. **客户端增量合并**：扩展接口只返回新增元素，浏览器合并并保留旧位置；
3. **服务端图会话**：服务端维护扩展上下文、游标和已返回集合。

选择方案 1。现有 API 已支持 20、50、100 节点档及筛选参数，完整重建不会引入图会话、增量一致性和坐标合并问题，符合第一版本简单可用的范围。

方案 1 的代价是扩展后旧节点可能移动。该行为已经确认接受，并通过旧图保留、后台布局和原子替换避免显示半成品。

## 5. 查询规模与扩展规则

`limit` 表示中心事件之外最多返回的关联节点数，沿用 P1-06 定义：

| 节点档位 | 关系保护上限 | 可执行的下一步 |
| ---: | ---: | --- |
| 20 | 200 | 仅在节点或关系达到限制时扩展到 50 |
| 50 | 500 | 仅在节点或关系达到限制时扩展到 100 |
| 100 | 1000 | 不再整体扩展，只能调整筛选或查询范围 |

规则：

- 中心事件不计入 `limit`，页面显示 API 返回的实际 `nodeCount`；
- 扩展请求继续使用同一中心事件、方向和筛选条件，只改变 `limit`；
- 不预取 50 或 100 节点图；
- 不为了判断是否还能扩展而执行额外计数查询；
- API 返回 `exhausted` 时表示当前查询条件下已完全取得可达内容；
- API 返回 `node_limit` 或 `relation_limit` 时表示达到当前档位保护上限，不代表系统已经计算出完整数量。

## 7. 筛选浮层

### 7.1 字段

工具栏增加“筛选”按钮，点击后打开紧凑浮层：

- 最低置信度 `minConfidence`：0～100 的整数，默认 0；
- 最少案例数 `minCaseCount`：大于等于 0 的整数，默认 0；
- “应用筛选”操作；
- “重置”操作。

按钮显示非默认筛选的数量。例如只设置最低置信度时显示“筛选 1”，两个值均为默认值时只显示“筛选”。

### 7.2 草稿与应用

- 打开浮层时，草稿从当前已应用筛选初始化；
- 修改输入只改变草稿，不请求数据、不写 URL；
- 点击“应用筛选”后校验全部字段；
- 校验成功后关闭浮层、把 `limit` 重置为 20、更新 URL 并开始查询；
- 点击浮层外部或按 `Esc` 只关闭浮层，不应用草稿；
- 下次打开时重新使用已应用值，丢弃上次未应用草稿；
- 非法输入显示字段级错误，不发送请求。

### 7.3 重置

点击“重置”立即执行：

1. 将最低置信度设为 0；
2. 将最少案例数设为 0；
3. 将 `limit` 重置为 20；
4. 关闭浮层；
5. 更新 URL 并重新查询。

## 8. 查询状态栏

状态栏显示：

- 当前 20、50 或 100 节点档；
- 非默认筛选条件；
- 当前查询停止原因；
- 可用的扩展、调整筛选或重试操作。

停止原因对应规则：

| 停止原因与档位 | 状态说明 | 操作 |
| --- | --- | --- |
| `exhausted` | 当前条件下已展示全部可达内容 | 不显示扩展 |
| `node_limit`，20/50 档 | 已达到当前节点显示档位 | 扩展至下一档 |
| `relation_limit`，20/50 档 | 关系较密集，已触发展示保护 | 扩展至下一档 |
| `node_limit` 或 `relation_limit`，100 档 | 已达到 100 节点显示上限 | “调整筛选” |

“调整筛选”直接打开筛选浮层并把焦点放到第一个筛选字段。扩展请求进行时扩展按钮显示加载状态并禁用，避免重复提交。

## 9. 查询状态与 URL

URL 保存：

```text
centerEventId=<uuid>
direction=upstream|downstream|both
limit=20|50|100
minConfidence=<0..100 integer>
minCaseCount=<non-negative integer>
```

刷新、分享链接和浏览器前进或后退都恢复同一组查询条件。

| 用户操作 | 查询方向 | 筛选条件 | 节点档位 |
| --- | --- | --- | ---: |
| 搜索并选择新中心事件 | 恢复 `both` | 保留 | 20 |
| 将图中节点设为中心 | 保留 | 保留 | 20 |
| 切换查询方向 | 使用新方向 | 保留 | 20 |
| 扩展图形 | 保留 | 保留 | 20 → 50 → 100 |
| 应用或重置筛选 | 保留 | 使用新筛选 | 20 |
| 刷新、前进或后退 | 从 URL 恢复 | 从 URL 恢复 | 从 URL 恢复 |

规范化规则：

- 无效 `direction` 使用 `both`；
- 无效或不支持的 `limit` 使用 20；
- 无效 `minConfidence` 使用 0；
- 无效 `minCaseCount` 使用 0；
- 规范化后使用 `replace` 写回 URL，避免给浏览历史增加无效条目；
- 中心事件 ID 格式无效或事件不存在时沿用 P1-07/P1-08 错误状态，不自动选择其他事件。

以下状态不进入 URL：筛选草稿、节点或关系选择、检查器开关、节点拖动位置、Zoom 和 Pan。

## 10. 完整查询与布局流程

一次查询条件变化依次执行：

```text
更新已应用查询状态和 URL
          ↓
调用现有局部图 API 取得完整响应
          ↓
在后台 Cytoscape/ELK 实例执行完整布局
          ↓
布局成功后原子替换可见画布
```

查询键包含：

```text
centerEventId + direction + limit + minConfidence + minCaseCount
```

每个查询或布局任务具有递增编号或等效失效标识。用户连续操作时，只允许最后一个仍有效的任务提交结果；已取消请求、过期响应和过期布局都不能覆盖最新目标状态。

## 11. 布局和视口

### 11.1 完整重排

- 每次扩展、切换中心、切换方向、应用筛选或重置筛选都执行完整 ELK 布局；
- 不尝试保持旧节点坐标，不把旧图位置作为新布局约束；
- 继续使用 P1-07 已确定的 ELK 有向分层布局；
- 节点保持统一圆角矩形、完整换行和必要的字体缩放；
- 继续使用现有关系走线、箭头和紧凑标签规则；
- 不新增布局选择器或用户可配置布局参数。

P1-09 的“布局稳定性”指不显示半成品、不发生过期结果覆盖、完成后没有明显节点重叠或文字遮挡；不表示扩展前后坐标稳定。

### 11.2 原子替换

- 查询和后台布局期间继续显示上一张完整图；
- 旧图保留当前选择、检查器、拖动位置、Zoom 和 Pan，并继续允许查看和操作；
- 只有查询和布局都成功后才替换画布；
- 成功替换时清除旧选择、关闭检查器、清除拖动位置并建立新视口；
- 查询或布局失败时不提交部分结果，完整保留旧图和旧图交互状态。

### 11.3 初始视口

- 20 节点档优先完整适应画布；
- 50 和 100 节点档先计算完整适应缩放，再使用 `max(fitZoom, 0.6)` 作为初始缩放；
- 新视口以中心事件为中心；
- 初始视口不要求一次显示全部节点；
- 用户仍可使用现有“适应画布”主动查看全图，此时允许缩小到 Runtime 的既有最小缩放；
- 打开或关闭 P1-08 检查器继续只 resize，不重新执行布局。

`0.6` 是本阶段桌面端可读性基线；如果真实浏览器视觉验收证明该值导致中心区域不可用或文字仍不可读，只允许在 P1-09 内调整这一常量和对应测试，不改变“可读优先、中心可见”的原则。

## 12. 异步状态与错误

### 12.1 加载

- 没有旧图的初次查询沿用现有全画布加载状态；
- 已有旧图的重新查询使用非阻断加载提示；
- 触发操作的按钮进入加载和禁用状态；
- 旧图仍可选择、查看详情、拖动、缩放和平移；
- 新图成功提交时才清除这些旧图交互状态。

### 12.2 查询失败

- 保留旧图和交互状态；
- 状态栏显示“查询失败，仍显示上一查询结果”；
- 提供“重试”，按当前 URL 条件重新调用 API；
- 不展示原始服务器响应、校验对象或堆栈。

### 12.3 布局失败

- 不把已获取但未完成布局的数据提交到画布；
- 保留旧图和交互状态；
- 状态栏显示“布局失败，仍显示上一查询结果”；
- 提供“重试”，重新执行当前条件的查询和布局。

查询条件在请求发起时立即写入 URL。发生失败时，URL 代表用户要求的目标条件，页面必须明确标记当前仍显示上一查询结果，避免把旧图误认为目标查询结果。

## 13. 前端架构

P1-09 延续 P1-07/P1-08 的页面、组件和 Runtime 边界，不新增全局状态容器。

建议职责：

- `CausalGraphPage`：解析和规范化 URL，维护已应用查询、最后成功图、请求/布局事务和 P1-08 交互状态；
- `CausalGraphToolbar`：保留中心事件、方向和视口操作，承载筛选入口；
- `GraphFilterPopover`：维护筛选草稿、校验、应用和重置；
- `GraphQueryStatus`：展示档位、筛选、停止原因、扩展、调整筛选和重试；
- `CausalGraphCanvas`：接收已完成布局的图，管理可见 Runtime、视口与现有交互；
- `createGraphRuntime`：继续封装后台布局与可见 Cytoscape 实例，增加以中心节点和可读缩放提交视口的窄能力；
- `graphQueryState`：无框架纯函数，处理 URL 参数、默认值、档位转换和查询状态文案。

筛选值继续由 `@causality/contracts` 的现有局部图查询约束定义。表单可使用受控输入和纯函数校验，不为两个字段额外引入表单或状态库。

## 15. 自动化测试

### 15.1 纯函数与 URL

- 解析和序列化全部查询参数；
- 无效方向、档位、置信度和案例数恢复默认值；
- 20 → 50 → 100 档位转换，100 不再产生下一档；
- 根据停止原因决定是否显示扩展；
- 搜索中心、图中设为中心、切换方向、筛选和重置对应的状态转换；
- 状态栏文案和启用筛选数量；
- 筛选输入边界和整数校验。

### 15.2 React 与 Runtime

- 筛选浮层打开、草稿、应用、重置、点击外部和 `Esc`；
- 非法筛选不请求 API；
- 查询键包含全部五个参数；
- 三种停止原因和三个档位的状态及操作；
- 扩展期间旧图保持可用，重复操作禁用；
- 查询失败和布局失败保留旧图并可重试；
- 新图提交前保留选择、检查器、拖动位置和视口；
- 新图成功后清除旧图交互状态；
- 过期响应和过期布局不能提交；
- 20 档适应全图，50/100 档中心可见且初始缩放不低于 0.6；
- 手工“适应画布”仍可显示完整大图；
- P1-08 选择、高亮、键盘、检查器和拖动行为不回归。

### 15.3 Playwright 与视觉测试

使用确定性测试数据验证：

1. 20 节点图达到限制后扩展到 50；
2. 50 节点图达到限制后扩展到 100；
3. 100 节点图不再扩展并可打开筛选；
4. `exhausted` 时不显示扩展；
5. 最低置信度和最低案例数筛选应用、URL 恢复和重置；
6. 切换方向和中心保留筛选并回到 20 档；

8. 查询失败后旧图可继续操作并可重试；
9. 浏览器刷新、前进和后退恢复正确查询；
10. 50 和 100 节点图中心事件可见、节点可辨认且没有明显遮挡；
11. 节点选择、关系选择、检查器、键盘和拖动在大图中继续可用；
12. 页面控制台无错误。

在 1280×720 保存筛选浮层、50 节点图和 100 节点上限状态截图。Canvas 内元素继续通过 Runtime 状态和稳定测试属性断言。

## 16. 人工复核

自动化门禁通过后检查：

1. 初次查询为 20 节点档；
2. 只有达到节点或关系限制时才出现扩展操作；
3. 20、50、100 的扩展顺序和提示正确；
4. 100 档达到限制后只能调整筛选，不能继续扩展；
5. 筛选浮层和查询状态栏符合现有统一视觉风格；
6. 筛选草稿不会立即查询，应用和重置行为正确；
7. 切换方向或中心保留筛选并回到 20 档；
8. 扩展和重新查询期间旧图不会消失或显示半成品；
9. 查询失败后旧图仍可操作并能重试；
10. 新图成功后旧选择、检查器、拖动位置和视口被清除；
11. 50 和 100 节点图初次显示时中心可见、文字和节点可辨认；
12. 扩展后允许完整重排，不要求旧节点保持位置；
