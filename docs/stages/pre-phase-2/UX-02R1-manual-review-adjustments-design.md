# UX-02R1 人工复核修订设计

版本：V1.0

日期：2026-07-22

状态：实施完成，待人工复核

所属阶段：第二阶段开始前的 UX-02 人工复核修订

前置状态：P1-01 至 P1-10 已完成；UX-01、UX-02 已实施，UX-02 人工复核提出修订项

## 1. 目标

根据 UX-02 人工复核结果，统一编辑页返回与错误反馈，修正关系详情零案例加载状态，继续压缩关系录入操作路径，并提高局部因果图的可读性。本修订同时把事件名称、别名、关键词和具体案例内容的长度边界写入前端、接口与数据库。

本步骤不增加新的业务字段、推理规则、查询深度或移动端适配，也不进入第二阶段。

## 2. 范围

本步骤修改：

- 原子事件列表的别名、关键词完整内容提示；
- 事件、因果关系、具体案例三个编辑页面的返回目标；
- 事件、因果关系、具体案例的创建页和编辑页提交错误提示；
- 因果关系列表的事件与箭头链接样式；
- 因果关系详情页的案例加载状态；
- 因果关系表单的“添加案例”按钮位置；
- 因果图重新布局后的默认视口，以及节点、关系和选择状态样式；
- 事件名称、别名、关键词和具体案例内容的契约、数据库约束、表单及相关搜索边界；
- 直接相关的自动化测试和文档。

本步骤不修改：

- 创建页面成功后的现有详情页落点；
- 关系方向、置信度、案例验证及局部图查询算法；
- 图节点固定尺寸、布局算法和 20/50/100 节点档位；
- 关系说明的长度限制；
- 列表分页数量、候选匹配排序或候选完整加载方式。

## 3. 原子事件列表提示

别名和关键词只要存在至少一个值，就启用完整内容提示，不再检测值是否超过 3 项，也不检测文本是否发生宽度截断。

- 表格仍直接显示最多 3 项并保持当前省略样式；
- 鼠标连续悬停 2 秒后显示包含全部值的提示；
- 键盘聚焦时立即显示；
- 离开、失焦、滚动或按 `Esc` 时关闭；
- 空数组继续显示“—”，不创建空提示；
- 提示不改变表格行高和列宽。

现有延时提示组件保留关闭、计时和无障碍能力，只移除“是否溢出”的启用判断。

## 4. 编辑页面返回规则

“所有编辑页面”限定为以下三个路由：

- `/events/:eventId/edit`；
- `/relations/:relationId/edit`；
- `/cases/:caseId/edit`。

三个页面统一执行：

| 页面 | 点击取消 | 保存成功 | 顶部返回入口 |
| --- | --- | --- | --- |
| 编辑事件 | `/events` | `/events` | 返回事件列表 |
| 编辑因果关系 | `/relations` | `/relations` | 返回关系列表 |
| 编辑具体案例 | `/cases` | `/cases` | 返回案例列表 |

保存前仍先完成缓存更新和列表缓存失效，再进入列表。创建页面不受此规则影响。

## 5. 创建与编辑页面短暂错误提示

以下六个页面中，由点击主保存按钮触发的校验错误、冲突错误和服务端保存错误，统一使用应用内短暂错误提示：

- 创建事件和编辑事件；
- 创建因果关系和编辑因果关系；
- 创建具体案例和编辑具体案例。

- 错误提示保留当前所在位置：表单级错误继续显示在表单顶部，字段错误继续显示在对应字段下方；
- 错误提示保留当前边框、背景、颜色、字号和布局样式，不改为 Toast、弹窗或悬浮层；
- 每一项错误默认显示 3 秒，然后自动移除；
- 用户再次点击“创建”或“保存修改”时，先关闭旧提示；如果问题仍存在，则重新显示并重新计时；
- 多个字段同时错误时，仍分别显示在各自原有位置，并使用同一轮 3 秒计时；
- 无效字段继续使用现有 `aria-invalid` 和红色边框；对应提示消失时，同步清除该字段的错误状态；
- 案例内容冲突提示仍可包含“查看已有案例”链接；
- 继续使用现有 `role="alert"` 语义，并在组件卸载时清理计时器；不新增手动关闭按钮。

编辑页面首次数据读取失败不属于保存错误，继续使用持久错误页和返回列表入口，避免错误提示消失后页面失去可操作内容。

## 6. 因果关系列表链接样式

原因事件、方向箭头和结果事件三个链接使用一致的交互状态：

- 默认使用原因事件链接当前的深绿色和字重；
- 鼠标悬停或键盘聚焦时提高文字颜色对比度并显示下划线；
- 下划线与文字保留当前间距；
- 箭头仍在方向列居中并保留方向符号所需字号；
- 删除箭头链接的圆形背景、圆角和悬停背景色；
- 保留箭头链接的可点击区域、无障碍名称和可见键盘焦点。

## 7. 因果关系详情页

“编辑因果关系”按钮保持当前宽度、换行和布局状态，本修订不修改该按钮。

### 7.1 零案例加载状态修复

已确认持续显示“加载具体案例…”的原因：关系的 `caseCount` 为 0 时，案例查询被正确禁用，但查询对象仍处于初始 `pending` 状态；页面没有判断查询是否实际启用，因而同时渲染空状态和加载状态。

修正规则：

- `caseCount = 0` 时只显示“尚未关联具体案例”，不发起案例请求，也不显示加载提示；
- `caseCount > 0` 且首次请求正在执行时显示“加载具体案例…”；
- 自动读取后续页时只显示“正在加载其余案例…”；
- 请求结束且没有下一页时不保留任何加载文案；
- 首次失败和后续页失败继续保留现有重试能力。

回归测试必须覆盖零案例关系，并断言等待后页面不存在“加载具体案例…”。

## 8. 因果关系表单案例区

“具体案例”标题与说明保持在区域顶部。案例行或空状态显示在中间，“添加案例”按钮移到整个案例列表下方并继续右对齐。

顺序固定为：

1. 标题和说明；
2. 已添加案例行，或“尚未关联具体案例”空状态；
3. 当前校验提示；
4. 右对齐的“添加案例”按钮。

新增行、删除行、候选列表向上展开、最多可输入长度和提交校验行为保持不变，仅调整按钮位置。

## 9. 因果图重新生成与默认视口

修改中心事件、方向、节点上限、最低置信度或最少案例数后，仍保留旧图直到新查询和布局成功。新图提交到画布时统一执行完整适应画布：

- 中心事件不变时，方向、节点上限、最低置信度和最少案例数四个参数互相独立；修改任一参数只更新该参数；
- 修改方向不再把节点上限重置为 20，修改节点、置信度或案例也不改变其他参数；
- 从顶部中心事件输入框选择新事件时，重置为默认查询参数：“双向、20 节点、最低置信度 0%、最少案例数 0”；
- 从右侧节点详情面板点击“设为中心”时，只替换中心事件，完整保留当前方向、节点上限、最低置信度和最少案例数；
- 20、50、100 三个节点档位均使用完整图 `fit`；
- 不再对 50/100 节点图强制中心节点可见和最低 60% 缩放；
- 每次成功重新生成都会清除当前选择、关闭检查器并覆盖临时拖动位置；
- 查询或布局失败时继续保留旧图及旧视口，重试成功后再适应新图；
- 用户之后仍可手动缩放、平移、拖动节点或点击“适应画布”。

## 10. 因果图元素样式

### 10.1 节点文字

节点尺寸继续固定为 `220 × 96`，避免布局密度和拖动命中区域发生额外变化。

- 字号从 `16px` 开始，按照 `16/15/14/13/12/11/10/9px` 逐级尝试；
- 对每个事件名称选择能够在固定节点内完整显示的最大字号，短名称使用较大字号，长名称自动缩小；
- 文字可用宽度由 `196px` 提高到约 `204px`；
- 文字可用高度由 `72px` 提高到约 `80px`；
- 继续完整换行显示，不截断、省略或隐藏事件名称中的任何字符；
- 事件名称的新 50 字上限作为最坏输入边界，并保证该边界在最低字号时仍可完整显示；
- 节点内仍保留约 8px 的安全留白，不让文字贴边。

### 10.2 节点边框

删除普通节点、相邻节点和当前节点的外部 underlay 阴影。中心节点、相邻节点和当前节点继续通过背景色及不同边框宽度表达状态，不降低其他元素透明度。

### 10.3 关系文字和箭头

- 关系标签字号由 `10px` 提高为 `12px`；
- 标签继续使用浅色背景，避免与线条重叠后难以阅读；
- 普通箭头比例由 `0.9` 提高到约 `1.3`；
- 相邻线和当前线的箭头按线宽继续略微放大；
- 线宽、自动弯曲、方向和标签内容保持不变。

### 10.4 选中节点的入线和出线

选择节点时，对一跳关系增加方向类：

- 指向当前节点的入线使用蓝色；
- 从当前节点出发的出线使用暖橙色；
- 线条和目标箭头使用同一种方向颜色；
- 另一端节点继续使用相邻节点边框样式；
- 选择关系时仍使用现有深绿色当前关系样式；
- 未关联元素保持原样，不降低透明度。

颜色使用应用现有低饱和度体系，确保在白色画布上区分清晰，并在自动化测试中通过确定的样式值锁定。

## 11. 字数限制与数据库迁移

### 11.1 原子事件名称

事件标准名称由 1–120 字调整为 1–50 字：

- Contracts 的事件名称输入、引用和响应约束统一为 50；
- 创建、更新 API 和数据库约束统一为 50；
- 前端事件表单显示“最多 50 字”并阻止保存超长名称；
- 别名单项由最多 120 字调整为最多 80 字；
- 关键词单项由最多 60 字调整为最多 50 字；
- 事件列表和候选搜索的查询字符串上限同步调整为 80 字，以覆盖最长的可搜索别名。

### 11.2 具体案例内容

具体案例内容由 1–50 字调整为 1–100 字：

- Contracts、创建与更新 API、关系表单新案例、案例候选和案例列表响应统一为 100；
- 案例列表与候选查询字符串上限同步调整为 100；
- 案例表单帮助文字、计数器和错误文案改为 100；
- 关系表单案例输入在 100 字以内才允许搜索、选择或创建。

### 11.3 迁移策略

新增数据库迁移同时：

- 把 `abstract_events.name` 和生成列 `normalized_name` 调整为 `varchar(50)`，名称检查改为 1–50；
- 把 `event_aliases.alias` 和生成列 `normalized_alias` 调整为 `varchar(80)`，别名检查改为 1–80；
- 为 `abstract_events.keywords` 增加逐项 1–50 字检查；
- 把 `concrete_cases.content` 调整为 `varchar(100)`，内容检查改为 1–100；
- 保留现有唯一索引和 trigram 索引；
- 不截断任何既有数据。

迁移前检查是否存在超过新边界的事件名称、别名或关键词。如果存在，迁移明确失败并要求用户先手工缩短，禁止静默截断或自动改名。当前开发数据库已核对：最长事件名称为 36 字、最长别名为 34 字、最长关键词为 26 字，三个字段均没有超过新限制的记录；最长案例内容为 50 字，可以安全执行本迁移。

## 12. 组件与文件边界

预计修改范围：

- `DelayedOverflowTooltip` 和事件列表：始终启用非空元数据提示；
- 三个 `*EditPage`：统一列表返回目标；
- `EventForm`、`RelationForm`、`CaseForm`：创建和编辑模式的短暂错误提示；
- 表单内部复用一个小型自动清理计时逻辑，不新增 Toast 组件或第三方通知框架；
- 关系列表、关系详情和关系案例字段：链接、加载状态、按钮布局；
- `CausalGraphCanvas`：每次新图布局完成后适应画布；
- `graphStyles`、`fitNodeLabel` 和 Runtime 选择类：图元素可读性与入出线颜色；
- Contracts、数据库 Schema、迁移、API 游标边界和表单：50/100 字限制；
- README、UX-02 状态记录及直接相关测试。

不重构通用页面框架，不新增全局状态库，不引入新的图组件或通知框架依赖。

## 13. 实施顺序

1. 修改长度契约、数据库 Schema 和迁移，先验证数据兼容与 API 边界；
2. 修改三个编辑页返回规则、六个创建/编辑页面的短暂错误提示和关系案例按钮位置；
3. 修改事件提示、关系列表链接和关系详情加载状态；
4. 修改因果图默认适应行为及节点、关系、入出线样式；
5. 完成单元、集成、E2E、生产构建和 1280×720 浏览器复核；
6. 交付用户人工复核，复核通过前不标记 UX-02R1 完成。

## 14. 自动化测试

### 14.1 Contracts、数据库与 API

- 事件名称 50 字成功、51 字失败；
- 别名 80 字成功、81 字失败；
- 关键词 50 字成功、51 字失败；
- 案例内容 100 字成功、101 字失败；
- 案例列表、候选和游标查询接受 100 字并拒绝 101 字；
- 数据库迁移保留唯一索引和搜索索引；
- 数据库拒绝 51 字事件名称、81 字别名和 51 字关键词，接受 100 字案例并拒绝 101 字案例；
- 关系表单创建新案例支持 100 字边界。

### 14.2 Web

- 非空且未被截断的别名、关键词也可显示提示；
- 三个编辑页取消和保存后均进入列表；
- 创建和编辑模式的原位错误提示 3 秒后自动消失，同一错误再次提交后重新出现；
- 关系列表三个链接共享悬停、聚焦样式，箭头没有背景色；
- 零案例关系详情只显示空状态；
- “添加案例”按钮位于案例行之后；
- 五类图查询参数变化后的新图都调用完整适应；中心事件不变时四个查询参数互不重置；
- 顶部输入框更换中心事件时恢复全部默认参数，详情面板更换中心事件时保留全部当前参数；
- 固定节点在不同名称长度下选择可完整显示内容的最大字号；
- 关系字号、箭头比例、无 underlay、入线蓝色和出线暖橙色样式；
- 50 字事件名称、80 字别名、50 字关键词和 100 字案例内容的表单边界与错误状态。

### 14.3 浏览器与人工复核

- 1280×720 下错误提示和关系详情无横向溢出；
- 编辑页保存与取消返回正确列表；
- 创建页和编辑页保存错误均短暂显示并自动关闭；
- 零案例和多页案例的关系详情状态正确；
- 20/50/100 节点图修改五类查询项后均自动适应；
- 分别从顶部输入框和详情面板更换中心节点，核对重置与保留两套参数规则；
- 长短事件名称都在固定尺寸节点内完整显示，节点文字、线标签和箭头清晰可见；
- 选择同时具有入线和出线的节点时，两种方向颜色区分明确；
- 图的拖动、选择、方向键、检查器和手动缩放没有回归。

## 15. 验收标准

1. 非空别名和关键词无论是否截断，都能显示完整内容提示；
2. 三个编辑页面取消、顶部返回和保存成功均进入对应列表；
3. 创建和编辑提交错误保留原有样式和位置，3 秒后消失，再次保存失败时可以重新出现；
4. 关系列表原因、箭头和结果链接具有一致的悬停下划线，箭头没有悬停背景；
5. 关系详情的“编辑因果关系”按钮保持当前状态，零案例时不显示任何加载文案；
6. 关系表单“添加案例”位于案例列表下方并右对齐；
7. 五类图查询条件变化后，新图均完成重新布局并自动适应画布；中心事件不变时，方向、节点、置信度和案例只修改自身；
8. 顶部输入框更换中心事件时重置为“双向、20、0%、0”，详情面板更换中心事件时保留当前四项参数；
9. 节点尺寸保持不变，并为每个事件名称选择能够完整显示全部文字的最大字号；关系文字更大、节点无外阴影、箭头更明显；
10. 选中节点时入线和出线使用不同颜色；
11. 事件名称最多 50 字、别名单项最多 80 字、关键词单项最多 50 字、案例内容最多 100 字，前后端和数据库一致；
12. 自动化质量门禁通过；
13. 用户完成人工复核。

只有用户明确审核通过本设计后，才编写并执行 UX-02R1 实施计划。只有用户明确确认人工复核通过后，UX-02R1 才标记为完成；第二阶段不会自动开始。
