# UX-01 紧凑桌面布局与全画布因果图设计

版本：V1.0  
日期：2026-07-22  
状态：开发与自动化测试完成，等待人工复核
所属阶段：第二阶段开始前的独立界面优化  
前置状态：P1-01 至 P1-10 和第一阶段均已完成

## 1. 目标

提高桌面应用的空间利用率，在不改变现有业务功能和数据模型的前提下，将全局页面改为紧凑型布局，并让因果图使用左侧导航之外的全部工作区。

本步骤重点解决：

- 顶部导航、固定内容宽度和过大留白造成的屏幕浪费；
- 因果图标题、工具条、状态条和属性面板持续压缩画布；
- 普通管理页面单位屏幕内可见内容过少；
- 因果图筛选与扩展操作占用空间较多。

## 2. 范围

本步骤修改：

- 应用全局桌面壳层；
- 左侧可折叠导航栏；
- 普通管理页面的间距和组件密度；
- 因果图页面的全画布布局；
- 因果图顶部工具条、左下状态框和右侧属性面板；
- 与新布局直接相关的前端状态管理、无障碍行为和测试。

本步骤不修改：

- 事件、关系和案例的业务字段或操作流程；
- API、数据库 Schema、查询契约和 Docker 配置；
- 因果图的节点、关系、布局算法、选择、高亮、拖动、缩放、平移和键盘导航规则；
- 100 个关联节点的整体显示上限；
- 移动端适配；
- 第二阶段业务功能。

## 3. 方案选择

采用“共享紧凑侧栏 + 因果图专用工作台布局”。

所有页面复用同一个可折叠左侧栏。普通页面继续使用现有内容结构，只调整密度；因果图路由使用独立的全画布工作区，控制组件覆盖在画布之上。

不采用纯 CSS 负边距覆盖，因为其高度和定位容易受到页面结构变化影响；不为因果图建立独立应用壳层，因为这会复制导航、折叠状态和无障碍逻辑。

## 4. 全局页面壳层

### 4.1 基本结构

应用从“顶部导航 + 居中内容区”改为“左侧导航 + 右侧工作区”。顶部导航栏移除。

- 左侧栏展开宽度约为 `184px`；
- 左侧栏收起宽度约为 `56px`；
- 右侧工作区使用剩余宽度；
- 普通页面由右侧工作区负责滚动；
- 因果图页面锁定工作区滚动，将剩余区域全部交给画布。

### 4.2 左侧栏内容

左侧栏分为三个区域：

1. 顶部品牌区；
2. 中部导航区；
3. 底部折叠按钮。

展开时显示品牌、导航图标和文字。收起时只显示品牌标识和导航图标；图标悬浮或键盘聚焦时通过 Tooltip 显示完整标签名称。导航仍包含事件、因果关系、具体案例、因果图和系统状态。

导航图标使用项目内维护的轻量 SVG，不为本次调整增加图标运行时依赖。

### 4.3 折叠状态

- 普通页面默认展开；
- 用户手动选择的普通页面状态保存在浏览器本地；
- 每次进入因果图页面自动收起侧栏，但允许用户在当前图页面临时展开；
- 离开因果图后恢复进入前的普通页面状态；
- 展开侧栏会使可用画布宽度小于约 `960px` 时强制收起侧栏，但不覆盖用户保存的普通页面偏好；
- 强制收起期间折叠按钮保持可识别的禁用状态，并说明当前空间不足；
- 因果图中的临时展开或收起不写回普通页面偏好。

### 4.4 动画

左侧栏展开和收起使用约 `180ms` 的宽度、位移和内容淡入淡出动画。顶部工具条随可用画布中心同步平滑移动。

系统启用 `prefers-reduced-motion: reduce` 时取消非必要动画，直接切换最终状态。

## 5. 普通管理页面紧凑化

事件、因果关系、具体案例和系统状态页面保留现有标题、说明、搜索、创建入口、表格、展开区和表单结构，不重新排列业务组件。

主要尺寸调整：

- 工作区内边距约为 `24px–28px`；
- 取消原有较大的顶部和底部留白；
- 页面标题约为 `28px–30px`；
- 搜索框高度约为 `40px–42px`；
- 普通按钮高度约为 `36px–38px`；
- 表头高度约为 `42px–44px`；
- 表格数据行高度约为 `54px–58px`；
- 表格单元格左右内边距约为 `14px–16px`；
- 详情区、展开区、表单卡片和字段间距按同一密度收紧。

普通页面不再固定在 1280px 的居中容器中，而是使用侧栏之外的可用宽度，仅保留必要边距。已有字段、校验提示和操作入口不得因紧凑化而隐藏。

## 6. 因果图全画布工作台

### 6.1 画布

因果图页面移除独立标题、副标题和查询状态条。画布填满侧栏之外的整个工作区，从窗口顶部延伸到底部。

画布的节点、关系、临时拖动位置、自动布局、选择、高亮、方向键导航、空格键检查器、缩放和平移行为保持不变。

### 6.2 顶部悬浮工具条

工具条覆盖在画布顶部：

- 距离画布顶部约 `16px`；
- 在当前画布区域内水平居中；
- 标准宽度约 `1080px`；
- 固定高度约 `52px`；
- 左右栏宽度发生变化时自动重新居中；
- 可用宽度不足时缩小到画布宽度减去左右各 `16px`，只压缩中心事件输入区域；
- 使用单行、圆角、轻边框、轻阴影和不透明背景。

工具条从左到右包含：

1. 中心事件搜索选择框；
2. 查询方向下拉框；
3. 节点上限下拉框；
4. 最低置信度下拉框；
5. 最少案例数下拉框；
6. 缩小、当前比例、放大和适应画布。

下拉框显示紧凑短标签，例如“方向｜双向”“节点｜20”“置信度｜30%”“案例｜2”，同时提供完整的程序化名称。

### 6.3 查询选项

- 查询方向：上游、下游、双向；
- 节点上限：20、50、100；
- 最低置信度：0% 至 100%，以 10% 为一档；
- 最少案例数：0 至 10，以 1 为一档。

最低置信度和最少案例数不再使用文本输入、弹出筛选器、应用按钮或重置按钮。

修改方向、节点上限、最低置信度或最少案例数后，立即更新 URL 查询参数并重新查询。刷新页面、复制链接和浏览器前进后退仍可恢复同一查询。

选择新中心事件时恢复为“双向、20 节点”，保留当前最低置信度和最少案例数。切换方向时回到 20 节点；用户可随后重新选择 50 或 100。

### 6.4 查询更新

重新查询和布局期间继续显示上一张图，左下状态框显示“更新中”。成功后替换图；失败时保留旧图，状态框显示简短错误和“重试”。

没有可用旧图时，画布显示现有初始加载或错误状态。

## 7. 左下悬浮状态框

状态框距离画布左侧和底部约 `16px`。

常态只显示：

- 节点数；
- 关系数。

状态框按需追加“更新中”、查询错误和“重试”。它不再提供“扩展至 50/100”；节点数量只由顶部节点上限下拉框控制。没有中心事件时显示“请选择中心事件”。

## 8. 右侧悬浮属性面板

节点和关系继续共用同一个属性面板：

- 固定宽度约 `360px`；
- 位于顶部工具条下方；
- 距离工具条、右边缘和底部约 `12–16px`；
- 使用圆角、边框和阴影；
- 打开时从右侧滑入，关闭时滑出；
- 覆盖画布，不改变画布宽度；
- 不占用顶部工具条空间；
- 不触发节点重新布局或工具条重新居中。

如果选中元素被属性面板遮挡，只允许平移视口使其进入未遮挡区域，不重新计算节点布局。

交互保持：

- 点击节点或关系、使用方向键改变选择时，已打开面板直接切换详情；
- 空格键打开或关闭面板；
- 关闭面板不清除选择；
- `Esc` 清除选择并关闭面板；
- 面板内交互不传播为画布点击。

## 9. 前端状态和组件边界

应用壳层负责：

- 普通页面侧栏偏好；
- 因果图路由的临时折叠状态；
- 空间不足时的强制折叠；
- 侧栏与工作区的布局类名和动画。

因果图页面负责：

- URL 查询状态；
- 工具条查询选项；
- 查询、布局和旧图保留；
- 左下状态框；
- 选择和右侧属性面板。

查询仍由现有 React Query 和现有 API 驱动。不得将侧栏状态与业务查询状态混合，也不得为布局调整修改服务端契约。

## 10. 无障碍与键盘

- 折叠按钮包含当前状态和目标动作的无障碍名称；
- 收起侧栏中的图标链接仍可通过键盘访问；
- Tooltip 同时支持悬浮和键盘聚焦；
- 下拉框使用原生或等价可访问选择控件；
- 当前导航项、查询方向和当前选择值可被辅助技术识别；
- 工具条、状态框和属性面板拥有明确区域名称；
- 现有画布键盘操作不得因下拉框和悬浮面板而失效；
- 组件处理过按键后不得继续触发画布快捷键。

## 11. 错误处理

- 查询选项仅提供合法离散值，从 UI 阻止越界值；
- URL 中的非法或旧筛选值继续由现有查询状态解析逻辑规范化；
- 自动查询失败时不清空已经显示的图；
- 无旧图时保留现有错误空态；
- 侧栏本地状态读取失败时退回普通页面默认展开；
- 动画失败或被禁用不影响最终布局和操作。

- 空间不足时强制收起但不覆盖普通页面偏好；
- 工具条下拉选项范围、无障碍名称和自动查询；
- 修改方向时回到 20，修改节点上限和筛选时保留其他条件；
- 查询期间旧图保留、成功替换、失败保留和重试；
- 左下状态框的计数和状态；
- 右侧面板不改变画布尺寸和工具条中心；

## 13. 验收标准

1. 顶部导航已替换为可折叠左侧栏；
2. 普通页面保留原结构并明显提高内容密度；
3. 进入因果图时侧栏自动收起，离开后恢复；
4. 因果图画布填满侧栏之外的工作区；
5. 所有查询和缩放控件位于一个居中的单行悬浮工具条；
6. 方向、节点上限、置信度和案例数均使用已确认的离散下拉项；
7. 修改查询选项后自动重新生成因果图；
8. 左下状态框只承担计数、更新、错误和重试；
9. 右侧属性面板悬浮滑入，不压缩画布或工具条；
10. 原有因果图交互和业务页面功能没有回归；
11. 自动化门禁通过；
12. 用户完成人工复核。

只有用户明确确认人工复核通过后，UX-01 才标记为“已完成”。第二阶段不会因此自动开始。
