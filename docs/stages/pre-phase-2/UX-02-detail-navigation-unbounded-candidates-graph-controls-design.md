# UX-02 详情导航、完整候选与因果图控件优化设计

版本：V1.0

日期：2026-07-22

状态：开发与自动化测试完成，等待人工复核

所属阶段：第二阶段开始前的独立体验优化

前置状态：P1-01 至 P1-10 已完成；UX-01 已实施并等待人工复核

## 1. 目标

在不增加业务字段和推理能力的前提下，完善事件、因果关系、具体案例之间的详情导航和编辑入口，取消关系录入与因果图中心事件搜索中的候选总数限制，并统一因果图工具条的应用内控件风格。

本步骤重点解决：

- 因果关系缺少独立详情页面，关系与事件、案例之间的导航不完整；
- 列表展开区承担了详情与编辑两种职责；
- 事件和案例候选只返回少量结果，无法浏览全部匹配项；
- 原子事件列表中的别名和关键词可能无法查看完整内容；
- 因果图工具条仍使用系统原生下拉框，中心事件文字偏大，最低缩放比例偏高。

## 2. 范围

本步骤修改：

- 原子事件列表的编辑入口和延时完整内容提示；
- 因果关系列表的展开内容、行内操作和分页行为；
- 新增因果关系详情页面及详情导航；
- 具体案例详情中的关系入口；
- 因果关系创建、编辑后的跳转；
- 事件与案例候选接口的游标分页能力；
- 关系表单和因果图的完整候选加载；
- 因果图自定义下拉控件、选项顺序、文字尺寸和缩放下限；
- 与以上行为直接相关的自动化测试和文档。

本步骤不修改：

- 事件、关系、案例的数据字段和数据库 Schema；
- 关系置信度、案例验证和因果图查询算法；
- 列表主分页每页数量；
- 事件创建或编辑页原有的最多 5 条重复候选提示；
- 因果图节点、关系、布局、选择、高亮和检查器规则；
- 移动端适配和第二阶段业务功能。

## 3. 方案选择

采用“共享候选分页能力 + 小型通用交互组件 + 独立关系详情页”。

- 服务端候选接口提供稳定的游标分页，前端自动连续读取并追加；
- 关系表单和因果图共享完整事件候选查询逻辑；
- 案例选择器复用同一分页模式，但保留创建新案例规则；
- 因果图四个筛选项复用一个应用内紧凑下拉组件；
- 原子事件列表复用一个延时溢出提示组件；
- 新增关系详情页，不继续扩大列表展开区职责。

不采用各页面分别实现候选加载和下拉交互，避免行为与无障碍规则分叉；不全面重构现有表单和详情页体系，避免超出本轮范围。

## 4. 因果关系列表

### 4.1 行内容与导航

列表继续显示原因事件、方向、结果事件、置信度、案例数和更新时间。

- 原因事件名称链接到 `/events/:eventId`；
- 结果事件名称链接到 `/events/:eventId`；
- 中间箭头链接到 `/relations/:relationId`；
- 箭头链接具有“查看因果关系详情”的程序化名称、可见焦点状态和不小于现有单元格的点击区域；
- 每行操作列同时提供“展开/收起”和“编辑”；
- “编辑”直接进入 `/relations/:relationId/edit`。

### 4.2 展开区域

原“查看详情/收起详情”改为“展开/收起”。同一时间仍只展开一条关系。

展开区域只显示：

- 关系说明；
- 最近 5 条具体案例；
- 案例总数；
- 案例超过 5 条时显示“查看全部 N 条”，跳转到按关系筛选的案例列表。

展开区域不显示创建时间、最后更新时间或编辑按钮。具体案例内容继续链接到案例详情页。

### 4.3 分页与搜索

- 点击上一页或下一页时先从 URL 移除 `expanded`，再切换页面；
- 搜索条件变化时继续清除展开项并回到第一页；
- 分页切换后不自动展开任何关系；
- 展开详情加载失败时不影响列表主数据和分页操作。

## 5. 因果关系详情页

新增路由 `/relations/:relationId`，页面结构沿用事件详情和案例详情的紧凑视觉体系。

### 5.1 标题与操作

- 标题区域显示“原因事件 → 结果事件”；
- 原因事件和结果事件名称分别链接到对应事件详情；
- 箭头只表达方向，不再次嵌套链接；
- 标题右侧提供主按钮“编辑因果关系”；
- 返回入口为“返回关系列表”。

### 5.2 详情字段

页面显示：

- 置信度；
- 关联案例数；
- 关系说明，空值显示“未填写”；
- 创建时间；
- 最后更新时间。

### 5.3 全部关联案例

- 详情页一次性向用户呈现全部关联具体案例，不设置展示总数上限；
- 前端通过案例分页接口以每批最多 100 条自动读取全部分页，再组成一份连续列表；
- 第一批返回后立即显示，后续分页继续追加；
- 每条案例内容链接到 `/cases/:caseId`；
- 后续分页加载时显示紧凑加载状态；
- 后续分页失败时保留已加载案例并提供重试；
- 当前关系没有案例时显示明确空状态。

### 5.4 创建与编辑跳转

- 创建关系成功后进入 `/relations/:relationId`；
- 编辑关系保存成功后进入 `/relations/:relationId`；
- 编辑页的返回和取消均进入 `/relations/:relationId`；
- 关系表单中的“查看已有关系”和“查看反向关系”进入 `/relations/:relationId`。

## 6. 事件与案例页面导航

### 6.1 原子事件列表

- 表格增加操作列；
- 每行提供“编辑”，进入 `/events/:eventId/edit`；
- 事件名称继续进入事件详情页；
- 事件详情页保留现有“编辑事件”主按钮。

### 6.2 具体案例详情

- “关联的因果关系”中的每一项改为链接到 `/relations/:relationId`；
- 原因事件、箭头和结果事件继续作为一个完整的关系入口显示；
- 案例详情页现有“编辑案例”主按钮保持不变。

## 7. 原子事件完整内容提示

别名和关键词列仍最多直接显示 3 项，以维持列表密度。

### 7.1 启用条件

只有以下任一条件满足时才启用提示：

- 实际值超过 3 项，列表隐藏了后续内容；
- 当前可见文字因单元格宽度产生截断。

空值或已经完整显示的内容不产生提示。

### 7.2 交互

- 鼠标连续悬停 2 秒后显示；
- 提示内容包含该字段全部值，使用“、”分隔并自动换行；
- 鼠标离开、列表滚动、页面切换或按 Esc 时关闭；
- 键盘聚焦内容时立即显示，焦点移开时关闭；
- 不使用浏览器原生 `title`；
- 提示框不改变表格行高，不遮挡当前操作列，并保持白色表面、细边框和轻阴影。

## 8. 完整候选搜索

### 8.1 接口契约

事件候选和案例候选查询增加：

- 可选 `cursor`；
- `limit`，范围 1–100，默认 100；
- 响应字段 `items`、`nextCursor`、`hasMore`。

游标绑定规范化查询条件和稳定排序字段。查询条件或排除事件变化后，旧游标不得继续使用。

事件排序继续按照标准名称精确、标准名称前缀、别名精确、别名前缀、关键词精确和其他包含匹配的既有优先级，再以规范化名称和 ID 保证稳定顺序。

案例排序继续按照内容精确、内容前缀和内容包含匹配，再以更新时间和 ID 保证稳定顺序。

接口和前端均不得通过候选总数上限截断最终结果。数据库不新增字段或索引。

### 8.2 自动读取规则

- 输入防抖保持 250ms；
- 空输入不查询；
- 第一批候选返回后立即打开列表；
- 前端在后台自动继续请求后续游标，直到 `hasMore` 为 `false`；
- 所有页面按 ID 去重并按接口顺序追加；
- 候选数据最终完整保留，列表采用窗口化渲染，只创建当前可视项及少量缓冲项；滚动和键盘导航仍可到达每一个匹配结果；
- 输入内容变化、选中项目或组件卸载时取消过期请求；
- 后续分页失败时保留已加载候选并在列表末尾提供重试；
- 不向用户显示匹配原因、分页批次或完整匹配数量。

### 8.3 关系表单中的事件候选

- 原因事件和结果事件均可以浏览全部匹配事件；
- 候选列表显示在输入框下方；
- 列表设置最大可视高度并在内部滚动；
- 鼠标、方向键、Home、End、Enter 和 Esc 均可操作；
- 选择事件后关闭列表并保持现有同向、反向和自环检查。

### 8.4 关系表单中的案例候选

- 案例候选列表显示在当前输入框上方；
- 列表设置最大可视高度并在内部滚动；
- 如果输入内容合法且没有完全相同的已有案例，“创建新案例：……”始终位于第一项；
- 已有匹配案例按照接口顺序列在创建项之后；
- 如果已有案例与输入内容完全相同，不显示重复创建项；
- Enter 选择当前高亮项，不再固定选择第一个已有案例；
- 已选择案例、50 字限制、重复关联校验和移除行为保持不变。

### 8.5 非本次范围的候选提示

事件创建和编辑表单中的重复事件提示仍只显示最多 5 条。该区域用于提醒命名重复，不是供用户从全部事件中选择，因此不接入自动读取全部候选。

## 9. 因果图工具条

### 9.1 中心事件搜索

- 中心事件候选接入完整事件候选分页；
- 输入框文字为 `12px`；
- 候选文字为 `11px`；
- 候选项保持现有点击高度，不通过缩小点击区域压缩字体；
- 候选列表在工具条下方显示并在内部滚动；
- 选择新中心事件后的查询重置规则保持不变。

### 9.2 应用内自定义下拉

方向、节点、置信度和案例四个系统原生选择框替换为共享 `CompactSelect`。

- 触发按钮保持现有约 36px 高度和工具条单行布局；
- 菜单使用应用现有白色表面、细边框、8px 左右圆角和轻阴影；
- 当前值、悬停值、键盘高亮值和焦点状态清晰区分；
- 同一时间只允许打开一个菜单；
- 点击外部关闭；
- 支持方向键、Home、End、Enter、Space、Esc；
- 处理过的按键不继续触发画布快捷键；
- 选择后立即更新 URL 并重新查询，不增加应用或重置按钮。

方向选项顺序固定为：

1. 双向；
2. 下游；
3. 上游。

其他选项保持：

- 节点：20、50、100；
- 置信度：0%–100%，每 10% 一级；
- 案例：0–10，每次递增 1。

### 9.3 缩放

- 因果图运行时最低缩放从 25% 调整为 10%；
- 减号按钮最低值、鼠标滚轮最低值和程序设置最低值统一为 10%；
- 最高缩放保持 200%；
- 加减按钮继续按照当前约 1.2 倍比例缩放；
- 在百分比和加号之间增加分割线，使减号、百分比和加号左右分隔一致；
- “适应画布”行为保持不变。

## 10. 前端组件边界

- `RelationDetailPage`：关系基础信息、全部案例和详情操作；
- 候选分页查询模块：游标状态、自动后续请求、取消、去重、窗口化数据和重试；
- `EventSelector`：关系表单事件选择和表单状态；
- `CaseSelectorRow`：案例创建选项、已有案例选择和单行校验；
- `GraphEventSelector`：因果图中心事件选择；
- `CompactSelect`：因果图离散单选菜单；
- `DelayedOverflowTooltip`：2 秒延迟、溢出检测、定位和关闭；
- 各页面继续负责自己的路由、查询缓存失效和成功跳转。

共享模块只抽取本次存在重复的能力，不重构无关页面或表单。

## 11. 错误处理与无障碍

### 11.1 错误处理

- 关系基础详情加载失败时显示整页错误和返回关系列表入口；
- 全部案例后续分页失败时保留已加载内容并允许重试；
- 候选后续分页失败时保留输入、选择和已加载候选；
- 新搜索取消旧搜索，旧响应不得覆盖新结果；
- 不存在的事件、关系或案例沿用现有无法读取状态；
- 列表展开详情失败不阻断列表分页。

### 11.2 无障碍

- 关系箭头链接具有可理解的无障碍名称；
- 行内“展开/收起”暴露正确 `aria-expanded`；
- 自定义下拉使用按钮与 listbox/option 语义，当前值和当前高亮项可被识别；
- 候选组合框继续暴露 `aria-expanded`、`aria-controls` 和活动项；
- 延时提示与触发内容建立说明关系，键盘用户无需等待 2 秒；
- 自定义控件处理按键后不触发因果图画布快捷键；
- 视觉焦点不得被悬停样式替代。

## 13. 验收标准

1. 关系列表使用“展开/收起”，展开区只显示关系说明和最近 5 条具体案例；
2. 关系列表分页时自动收起，原因、箭头、结果和编辑入口均按设计跳转；
3. 独立关系详情页包含全部已确认字段、编辑按钮和所有关联案例；
4. 创建或编辑关系成功后进入关系详情页；
5. 案例详情中的关系入口进入关系详情页；
6. 事件和关系列表均有行内编辑入口；
7. 隐藏或截断的别名、关键词在悬停 2 秒后显示全部内容；
8. 关系表单事件、案例和因果图中心事件最终可浏览所有匹配候选；
9. 案例创建项位于候选第一项，案例候选菜单显示在输入框上方；
10. 因果图方向、节点、置信度、案例均使用应用内自定义下拉；
11. 方向顺序为双向、下游、上游；
12. 中心事件输入和候选字体已缩小；
13. 因果图最低缩放为 10%，百分比和加号之间存在分割线；
14. 自动化门禁通过；
15. 用户完成人工复核。

只有用户审核本设计文档并明确同意实施后，才编写 UX-02 实施计划。只有用户明确确认人工复核通过后，UX-02 才标记为“已完成”。第二阶段不会因此自动开始。
