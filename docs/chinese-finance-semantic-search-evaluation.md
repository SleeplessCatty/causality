# 中文金融增强搜索能力边界与模型验收

更新时间：2026-07-24

## 1. 目标

本次选型不追求“参数最大的模型”，而是在 Causality 的实际使用范围内，选择满足质量门槛的
最小模型。模型只负责从同一类实体中召回语义相关候选，最终结果仍由普通搜索、结构化过滤和
人工判断共同确定。

模型需要处理的文本上限来自现有产品约束：

- 原子事件名称最多 50 字；
- 具体案例最多 100 字；
- 增强查询最多 200 字；
- 因果关系由原因事件、结果事件和简短说明组成；
- 当前约有 56,184 条可索引记录，第二阶段按 100,000 条进行容量验收；
- 增强查询由用户主动点击，优先保证单用户交互体验，不以高并发服务为目标。

## 2. 模拟测试数据

中文金融困难集位于
[`apps/semantic-worker/test/fixtures/semantic-quality-zh-finance.json`](../apps/semantic-worker/test/fixtures/semantic-quality-zh-finance.json)。

数据全部为模拟记录，不代表真实公司、真实公告或投资结论。措辞、数字和业务结构参考常见的
宏观数据、上市公司公告和股票市场表达。

| 类型 | 文档数 | 查询数 |
| --- | ---: | ---: |
| 原子事件 | 20 | 15 |
| 因果关系 | 20 | 15 |
| 具体案例 | 20 | 15 |
| 合计 | 60 | 45 |

困难集没有只放容易匹配的同义词，而是为每个查询指定容易误召回的相邻概念或反向事件：

- 降准与降息、降准与提高准备金率；
- 人民币升值与贬值；
- PMI 进入扩张区间与跌入收缩区间；
- 业绩预增与预减；
- 扭亏为盈与亏损收窄但仍亏损；
- 控股股东增持、公司回购和股东减持；
- 股份回购与定向增发；
- 重大合同签订与合同终止；
- 原材料涨价压缩毛利与产品涨价提高毛利；
- 日期、百分比、金额、公司行业和金融缩写的组合匹配。

## 3. 模型应当具备的能力

模型需要在候选召回层完成以下工作：

1. 识别中文金融术语及常用简称，例如降准、LPR、PMI、定增、解禁和 EPS。
2. 识别不改变含义的中文改写，例如“形成潜在卖盘”和“抛售压力上升”。
3. 区分方向相反但关键词高度重合的事件，例如增持与减持、升值与贬值。
4. 区分相近但不相同的概念，例如降准与降息、股东增持与公司回购。
5. 在案例查询中结合主体类别、时间、金额、百分比和事件方向找到候选。
6. 在因果关系查询中同时保留原因、结果和方向，不能只因共享行业词而匹配。

## 4. 明确不要求模型完成的工作

以下能力超出向量增强搜索的边界，不应通过更大的 embedding 模型强行解决：

- 判断一条事件或因果关系是否真实；
- 根据模型知识补充数据库中不存在的事实；
- 预测股票涨跌或给出投资建议；
- 完成多跳因果推理；
- 判断具体案例在不同市场环境中的条件有效性；
- 精确计算日期范围、金额区间或财务指标；
- 仅凭向量相似度自动去重或自动合并记录。

精确名称、股票代码、日期和数字首先由普通搜索与后续结构化字段负责；向量搜索只提供候选。

## 5. 质量验收门槛

每个候选模型使用同一份冻结测试集和同一套查询规则。阈值允许按模型单独校准，但不能针对
单条查询调整。

| 指标 | 最低要求 | 说明 |
| --- | ---: | --- |
| Recall@10 | ≥ 95% | 相关文档进入前 10 |
| Top-1 命中率 | ≥ 85% | 第一候选就是相关文档 |
| MRR@10 | ≥ 0.90 | 相关文档整体排序靠前 |
| 困难负样本排在相关结果之前 | ≤ 10% | 检查方向和近义概念混淆 |
| 方向/否定类 Top-1 命中率 | ≥ 90% | 升降、增减、扭亏/仍亏等 |
| 默认阈值下无匹配查询误召率 | ≤ 5% | 控制与库中内容无关的查询噪声 |

困难负样本本身通常与查询主题相关，例如“降准”和“降息”。它可以出现在候选列表中，
但不能排在正确结果之前。阈值误召率应使用真正与库中内容无关的查询测量，不能把所有
相邻金融概念都当作无关文本。

45 条查询只用于第一轮工程筛选，不能宣称通用金融检索质量。最终模型确定前，测试集应扩大到
至少 200 条人工复核查询，并把开发集和最终验收集分开，避免根据当前小样本过拟合阈值。

## 6. 资源与性能上限

当前部署基线为 Apple Silicon、Colima 8 GiB、2 个 CPU、PostgreSQL + pgvector。

| 指标 | 优先目标 | 淘汰上限 |
| --- | ---: | ---: |
| 参数量 | ≤ 150M | 300M |
| 模型下载量 | ≤ 180 MB | 300 MB |
| 向量维度 | ≤ 512 | 768 |
| Worker 热状态 RSS | ≤ 1.0 GiB | 1.25 GiB |
| 单次查询向量 P95 | ≤ 400 ms | 800 ms |
| 增强搜索端到端 P95 | ≤ 600 ms | 1,000 ms |
| 56,184 条全量索引时间 | ≤ 45 分钟 | 60 分钟 |
| 100,000 条全量索引时间 | ≤ 80 分钟 | 120 分钟 |
| 56,184 条干净语义存储 | ≤ 350 MB | 500 MB |
| 100,000 条干净语义存储 | ≤ 600 MB | 900 MB |

1024 维模型不再进入默认模型候选。768 维模型只有在 Top-1、困难负样本或人工复核质量相对
小模型提高至少 5 个百分点时才保留，否则选择更小模型。

## 7. 选型规则

候选模型按以下顺序决策：

1. 淘汰不能直接生成检索向量、许可证不清晰或无法离线运行的模型。
2. 淘汰无法在 Linux ARM64 + Transformers.js/ONNX Runtime 中稳定加载的模型。
3. 淘汰超过资源上限的模型。
4. 淘汰未通过中文金融困难集质量门槛的模型。
5. 在全部通过的模型中选择模型文件、内存、维度和索引时间最小的一个。
6. 只有质量提升达到 5 个百分点以上，才允许选择资源明显更大的模型。

金融领域预训练的分类器、情感模型或生成式模型不能因为名称中含有 `Finance` 或 `FinBERT`
就直接进入候选；只有经过句子级检索训练、可以输出可比较向量的模型才有资格参与测试。

## 8. 验证顺序

1. 先用当前 E5 Small 和 BGE-M3 取得本地基线。
2. 从中文轻量模型中选择不超过四个候选，只下载这些候选。
3. 对候选运行模型加载、向量维度、质量和输出释放 smoke。
4. 对通过质量门槛的候选运行 56,184 条全量索引和查询 P50/P95。
5. 记录实际 RSS、CPU、模型缓存、PostgreSQL 存储和 HNSW 查询计划。
6. 选定模型后再修改生产模型目录、数据库约束和部分索引。

## 9. 第一轮实测结果

第一轮使用 60 条模拟文档、45 条相关查询和 12 条无匹配查询。测试运行在 Apple Silicon
本机 CPU，使用与项目一致的 Transformers.js、ONNX INT8、归一化向量和余弦相似度。
这些数据用于初筛，不替代后续 Linux ARM64 容器和 5.6 万条全量索引测试。

| 指标 | Multilingual E5 Small | BGE Small Zh v1.5 |
| --- | ---: | ---: |
| ONNX 主模型 | 约 118 MB | 约 24 MB |
| 向量维度 | 384 | 512 |
| Recall@10 | 100% | 100% |
| Top-1 命中率 | 93.3% | 93.3% |
| MRR@10 | 0.954 | 0.963 |
| 困难负样本排在正确结果前 | 4.4% | 2.2% |
| 满足质量和无匹配误召门槛的阈值 | 未找到 | 62% |
| 该阈值 Recall@10 | — | 95.6% |
| 该阈值无匹配误召率 | — | 0% |
| 文档向量吞吐量 | 约 367 条/秒 | 约 592 条/秒 |
| 单条查询 P95 | 约 3.01 ms | 约 1.75 ms |
| 测试进程峰值 RSS | 约 806 MB | 约 373 MB |

E5 Small 的相关分数中位数约为 0.916，无匹配查询最高分的 P95 仍约为 0.890，分数区间
高度重叠。在当前困难集上找不到同时满足 Recall 和无匹配误召门槛的整数百分比阈值。

BGE Small Zh v1.5 的相关分数中位数约为 0.792，无匹配查询最高分 P95 约为 0.588，
62% 可以作为下一轮开发集初始阈值。正式默认值仍需要用扩大后的独立验收集确认。

官方检索指令前缀也进行了对照。加入指令时 BGE Small 的 Top-1 为 91.1%，不加指令时为
93.3%，因此当前短事件相似检索采用无指令方式。该选择只适用于本项目任务，不能泛化为
其他检索场景的通用结论。

## 10. 当前选定模型

中文限定场景的当前首选是 **BGE Small Zh v1.5（无查询指令）**。

选择理由：

1. 已达到第一轮 Recall、Top-1、MRR、困难负样本和无匹配查询门槛。
2. 质量排序略好于当前 E5 Small，阈值可分性明显更好。
3. INT8 主模型只有约 24 MB，实测 RSS 和查询延迟显著低于 E5 Small。
4. 24M 参数、512 维、512 token 足以覆盖当前 50–100 字中文短文本。
5. MIT 许可明确，并已有固定 revision 的 Transformers.js ONNX 转换。

暂不继续下载更大的通用模型。GTE Small Zh 仍是有价值的研究挑战者，但没有可直接固定的
官方 Transformers.js ONNX；Fin-Retriever-base 的权重许可和 ONNX 交付不满足正式产品
门禁；BGE Base Zh v1.5 只有在扩大测试集后 BGE Small 质量不达标时才需要测试。

当前选择是“进入生产集成和全量性能验收的模型”，不是未经后续验证便永久锁定的模型。
下一门禁是在 Linux ARM64 容器中完成真实 smoke，并对 56,184 条数据测量全量索引时间、
Worker 峰值 RSS、数据库存储和增强查询端到端 P95。
